# 微信小程序：账号与权限模型

## 身份关系

```text
微信身份（openid / unionid，仅由服务端保存）
  └─ 平台用户账号
       ├─ 学生账号 ── 班级
       ├─ 家长账号 ── 已确认的学生绑定关系
       └─ 教师账号 ── 任教班级 + 学科 + 有效学期
```

微信授权只能证明当前微信身份；它不能自动建立亲子关系、师生关系或班级访问权限。

## 必须由后端保证的规则

1. 小程序先通过 `wx.login` 获得临时 code，后端换取微信身份并签发短期业务会话。
2. 学生绑定微信前，必须验证学生平台账号；绑定、换绑、解绑均需要审计记录。
3. 家长查看学生数据前，必须存在有效的家长—学生绑定关系；绑定应通过孩子码、学校审核或双向确认。
4. 教师每一次班级、学生、错题、时长和答案管控请求，都必须检查教师—班级—学科—学期授权。
5. 前端的角色判断只服务于导航和展示，不能替代服务端鉴权。

## 首期页面范围

| 角色 | 首期页面 |
|---|---|
| 学生 | 登录、微信绑定、我的作业、学习学情、活动、管控状态 |
| 家长 | 孩子绑定与切换、孩子作业、学习报告、活动、管控设置 |
| 教师 | 班级总览、学生学情、错题、学习时长、作业、答案开放与管控 |

## 接口边界（待后端确认）

- `POST /auth/wechat/code-login`：临时 code 换取业务会话。
- `POST /auth/platform-login`：验证学生、家长或教师的平台注册身份。
- `POST /account/wechat-bind`：完成已验证平台账号与微信身份的绑定。
- `GET /me/roles`：返回当前可用角色及其班级、孩子等授权范围。
- `GET /students/{id}/overview`：由后端判断访问者是否有权限查看。
- `GET /classes/{id}/analytics`：仅返回教师被授权班级和学科的数据。
