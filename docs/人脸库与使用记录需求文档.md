## 1. 需求范围

<callout emoji="📌">
**本期范围：**后台维护学生人脸照片并下发至同校柜机；柜机支持人脸识别登录和编号密码登录。柜机主动录入人脸本期不上线。
</callout>

人脸信息管理只维护已有学生的人脸数据，不创建学生账号，也不修改学生编号、姓名和班级。

## 2. 菜单与页面入口

“人脸信息管理”位于“用户管理”下，与“学生账号”同级。

```Plain Text
用户管理
├── 教师账号
├── 学生账号
├── 人脸信息管理
└── 后台账号
```

- 首次进入页面时不展示学生数据，先选择学校。
- 学校为必选项，切换学校后清空其他筛选条件并回到第一页。
- 不提供“查看上传历史”入口或独立历史页面。
- 注册任务通过“上传注册记录”独立标签页查看。

## 3. 人脸信息列表

### 3.1 查询条件

| 条件 | 规则 |
|-|-|
| 学校 | 必选；仅展示当前学校数据。 |
| 学生编号 | 支持按编号查询。 |
| 姓名 | 支持按姓名查询。 |
| 班级 | 选择当前学校下的班级，默认全部。 |
| 注册状态 | 全部、无、待注册、注册中、注册成功、注册失败。“无”筛选没有注册任务、列表注册状态显示“—”的学生。 |

以上条件可组合查询。点击“重置”时保留学校，清空其他条件。

### 3.2 列表字段

| 字段 | 展示规则 |
|-|-|
| 学生编号、姓名、班级 | 来自学生账号，只读。 |
| 学生照片 | 以缩略图展示最近一次注册成功的照片，点击放大查看；悬停显示文件名。无有效照片时显示“未上传”。 |
| 最近注册成功照片 | 以缩略图展示本次最新照片更新注册成功后的照片，点击放大查看；悬停显示文件名。尚未成功时显示“—”。两列缩略图统一尺寸，列表裁剪展示，放大预览保持原比例。 |
| 人脸来源 | **取值：**后台上传 / 柜机录入 / —。  <br/>**共同规则：**均对应学生照片，展示和删除规则相同。  <br/>**本期范围：**柜机录入关联柜机人脸注册，暂未开发；原型仅演示后续效果。 |
| 最近更新时间 | 当前有效人脸数据最近一次成功更新的时间。 |
| 注册状态 | 待注册、注册中、注册成功、注册失败；没有注册任务时显示“—”。 |
| 说明 | 位于注册状态之后。注册失败时展示该学生最新注册任务的失败原因；无说明时显示“—”。下发失败统一显示“下发失败，请重新上传照片”，不展示柜机名称、编号等信息。重新上传或删除照片后清空旧说明。 |
| 操作 | 上传照片或更新照片；已有照片时可删除照片。 |

**页面操作布局**

- 选择学校后，标题右上角才展示操作按钮：左侧“上传注册记录（进行中 N）”使用蓝色描边按钮，右侧“＋ 批量上传照片”使用蓝色主按钮。没有进行中任务时只显示“上传注册记录”；未选择学校时不展示这两个按钮。
- 标题下方不展示概述说明句和信息图标，直接进入学校筛选。
- 筛选区下方、表格上方左侧：保留普通按钮“批量删除”。进入勾选模式后显示已选人数、红色“删除所选”和“取消”。

**各页面的说明展示**

- 主列表：在“注册状态”后展示“说明”，注册失败时展示失败原因，无说明显示“—”。
- 上传弹窗保留上传数量、跳过数量及可展开的文件名和跳过原因；上传注册记录也保留完整明细。已完成记录可查看、下载明细。
- 上传注册记录：明细弹窗逐张展示上传状态、注册状态和说明；下载结果包含全部照片。

### 3.3 照片更新规则

| 场景 | 学生照片 | 最近注册成功照片 |
|-|-|-|
| 首次上传，尚未注册成功 | 未上传 | — |
| 已有旧照片，新照片尚未注册成功 | 保留旧照片 | — |
| 最新照片注册成功 | 更新为最新照片 | 更新为同一张最新照片 |

- 提交新照片后，先清空“最近注册成功照片”；原“学生照片”继续有效。
- **沿用现有实现：任意一台柜机下发成功即视为照片注册成功。**

  - 立即更新两列照片、人脸来源和最近更新时间。
  - 其他柜机失败：后台自动重试。
  - 其他柜机离线：上线后自动继续注册。
  - 其他柜机的处理结果不回退该照片已成功的状态。
- 待注册、注册中或注册失败不得覆盖原有效照片。
- 旧任务的回执不得覆盖更新任务的结果。

### 3.4 分页

默认每页 10 条，支持每页 10/20/50 条、页码、上一页、下一页和跳页。查询条件变化后回到第一页。

## 4. 上传学生照片

### 4.1 批量上传

1. 点击页面右上角“批量上传照片”，弹窗固定当前学校。
2. 选择班级后上传一个 ZIP 压缩包。
3. 系统按照片文件名匹配当前学校、当前班级的学生，展示匹配及校验结果；管理员点击该压缩包的“上传”后，才执行上传。
4. 有效照片进入注册队列；无效照片跳过，不影响其他照片。

### 4.2 文件名匹配

照片可按学生编号或完整姓名命名，同一个 ZIP 可混用两种方式。

```Plain Text
2026001.jpg
张三.png
```

- 支持 JPG、JPEG、PNG。
- 先按学生编号精确匹配；未命中时再按完整姓名精确匹配。
- 编号必须属于当前学校和所选班级，不得跨校、跨班上传。
- 同班姓名唯一时才可按姓名匹配。
- 同班重名时跳过，提示“姓名重复，请使用编号或单独上传”。
- 同一 ZIP 内用编号和姓名等不同文件名指向同一学生时，相关照片全部跳过，每张均提示“请按照规范命名”。
- 文件名可匹配本校学生但不属于所选班级时提示“学生不在所选班级”；在当前学校找不到对应编号或姓名时提示“学生不存在”。
- 压缩包内不使用多层文件夹。

### 4.3 图片处理

- 不限制用户上传的原始单张照片大小，也不设置 ZIP 总大小的产品限制。
- 系统自动压缩，保证每张用于保存和下发的照片不超过 2MB。
- 照片无法读取、无法压缩、未匹配学生或重复时跳过该照片。
- 批量上传不创建学生账号，也不修改学生基础资料。

### 4.4 上传结果展示

| 项目 | 规则 |
|-|-|
| 弹窗字段 | 文件名、说明、操作；提交时间在上传注册记录中查看。 |
| 说明 | 有效 ZIP 在点击“上传”前留空；上传后显示“上传 X 张，跳过 Y 张”。存在跳过项时点击展开文件名和原因，内容较多时在固定高度区域滚动。文件不可上传时在说明列显示错误原因。 |
| 下载 Excel | 上传弹窗不提供下载按钮；上传注册记录完成后可从列表或明细下载全部照片的结果。 |
| 下载字段 | 统一下载字段见5.3，包含上传状态、注册状态及说明。 |

上传结果与注册结果分别保存，上传不等待注册完成。

- 弹窗标题为“批量上传人脸照片”。左侧展示本次 ZIP 文件及校验说明，右侧并排展示当前学校和班级，下方为 ZIP 上传区域；“上传演示 ZIP”按钮位于上传区加号位置，“下载上传规范文件”位于上传区下方；使用右上角叉号关闭弹窗，底部不展示返回按钮。
- 弹窗不堆放照片准备步骤或大小限制说明。“下载上传规范文件”下载随原型提供的《学生照片提交规范与示例.zip》；匹配和压缩规则仍按4.2、4.3执行。
- 选择有效 ZIP 后“说明”列保持空白；文件不可上传时显示错误原因并标红，不另设“上传结果”列。
- 校验完成后展示“上传”按钮；执行后操作列改为“上传成功”，不再提供“查看上传注册记录”按钮。注册任务仍可从主页面的“上传注册记录”入口查看。
- 存在有效照片时仅提示“上传成功”，注册在后台继续；全部跳过时提示未上传照片，并在操作列显示“上传失败”。
- 主页面简短提示操作用途；柜机录入本期未开发的说明放在帮助提示中。

### 4.5 单人上传或更新

- 弹窗展示学生姓名、编号、班级、当前照片和新照片。
- 支持 JPG、JPEG、PNG，可预览并重新选择。
- 单人上传不要求原文件按姓名或编号命名，系统保留上传文件的原文件名。
- 系统自动压缩至每张不超过 2MB。
- 已有照片时操作名称为“更新照片”；选好新照片后点击“确定上传”进入注册队列，注册成功前保留原有效照片。
- 已有照片时提供“删除照片”操作。

## 5. 上传注册记录

### 5.1 任务生成

- 本文界面中的“注册”指后台照片下发至柜机并完成本次人脸注册；上传状态与注册状态分别记录。
- 每次 ZIP 上传和每次单人上传分别生成一个注册任务。
- 全部照片跳过时不下发照片，但仍保留一条已完成记录，展示上传0张、跳过数量，支持查看及下载明细。
- 注册按照片处理，排队中的照片显示“待注册”，正在处理显示“注册中”。
- 不使用“注册超时”表示排队。
- 不提供单条重试或批量重试入口。

### 5.2 上传注册记录标签页

- 点击页面右上角“上传注册记录”打开独立后台标签页，自动带入当前学校并展示学校名称。重复点击复用标签；每次 ZIP 上传或单张上传对应一行。
- 入口显示“上传注册记录（进行中 N）”：N为当前学校仍有待注册或注册中照片的任务数，不受筛选影响。N为0时隐藏括号；不展示全部记录数。
- 展示当前学校最近100条记录；进行中优先，同组按提交时间倒序。支持10/20/50条每页、页码及跳页。
- 筛选项：文件名称模糊查询、状态（全部/进行中/已完成）、“提交时间”起止日期范围（包含首尾日期）。点击查询生效，重置清空条件；开始日期晚于结束日期时提示。
- 表格字段：文件名称、班级、提交时间、状态、注册进度、成功、失败、操作。文件名称下不附加上传和跳过数量。注册进度以已处理照片数/进入注册的照片数展示进度条；全部跳过时为已完成，进度为0/0。
- 已处理=注册成功+注册失败。仍有待注册或注册中的照片即为进行中；全部处理结束即为已完成，允许包含失败。进行中记录的操作列留空；已完成后才显示“查看明细”和“下载明细”。
- 上传注册记录页通过顶部后台标签切换，不设独立返回按钮。关闭上传注册记录标签回到人脸信息管理，保留学校、筛选及页码。自动刷新保留记录筛选、页码与滚动位置，切换或关闭页面不停止注册。明细弹窗使用右上角叉号关闭。

### 5.3 明细与下载

- 已完成记录可点“查看明细”打开同名居中弹窗，右上角叉号关闭；展示文件信息、上传状态和注册状态筛选及分页，列表右上角提供“下载明细”。列为照片文件名、学生编号、姓名、上传状态、注册状态、说明。
- 明细注册状态仅筛选未注册、注册成功、注册失败，不提供待注册和注册中；未注册展示上传失败的照片。上传状态和注册状态分列，说明展示对应失败原因。
- 列表与弹窗统一使用“下载明细”，仅已完成记录可操作。Excel包括本次上传的每张照片，不受筛选分页影响；字段为任务文件名、学校、班级、提交时间、照片文件名、学生编号、姓名、上传状态、注册状态、说明。
- 匹配成功的照片上传状态为“上传成功”，注册状态为“注册成功”或“注册失败”；未通过匹配或校验的照片上传状态为“上传失败”、注册状态为“未注册”，说明保留失败原因。全部跳过的记录完成后也可下载。

## 6. 删除照片（柜机停用方式待确认）

**待确认：**能否删除柜机本地人脸照片，或通过“禁用”方式停用该人脸？需开发核实柜机接口能力后，与产品确认最终方案。

**业务目标：**操作后停止该学生使用原人脸刷脸登录。本节保留现有原型的删除交互；柜机执行方式、离线生效时机及相关结果口径待方案确认，不代表已实现。此处“禁用”仅为待评估方案，尚未确定新增后台禁用功能。

### 6.1 单人删除

- 学生存在学生照片、最近注册成功照片或本次待注册照片时，操作列显示“删除照片”。不按来源限制删除；柜机录入来源也必须有对应学生照片，并支持单人及列表勾选批量删除。
- 点击后弹出中小宽度的二次确认弹窗，展示学生姓名和编号，并提示两列照片都会清空。
- 确认后提交删除请求。受理成功才清空学生照片、最近注册成功照片、人脸来源、最近更新时间和注册状态；失败或超时保留原展示，按6.3提示；取消不修改数据。

### 6.2 批量删除

批量删除与单人删除共用结果规则，见6.3。

1. 点击筛选区下方“批量删除”，进入主列表勾选模式。
2. 可勾选多名学生；“全选当页”仅选择当前页有照片的学生，无照片的学生不可选。
3. 显示已选人数，未选择时“删除所选”不可点击。翻页、查询、重置或切换学校时清空选择；取消退出勾选模式。
4. 点击“删除所选”弹出二次确认，展示所选人数及“两列照片都会清空”的提示。取消弹窗保留选择，确认后才提交删除。
5. 成功后清空所选学生两列照片及关联状态，退出勾选模式；失败或超时保留照片和选择，可重新操作。

### 6.3 删除结果与重试

- **预期处理（柜机实现方式待确认）**

  - 后台原型：受理成功后清空两列照片及关联状态。
  - 柜机：需核实能否删除本地人脸照片，或以禁用方式停止刷脸。
  - 离线补发、部分柜机未完成时自动重试为预期要求，具体执行指令与生效时机随最终方案确认。
- 删除请求受理成功统一提示“删除成功”，包含离线待补发或部分柜机待完成的情况；此提示不代表所有柜机已经清除。
- **页面提示**

  - 成功：删除成功。
  - 超时：删除超时，请重试。
  - 失败：删除失败，请重试。
  - 提示短暂展示，不设置专用重试按钮或常驻异常区域。
  - 超时或失败时，原型保留照片和原删除入口。
  - 正式接口需查询实际受理结果，避免超时造成前后端状态不一致。
- **防止重复删除和旧数据恢复**

  - 重试重新下发原删除任务，指令关联原人脸版本。
  - 不能误删后续新上传的照片。
  - 柜机中已不存在的人脸，按删除成功处理。
  - 旧上传或注册任务不得恢复已删除的人脸。
- 再次删除仍使用原来的单人或批量删除入口及二次确认，按本次结果提示。控制台可模拟删除成功、超时和失败。
- **待开发核实：停用能力与生效时机**

  - 是否支持删除柜机本地人脸照片，或通过禁用停止该人脸识别。
  - 核实在线与离线柜机何时停止刷脸，以及上线补发能力。
  - 确认前不承诺离线柜机可立即停止刷脸；上线补发不等于离线期间已生效。

## 7. 柜机登录

点击柜机首页“借”后，进入编号密码登录页。该页面提供“登录”“返回”和“人脸识别”：编号密码验证成功进入设备列表；返回回到首页；人脸识别进入识别页面。

人脸识别页面只执行识别流程。左上角“返回”回到编号密码登录页，页面内不再提供编号密码登录按钮。识别失败可重新识别；离开页面时停止本次识别。

识别成功后弹出“确认登录身份”，展示识别到的学生编号和“是否确认登录？”。点击“取消”关闭弹窗并返回编号密码登录页；点击“确认登录”才完成登录并进入设备列表。

柜机主动录入人脸及其跨柜机分发属于独立的柜机注册流程，本期后台人脸信息管理不接入该来源；后台的“柜机录入”来源仅作后续效果演示。注册流程中的编号密码登录页面不提供“返回扫脸”或“人脸识别”按钮。

## 8. 学校与柜机数据范围

- 人脸数据按学校隔离，只向该校相关柜机下发并注册。
- 添加和编辑柜机时学校必选，未选择不得保存。
- 柜机更换学校后，清除原学校人脸数据，再下发新学校人脸数据。
- 同一学生只使用所属学校范围内的人脸数据。

## 9. 本期不做

- 后台人脸信息管理接入柜机主动录入的人脸及跨柜机分发；柜机端独立注册流程按柜机需求另行验收。
- 学生编号、姓名、班级等基础资料编辑。
- 查看上传历史及历史详情。
- 独立人脸登录记录菜单。
- 单条或批量注册重试。
- 复杂人脸库分组、算法版本管理、报表和告警中心。

## 10. 权限与日志

- 人脸照片和识别数据属于敏感个人信息，仅授权管理员可查看。
- 批量上传、单人更新、删除照片、注册和 Excel 导出均记录操作日志。
- 日志至少记录学校、学生编号、操作人、时间和结果。
- 访问、传输和存储采用符合部署要求的安全措施。

## 11. 验收标准

1. 菜单层级、查询条件、列表字段及按钮顺序与原型一致。
2. 未选学校时不展示学生数据；选择学校后可看到该校全部学生。
3. 主列表注册状态支持筛选无、待注册、注册中、注册成功、注册失败；“无”筛选没有注册任务的学生。不提供“是否已有人脸信息”筛选。
4. 批量上传支持编号或姓名匹配；同班重名和重复照片按规则跳过，区分“学生不在所选班级”与“学生不存在”。
5. 系统自动压缩照片，用户无需按原始大小预处理。
6. 单人上传不校验照片命名，并保留上传文件的原文件名。
7. 新照片只有在最新注册任务成功后才更新两列照片、来源和时间。
8. 仅已完成记录可查看和下载明细；包含全部跳过记录。Excel逐张展示上传成功或失败、注册成功或失败（未进入注册显示“未注册”）及说明。
9. 上传注册记录表格支持筛选分页，以“注册进度”进度条展示已处理/总数及进行中/已完成；明细弹窗可筛选失败项，且不出现待注册和注册中选项。下载不受筛选分页影响。
10. 主列表保留注册说明；上传弹窗保留上传数量与可展开的跳过原因；上传注册记录明细包含上传跳过原因和注册失败原因。下载明细统一在上传注册记录中提供，下发失败不展示柜机信息。
11. **删除验收**

    - 支持单人删除和列表勾选批量删除，可全选当页，按所选学生人数计数；不跨页选择。
    - 二次确认并受理成功后，清空两列照片及关联状态。
    - 失败或超时仅提示并保留原展示，无专用重试按钮。
    - 旧任务不得恢复已删除照片。柜机本地删除或禁用方案及生效时机待开发核实、产品确认后，再补充对应联动验收。
12. 后台人脸信息管理接入柜机主动录入来源不纳入本期开发与验收；柜机端独立注册流程按柜机需求验收。
13. 柜机借设备时先进入编号密码登录页；从该页进入人脸识别，识别成功后确认身份才登录，取消确认返回编号密码登录页。

## 12. 原型边界与待确认项

- 演示 ZIP 按钮和控制台异常模拟仅用于原型验收，不作为正式后台必需功能。演示包使用占位图，模拟注册结果，不代表真实人脸检测或柜机接口已接通。
- 柜机删除本地人脸还是通过禁用停用，以及在线、离线时的实际生效时间，按第6节待开发核实、产品确认。
- 待确认：学校没有可下发柜机，或所有柜机长期离线时，照片应保持待注册多久、何时转失败。当前成功规则仍为任意一台成功即成功，不据此推断等待时限。
- 原型限制：上传注册记录保存在浏览器本地，上传照片使用临时对象URL；刷新浏览器后的照片恢复与任务续传不能视为已完成。正式持久化、刷新恢复需接口实现并验证。
- 正式环境的照片保存期限、毕业离校后的清理策略和操作日志保存期限尚未明确，应另行确认，不由原型默认值推断。
