# 人脸库与使用记录需求文档

## 1. 需求背景

学习平板借还柜机目前使用“学生编号 + 密码”登录。接入第三方柜机摄像头和百度智能云人脸识别后，学生可以直接通过人脸完成身份识别，再进入原有借还流程。

学生编号和密码继续保留，作为人脸识别不可用时的登录方式。后台需要维护学生人脸信息，并在现有使用记录中记录本次使用的登录方式。

## 2. 本期范围

本期只增加以下能力：

1. 在“设备管理”下增加“人脸库”二级菜单。
2. 管理学生与百度人脸库用户的绑定关系。
3. 支持通过表格和照片压缩包批量导入学生人脸。
4. 支持学生人脸的编辑、照片替换、启用和停用。
5. 支持分页查看大量人脸数据。
6. 在现有“使用记录”中增加“登录方式”字段。

本期不新增独立的“登录记录”菜单。

## 3. 百度智能云接入方案

### 3.1 接入能力

接入百度智能云提供的：

- 百度人脸库
- 人脸注册接口
- 人脸 1:N 搜索/比对接口

柜机摄像头采集现场人脸后，调用百度 1:N 接口，在指定人脸库中搜索匹配的学生，返回百度用户 ID 和匹配结果。

### 3.2 人脸库字段映射

| 百度字段 | 系统使用方式 |
|---|---|
| `group_id` | 固定的学校学生人脸库分组，例如 `school_students` |
| `user_id` | 使用学生编号/学号，作为学生唯一关联 ID |
| `user_info` | 保存姓名、班级等辅助信息 |
| `image` | 学生照片转成 Base64 后提交 |
| `image_type` | 固定传 `BASE64` |

本地系统还需保存百度注册状态、同步时间、失败原因等信息。百度人脸库只负责算法识别，本地系统负责学生业务信息、启停状态和借用权限。

### 3.3 柜机识别流程

```text
学生到柜机前
→ 摄像头采集人脸
→ 调用百度 1:N 人脸搜索
→ 返回匹配学生编号
→ 检查学生人脸状态和现有借用规则
→ 进入原有借用/归还流程
→ 在使用记录中写入登录方式“人脸识别”
```

如果人脸识别失败或不可用，柜机继续支持学生编号和密码登录，并在使用记录中写入“编号密码”。

## 4. 后台菜单

```text
设备管理
├── 概览
├── 柜机管理
├── 平板设备
├── 使用记录
├── 状态告警
└── 人脸库
```

## 5. 人脸库页面

### 5.1 页面定位

维护学生人脸资料和百度人脸库的同步关系。

### 5.2 列表字段

- 选择框
- 学生编号
- 姓名
- 班级
- 人脸状态
- 最近同步时间
- 操作

人脸状态包括：

- 未录入
- 已启用
- 已停用
- 导入失败

“已启用”使用绿色标签，“已停用”使用灰色标签。

### 5.3 筛选条件

- 学生编号
- 姓名
- 班级
- 人脸状态

### 5.4 页面操作

筛选条件下方、列表上方放置：

- 批量导入
- 批量启用
- 批量停用

每个学生的操作列包括：

- 编辑
- 启用/停用

### 5.5 分页

人脸数据量较大时使用分页器，支持：

- 上一页、下一页
- 页码切换
- 每页 10 / 20 / 50 条
- 跳转到指定页

表头全选只选择当前页数据。批量操作默认只处理当前页已勾选的学生。

### 5.6 批量导入

导入弹窗仿照设备导入弹窗，包含：

- 左侧上传记录区域
- 右侧文件上传区域
- 模板下载
- 取消、确定按钮

管理员上传两个文件：

#### 学生信息表

| 字段 | 必填 | 说明 |
|---|---|---|
| 学生编号 | 是 | 与现有学生账号一致，也作为百度 `user_id` |
| 姓名 | 是 | 学生姓名 |
| 班级 | 是 | 学生所属班级 |
| 照片文件名 | 是 | 与照片压缩包中的文件名一致 |

#### 照片压缩包

照片文件名建议使用学生编号，例如：

```text
10001.jpg
10002.jpg
10003.jpg
```

导入处理流程：

```text
上传 Excel 和照片压缩包
→ 按照片文件名匹配学生编号
→ 校验学生信息和照片
→ 调用百度人脸注册接口
→ 保存本地学生信息与百度用户关联
→ 显示成功、失败和失败原因
```

需要校验：学生编号是否存在、照片是否缺失、照片是否能检测到人脸、是否包含多张人脸、照片格式和大小是否符合要求。

### 5.7 编辑学生人脸

点击“编辑”打开编辑弹窗，可以修改：

- 姓名
- 班级
- 学生照片

学生编号不可编辑，因为它同时关联现有学生账号和百度 `user_id`。

上传新照片后，系统重新调用百度人脸注册/更新接口，并更新最近同步时间。停用人脸只改变本地使用状态，不删除百度人脸数据，也不影响编号密码登录。

## 6. 使用记录调整

不新增独立登录记录页面，在现有“设备管理 → 使用记录”中增加：

- 登录方式：人脸识别 / 编号密码

使用记录示例：

| 记录 ID | 学生 | 设备 | 登录方式 | 借出时间 | 归还时间 | 状态 |
|---|---|---|---|---|---|---|
| U2026001 | 张三 | PAD-001 | 人脸识别 | 08:31 | — | 借出中 |
| U2026002 | 李四 | PAD-002 | 编号密码 | 08:35 | 16:20 | 已归还 |

本期不增加“是否为密码兜底”字段，只记录实际使用的登录方式。

如果人脸识别失败且没有进入借还流程，第一版可以不生成使用记录；后续如需追踪失败尝试，再单独增加认证日志。

## 7. 批量启用和停用规则

- 批量操作默认只作用于当前页勾选学生。
- 未录入或导入失败的学生不能启用，并提示失败原因。
- 停用只禁止人脸登录，不影响编号密码登录。
- 停用不删除百度人脸库数据。
- 开学或恢复使用时可以批量启用。
- 寒暑假可以按班级或选中学生批量停用。

## 8. 非本期范围

- 不做独立登录记录菜单。
- 不做复杂的人脸库分组管理页面。
- 不做算法版本管理。
- 不做复杂报表和告警中心。
- 不做 1:1 编号后比对流程；本期按百度 1:N 人脸搜索设计。

## 9. 数据与安全要求

- 人脸照片和人脸特征属于敏感数据，应限制访问权限。
- 本地只保存业务必要信息和百度关联信息。
- 删除或停用操作需要记录操作人和时间。
- 人脸照片上传、同步失败需要有明确提示。
- 学生停用后不得被 1:N 搜索结果直接用于借用授权。
- 实际上线前需根据部署地区的隐私和个人信息保护要求补充授权、保存期限和删除机制。
