# 教师端角色与权限需求说明

## 1. 文档目的

本文定义教师端账号角色、菜单权限、数据范围和学校管理员账号创建规则，供产品、设计、前端、后端和测试共同评审与实现。

权限必须同时控制页面可见性、操作能力和服务端数据访问范围。前端隐藏菜单不能替代后端鉴权。

## 2. 角色定义

教师端初期包含三类角色：

| 角色 | 账号来源 | 管理范围 | 主要用途 |
| --- | --- | --- | --- |
| 教师 | 后台创建或导入，并分配任教学科和班级 | 本人被授权的班级与学科 | 查看学情、学生档案和个人信息 |
| 班主任 | 后台创建或导入，并指定负责班级 | 本人负责的班级 | 教师权限，以及班级激励、班级消息处理 |
| 学校管理员 | 仅允许平台后台创建，并必须绑定一所所属学校 | 所属学校 | 管理本校信息、班级、师生账号和本校设备 |

一个学校管理员账号初期只绑定一所学校。需要管理多所学校时，应分别创建对应学校的管理员账号，不通过前端临时切换学校扩大数据范围。

## 3. 菜单权限矩阵

| 一级模块 / 功能 | 教师 | 班主任 | 学校管理员 |
| --- | :---: | :---: | :---: |
| 仪表盘 | ✓ | ✓ | ✓ |
| 学情分析 | 授权班级 | 负责班级 | 本校范围 |
| 学生管理 | 授权班级 | 负责班级 | 本校范围 |
| 班级激励 | — | ✓ | ✓ |
| 消息中心 | — | ✓ | ✓ |
| 学校信息管理 | — | — | ✓ |
| 设备管理 | — | — | ✓ |
| 个人中心 | ✓ | ✓ | ✓ |

“学校信息管理”和“设备管理”只对学校管理员显示。教师和班主任即使直接输入页面地址或构造接口请求，也必须返回无权限，不得返回页面数据。

## 4. 学校信息管理权限

学校信息管理位于教师端侧栏，包含：

1. 班级管理。
2. 教师账号。
3. 学生账号。
4. 学校信息。

该一级菜单仅学校管理员可见。学校管理员只能查看和维护账号所绑定学校的数据：

- 学校信息固定为当前账号所属学校，不提供学校切换器。
- 新增或导入班级、教师、学生时，所属学校由系统自动写入当前管理员的学校 ID，不允许前端提交其他学校 ID。
- 列表、搜索、导出和详情接口必须强制附加当前管理员的学校范围。
- 当前管理员不能查看、搜索、修改或删除其他学校的班级、教师、学生和学校资料。

## 5. 设备管理权限

设备管理作为独立一级菜单，固定排列在“学校信息管理”下方，包含：

1. 概览。
2. 柜机管理。
3. 平板设备。
4. 使用记录。
5. 状态告警。
6. 人脸信息管理。

设备管理仅学校管理员可见。所有页面和操作以当前管理员账号绑定的 `schoolId` 为强制数据边界：

- 概览统计只计算本校柜机、平板、借用和告警数据。
- 柜机列表、详情、编辑、格口信息和远程开门只允许查看或操作本校柜机。教师端学校管理员不能添加柜机；编辑柜机时不展示学校字段，柜机学校归属由当前管理员账号自动限定且不可修改。教师端学校管理员不配置柜机轮播内容。
- 平板列表和详情只允许查看本校设备。教师端学校管理员不提供设备导入和设备还原功能，这两项操作继续由平台后台负责。
- 使用记录和状态告警只返回本校设备产生的记录。
- 人脸信息管理进入后默认直接展示当前管理员所属学校的学生人脸列表，不提供学校选择器；照片导入和人脸登录记录均限定为当前学校，不得通过学号搜索到其他学校学生。
- 页面不提供学校筛选或切换入口；所属学校只读展示。
- 教师端设备管理不显示轮播素材、查看轮播、单柜配置或批量配置入口，也不能访问轮播配置路由。
- 教师端平板设备页面不显示“导入设备”和“设备还原”入口。
- 教师端柜机管理不显示“添加柜机”入口；编辑柜机不显示学校字段。
- 教师端柜机详情不显示“远程重启”操作；“远程开门”保留，仅允许操作本校柜机。
- 请求中即使传入其他学校的 ID，服务端也必须忽略该值并按登录账号的 `schoolId` 查询，或直接拒绝请求。
- 访问不属于本校的柜机、设备、记录或学生详情时，统一返回无权限或数据不存在，不得暴露对象是否真实存在。

## 6. 学校管理员创建流程

学校管理员不能在教师端自行注册或把普通教师提升为管理员，必须在平台后台完成创建：

1. 后台管理员进入账号或权限管理。
2. 选择“新建学校管理员”。
3. 填写姓名、登录账号、联系方式和初始密码。
4. 从学校库中选择一所所属学校；学校为必填且保存后写入管理员账号的 `schoolId` 与 `schoolName`。
5. 系统校验账号唯一性、学校有效性和创建者权限。
6. 创建成功后记录创建人、创建时间、所属学校和角色变更日志。
7. 学校管理员登录教师端后，系统从登录凭证读取角色与所属学校，生成对应菜单和数据权限。

更换所属学校属于高风险权限变更，只允许在平台后台操作，并记录变更前后的学校、操作者和时间。变更生效后，旧登录会话应失效，管理员重新登录后只看到新绑定学校的数据。

## 7. 鉴权与数据隔离要求

- 登录凭证至少包含用户 ID、角色、学校 ID 和有效期；学校 ID 由服务端签发，不采信前端自行传入值。
- 每个学校信息和设备管理接口都先校验 `role === school-admin`，再校验资源的 `schoolId` 与当前账号一致。
- 新增数据时由服务端写入当前账号的学校 ID；更新和删除前再次校验资源归属。
- 列表总数、筛选候选项、导出文件和统计图表都必须执行同样的数据范围过滤。
- 操作日志记录账号、角色、学校、资源、操作、结果和时间。
- 账号被停用、角色被移除或所属学校发生变更时，已有会话应立即失效或在下一次请求时拒绝访问。

## 8. 页面表现要求

- 学校管理员登录后，侧栏先显示“学校信息管理”，其下方显示“设备管理”。
- 教师和班主任的侧栏不渲染这两个一级菜单。
- 学校信息与设备页面顶部显示“数据范围：当前学校名称”，不提供切换控件。
- 无权限访问显示统一的权限不足页面，不出现空白页或部分数据。
- 数据为空时提示“当前学校暂无数据”，不得自动展示其他学校的演示数据。

## 9. 验收标准

- 后台创建学校管理员时未选择学校不能保存。
- 学校管理员账号登录后能看到学校信息管理和设备管理，顺序符合要求。
- 教师和班主任看不到上述两个菜单，直接访问也不能获得数据。
- 学校管理员的学校信息、班级、教师、学生、柜机、平板、记录、告警和人脸数据均限定在所属学校。
- 修改请求参数中的学校 ID 不能越权访问其他学校。
- 管理员所属学校变更后旧会话失效，重新登录后数据范围正确更新。
- 权限变更和设备操作均有可追溯的审计日志。
