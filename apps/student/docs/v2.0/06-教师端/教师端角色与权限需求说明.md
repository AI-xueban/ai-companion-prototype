# 后台设备管理移植教师端需求说明

## 1. 文档目的

本文说明将平台后台“设备管理”移植到教师端后的功能范围、权限规则和页面调整，供产品、设计、开发和测试共同使用。

本次调整遵循以下原则：

1. 教师端保留后台设备管理的六个子模块、主要字段名称和操作逻辑，方便内部人员对照使用。
2. 学校管理员通常由教师兼任，只保留本校日常管理需要的查看、编辑和处理能力。
3. 权限同时覆盖菜单、页面、操作和接口数据范围，不能只依靠前端隐藏。
4. 本文是本次移植的唯一需求基线，其他讨论和原型以本文为准。

## 2. 使用角色与数据范围

### 2.1 使用角色

- 学校管理员由平台后台创建，并绑定一所学校。
- 只有学校管理员登录教师端后，才能看到“学校信息管理”和“设备管理”。
- 普通教师、班主任等其他角色不显示上述入口，直接输入地址或构造接口请求也不能获得数据。
- “设备管理”一级菜单固定放在“学校信息管理”下方。

### 2.2 学校数据范围

- 一个学校管理员账号只管理所属学校，不提供学校选择或切换功能。
- 进入设备管理后，页面顶部只显示当前学校，不显示班级选择器。
- 统计、列表、详情、筛选、候选项、导出和操作均限定为当前学校数据。
- 所属学校由服务端根据登录身份确定，不采信客户端传入的学校标识。
- 请求其他学校资源时，统一返回无权限或数据不存在，不暴露资源是否真实存在。

## 3. 菜单与整体调整

设备管理保留以下六个二级菜单：

1. 概览
2. 柜机管理
3. 平板设备
4. 使用记录
5. 状态告警
6. 人脸信息管理

教师端不提供以下后台能力：

- 新增柜机
- 设备导入、设备还原
- 远程重启
- 广告轮播筛选
- 轮播素材字段和轮播预览
- 单柜轮播配置和批量轮播配置
- 轮播配置页面或路由
- 跨学校筛选、查询和切换
- “当前数据范围”等额外说明条

## 4. 页面需求

### 4.1 概览

#### 4.1.1 设备概览

保留后台原有六项统计，数据范围均为当前学校：

- 柜机在线数
- 平板设备总数
- 在柜数
- 离柜数
- 逾期提醒数
- 待处理告警数

#### 4.1.2 今日使用数据

在设备概览下方增加“今日使用数据”，视觉样式与设备概览保持一致，不增加“点击查看”等说明文字。

| 指标 | 统计口径 | 点击后的页面与筛选 |
| --- | --- | --- |
| 今日借出设备 | 当天成功借出的记录数，不含取消借用 | 使用记录：当天借出，排除取消记录 |
| 今日归还设备 | 当天成功归还的记录数 | 使用记录：当天归还，状态为已归还 |
| 今日借用人数 | 当天成功借出的学生人数，按学生编号去重 | 使用记录：当天成功借出 |
| 今日逾期未归还 | 当前已逾期且仍未归还的设备数 | 使用记录：状态为已逾期 |
| 今日归还异常 | 当天产生的未关门、未充电和设备损坏告警数 | 状态告警：当天归还相关异常 |

不展示“当前借出设备”和“今日取消借用”两项卡片。

#### 4.1.3 状态告警

用“状态告警”替换后台概览中的“最近使用记录”：

- 筛选项为产生时间段和处理状态，两项均可修改。
- 默认产生时间为当月第一天至当天，默认状态为“待处理”。
- 支持查询和重置；查询或重置后返回第 1 页。
- 按产生时间倒序排列，不按告警严重程度排序。
- 每页 10 条，显示上一页、页码、下一页、总条数和当前页。
- 字段、处理建议和状态操作与“状态告警”页面一致。

概览中去掉外观检测、放置检测和归还流程等面向内部人员的说明内容。

### 4.2 柜机管理

#### 4.2.1 柜机列表

保留字段：

- 序号
- 柜机名称
- 安装位置
- 格口数量
- 在线状态
- 负责人
- 操作

隐藏字段和功能：

- 柜机 ID
- 轮播素材
- 最近心跳
- 绑定手机号
- 负责人联系方式
- 批量选择框和已选数量

操作列仅保留“编辑”和“查看详情”。

#### 4.2.2 编辑柜机

允许编辑：

- 柜机名称
- 安装位置
- 绑定手机号
- 负责人
- 负责人联系方式

隐藏且不可编辑：

- 所属学校
- 柜机 ID
- 格口数量
- 在线状态
- 最近心跳

柜机所属学校由当前账号自动限定，不能通过表单或请求参数修改。

#### 4.2.3 柜机详情

保留柜机基本信息、格口状态和“远程开门”。

去掉：

- 远程重启
- “绑定本柜机设备”区块
- “最近告警”区块

相关设备和告警分别前往“平板设备”和“状态告警”查看。

远程开门要求：

1. 只能操作当前学校的柜机。
2. 柜机离线时禁用远程开门。
3. 操作者先选择需要开启的格口，再点击开门。
4. 下发指令前必须弹出二次确认。
5. 弹窗展示柜机名称、安装位置和格口号。
6. 弹窗提示：“请确认本人或学校工作人员正在柜机现场，避免误开其他格口。”
7. 再次确认后才下发开门指令。

### 4.3 平板设备

教师端不显示“导入设备”和“设备还原”。

列表保留：

- 设备 SN
- 型号
- 柜机名称
- 格口号
- 设备状态
- 说明
- 查看详情

列表隐藏：

- 设备 ID
- 柜机 ID
- 柜门状态
- 格口状态
- 轮播内容相关字段和操作

完整设备信息可继续在详情页查看，但不能出现轮播配置入口。

### 4.4 使用记录

- 默认展示当前学校全部设备使用记录。
- 筛选项包括学生姓名或学号、设备 SN、柜机 ID、记录状态、借出时间段和归还时间段。
- 学生条件支持姓名和学号模糊查询。
- 列表去掉“登录方式”字段。
- 其他列表字段和详情内容沿用后台使用记录原型。
- 列表及详情均不能查询到其他学校数据。

### 4.5 状态告警

#### 4.5.1 告警类型与处理建议

| 告警类型 | 告警内容 | 处理建议 |
| --- | --- | --- |
| 设备损坏 | 外观对比发现设备损坏 | 核对设备情况并联系平台运营人员 |
| 借用逾期 | 设备借出满 24 小时仍未归还 | 联系当前借用学生尽快归还 |
| 柜门未关 | 对应格口柜门未关闭 | 到柜机现场检查并关闭对应格口 |
| 设备未充电 | 设备入柜后未进入充电状态 | 检查设备是否放稳及充电线是否连接 |
| 柜机离线 | 柜机心跳超时 | 检查柜机电源和网络连接 |
| 人工问题反馈 | 展示用户提交的具体反馈内容 | 根据反馈内容到现场核查处理 |

人工问题反馈至少覆盖：

- 柜门无法关闭
- 充电线损坏
- 格口内有异物
- 设备外观损坏

#### 4.5.2 筛选与排序

筛选项：

- 设备 SN
- 所属柜机 ID
- 告警类型
- 处理状态
- 产生时间段，包含开始日期和结束日期

默认筛选条件为“当月第一天至当天 + 待处理”。

告警按产生时间倒序排列，不按严重程度重新排序。查询或重置后返回第 1 页。

#### 4.5.3 列表与分页

列表字段：

- 告警 ID
- 告警类型
- 设备 SN
- 格口号
- 所属柜机 ID
- 告警内容
- 处理建议
- 状态
- 产生时间
- 操作

每页 10 条，提供上一页、页码、下一页、总条数和当前页信息。

#### 4.5.4 状态处理

告警包含“待处理”和“已解决”两种状态，并允许双向切换：

- 待处理记录显示“标记已解决”。
- 点击后弹出二次确认，提示只有现场问题处理完成后才能标记。
- 确认后状态改为“已解决”。
- 已解决记录显示“恢复待处理”。
- 点击后弹出二次确认，提示恢复后将重新进入待处理列表。
- 确认后状态改为“待处理”。
- 操作成功提示包含告警 ID 和变更结果。
- 状态需要持久保存，刷新页面后不能恢复为初始状态。

### 4.6 人脸信息管理

进入页面后直接展示当前学校的学生人脸列表，不提供学校选择器。

以下数据均限定为当前学校：

- 学生人脸列表
- 照片导入及导入记录
- 当前识别来源
- 人脸登录记录
- 学号和姓名搜索结果

不能通过学号、姓名或请求参数查询其他学校学生。

## 5. 页面文案

- 设备 SN 输入提示：“请输入设备背面的 SN”。
- 柜机 ID 输入提示：“请输入柜机编号，如 CAB-001”。
- 安装位置输入提示使用校内位置示例，如“图书馆一楼大厅”。
- 学生搜索提示明确支持姓名或学号。
- 页面使用学校人员容易理解的业务语言，减少心跳、指令等技术说明。

## 6. 原型演示数据

### 6.1 状态告警

准备 20 条 2026 年 10 月记录：

- 待处理 15 条，已解决 5 条。
- 覆盖六种告警类型。
- 人工问题反馈覆盖四种指定场景。
- 数据分布在当前学校的不同柜机、设备和格口。
- 告警状态在本地演示环境中持久保存。

### 6.2 使用记录

准备 20 条 2026 年 10 月 10 日记录，用于支撑概览统计：

- 成功借出 18 条。
- 成功归还 15 条。
- 成功借出记录涉及 16 名学生。
- 另有 2 条取消借用记录，只用于使用记录列表演示，不计入概览。
- 当日归还异常数由当天的未关门、未充电和设备损坏告警统计。

## 7. 服务端权限与审计

- 登录凭证至少包含用户 ID、角色、学校 ID 和有效期。
- 设备管理接口先校验学校管理员角色，再校验资源所属学校。
- 学校 ID 由服务端签发和写入，不允许客户端自由指定或修改。
- 列表总数、筛选候选项、统计、导出、详情、编辑、状态处理和远程操作执行相同的学校范围校验。
- 更新、删除、远程开门和告警状态操作前，需再次校验资源归属。
- 关键操作记录账号、角色、学校、操作对象、操作内容、结果和时间。
- 账号停用、角色移除或所属学校变化后，旧会话应立即失效或在下一次请求时拒绝访问。

## 8. 本次不处理

- 不对后台设备管理的信息架构进行大幅调整。
- 不按告警严重程度排序。
- 不增加复制设备信息和页面数据更新时间。
- 不跨页面保留筛选条件和当前页。
- 不增加额外的“当前数据范围”横幅。
- 空数据、无权限和加载失败提示的进一步分类暂不处理。

## 9. 验收重点

1. 只有学校管理员能看到并访问设备管理，并且只能查看和操作所属学校数据。
2. 教师端保留六个二级菜单，字段、按钮和限制符合本文要求。
3. 新增柜机、设备导入、设备还原、远程重启和轮播配置入口全部移除。
4. 概览六项设备统计和五项今日使用数据口径正确，点击后筛选结果与卡片一致。
5. 概览和状态告警页面默认筛选当月待处理数据，时间段、状态、分页及双向状态操作可用。
6. 柜机远程开门具备学校校验、离线禁用、格口选择和二次确认。
7. 人脸信息默认展示当前学校数据，使用记录不显示登录方式。
8. 直接访问页面、修改学校参数或构造接口请求均不能越权。

## 10. 原型与正式开发说明

原型可以通过前端数据、字段隐藏和本地状态模拟上述效果。正式开发必须在服务端实现角色鉴权、学校数据隔离、远程操作校验、告警状态持久化和操作审计，不能依赖前端隐藏或本地存储作为安全边界。
