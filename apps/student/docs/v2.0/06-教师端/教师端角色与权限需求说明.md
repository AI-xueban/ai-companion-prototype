# 教师端角色、权限与设备管理整改需求

## 1. 文档目的

本文说明教师端的角色权限、学校数据范围，以及从平台后台移植到教师端后的设备管理整改内容，供产品、设计、前端、后端和测试共同评审与验收。

本次整改遵循以下原则：

1. 教师端继续沿用平台后台“设备管理”的六个子模块、主要字段名称和基础操作逻辑，降低内部人员在两端切换时的理解成本。
2. 学校管理员很可能由教师兼职，教师端只保留本校日常管理需要的查看、编辑和处理能力。
3. 权限必须同时控制菜单、页面、操作和服务端数据范围。前端隐藏菜单或按钮不能替代后端鉴权。
4. 本文描述的是最终确认口径；未采用和仍待确认的内容单独列出。

## 2. 角色定义

教师端包含三类角色：

| 角色 | 账号来源 | 数据范围 | 主要用途 |
| --- | --- | --- | --- |
| 教师 | 平台后台创建或导入，并分配任教学科和班级 | 本人被授权的班级与学科 | 查看学情、学生档案和个人信息 |
| 班主任 | 平台后台创建或导入，并指定负责班级 | 本人负责的班级 | 教师权限，以及班级激励、班级消息处理 |
| 学校管理员 | 仅允许平台后台创建，并必须绑定一所学校 | 所属学校 | 管理本校信息、班级、师生账号和设备 |

一个学校管理员账号只绑定一所学校。需要管理多所学校时，应分别创建对应学校的管理员账号，不在教师端提供学校切换能力。

## 3. 菜单权限

| 一级模块 / 功能 | 教师 | 班主任 | 学校管理员 |
| --- | :---: | :---: | :---: |
| 仪表盘 | ✓ | ✓ | ✓ |
| 学情分析 | 授权班级 | 负责班级 | 本校范围 |
| 学生管理 | 授权班级 | 负责班级 | 本校范围 |
| 班级激励 | — | ✓ | ✓ |
| 消息中心 | — | ✓ | ✓ |
| 学校信息管理 | — | — | ✓ |
| 设备管理 | — | — | ✓ |
| 个人中心 | ✓ | ✓ | ✓ |

“学校信息管理”和“设备管理”只对学校管理员显示。侧栏中“设备管理”固定排列在“学校信息管理”下方。

教师和班主任即使直接输入页面地址或构造接口请求，也不得获得上述模块的数据。

## 4. 学校信息管理

学校信息管理包含：

1. 班级管理。
2. 教师账号。
3. 学生账号。
4. 学校信息。

学校管理员只能查看和维护账号绑定学校的数据：

- 学校信息固定为当前账号所属学校，不提供学校选择或切换入口。
- 新增或导入班级、教师和学生时，所属学校由服务端根据当前账号自动写入。
- 列表、搜索、统计、导出和详情接口都必须强制附加当前学校范围。
- 学校管理员不能查看、搜索、修改或删除其他学校的数据。

## 5. 设备管理整体范围

教师端保留与平台后台一致的六个设备管理子模块：

1. 概览。
2. 柜机管理。
3. 平板设备。
4. 使用记录。
5. 状态告警。
6. 人脸信息管理。

所有统计、列表、详情和操作均以学校管理员账号绑定的 `schoolId` 为强制数据边界。

### 5.1 教师端统一删除或限制的后台能力

教师端不提供以下平台级能力：

- 添加柜机。
- 设备导入。
- 设备还原。
- 远程重启。
- 广告轮播筛选。
- 轮播素材列和轮播预览。
- 单柜轮播配置和批量轮播配置。
- 跨学校筛选、查询或切换。
- 访问轮播配置路由。

所属学校由当前账号决定，不允许通过请求参数更改数据范围。

### 5.2 页面通用表现

- 不额外增加“数据范围：当前学校”横幅；学校信息沿用教师端现有账号区域展示。
- 设备 SN 输入框提示“请输入设备背面的 SN”。
- 柜机 ID 输入框提示“请输入柜机编号，如 CAB-001”。
- 安装位置输入框提示校园位置示例，如“图书馆一楼大厅”。
- 学生搜索明确支持姓名或学号。
- 不属于本校的资源统一返回无权限或数据不存在，不得暴露资源是否真实存在。

## 6. 各设备页面整改

### 6.1 概览

保留平台后台原有统计卡片，统计范围只包含当前学校：

- 柜机在线数。
- 平板总数。
- 在柜数。
- 离柜数。
- 逾期提醒数。
- 待处理告警数。

在设备状态统计下方增加独立的“今日使用数据”区块，保持后台原有卡片样式，不改动整体页面结构：

| 指标 | 统计口径 | 点击后的去向 |
| --- | --- | --- |
| 今日借出设备 | 当天成功借出的记录数，不含取消借用 | 使用记录，预筛选当天借出且排除取消记录 |
| 今日归还设备 | 当天成功归还的记录数 | 使用记录，预筛选当天归还、状态为已归还 |
| 今日借用人数 | 当天成功借出的学生数，按学生编号去重 | 使用记录，预筛选当天成功借出 |
| 当前借出设备 | 当前处于正常借出中的记录数，不含已逾期 | 使用记录，预筛选借出中 |
| 今日逾期未归还 | 当前已逾期且尚未归还的设备数 | 使用记录，预筛选已逾期 |
| 今日归还异常 | 当天产生的未关门、未充电和外观损坏告警数 | 状态告警，预筛选当天归还相关异常 |

移除面向内部人员的外观检测、放置检测和归还流程说明。

原“最近使用记录”区块替换为“状态告警”列表：

- 提供“产生月份”和“处理状态”筛选项。
- 默认产生月份为当月。
- 默认处理状态为“待处理”。
- 支持搜索和重置。
- 按产生时间倒序排列，不按严重程度重新排序。
- 每页 10 条，提供上一页、页码、下一页、总条数和当前页信息。
- 字段、处理建议和状态操作与“状态告警”页面一致。

### 6.2 柜机管理

#### 6.2.1 柜机列表

教师端列表保留学校人员日常识别和管理需要的字段：

- 序号。
- 柜机名称。
- 安装位置。
- 格口数量。
- 在线状态。
- 负责人。
- 操作。

教师端列表隐藏以下字段：

- 柜机 ID。
- 轮播素材。
- 最近心跳。
- 绑定手机号。
- 负责人联系方式。
- 批量选择框和已选数量。

操作列保留：

- 编辑。
- 查看详情。

#### 6.2.2 编辑柜机

教师端编辑柜机时隐藏：

- 所属学校。
- 柜机 ID。
- 格口数量。
- 在线状态。
- 最近心跳。

教师端允许编辑：

- 柜机名称。
- 安装位置。
- 绑定手机号。
- 负责人。
- 负责人联系方式。

学校归属由当前学校管理员账号自动限定，不得通过表单修改。

#### 6.2.3 柜机详情

柜机详情保留柜机基础信息和格口概览。

移除：

- 远程重启。
- “绑定本柜机设备”区块。
- “最近告警”区块。

相关平板和告警分别通过“平板设备”和“状态告警”菜单查看。

保留“远程开门”，并满足以下要求：

1. 仅允许操作本校柜机。
2. 柜机离线时禁止开门。
3. 用户选择格口并点击确认后，再显示二次确认弹窗。
4. 弹窗明确展示柜机名称、安装位置和格口号。
5. 弹窗提示“请确认本人或学校工作人员正在柜机现场，避免误开其他格口”。
6. 用户再次确认后才下发开门指令。

### 6.3 平板设备

教师端不显示“导入设备”和“设备还原”。

平板列表隐藏以下次要技术字段：

- 设备 ID。
- 柜机 ID。
- 柜门状态。
- 格口状态。

列表保留：

- 设备 SN。
- 型号。
- 柜机名称。
- 格口号。
- 设备状态。
- 说明。
- 查看详情。

完整设备信息继续在详情页展示。

### 6.4 使用记录

使用记录仅展示当前学校设备产生的数据。

教师端列表隐藏“登录方式”列，其他记录字段和使用记录详情保持不变。

筛选中的学生条件支持按姓名或学号查询。

### 6.5 状态告警

#### 6.5.1 告警类型

状态告警覆盖以下类型：

| 类型 | 告警内容 | 处理建议 |
| --- | --- | --- |
| 外观损坏 | 外观对比发现损坏 | 请核对设备并联系平台运维 |
| 逾期提醒 | 借出满24小时未归还 | 请联系当前借用学生归还 |
| 未关门 | 未关门 | 请到柜机现场检查对应格口 |
| 未充电 | 未充电 | 请检查设备是否放稳、充电线是否连接 |
| 柜机离线 | 柜机心跳超时 | 请检查柜机电源和网络 |
| 人工问题反馈 | 展示具体反馈内容 | 请根据反馈内容进行现场检查 |

人工问题反馈至少覆盖：

- 门关不上。
- 充电线损坏。
- 格口内有异物。
- 设备损坏。

#### 6.5.2 筛选与排序

状态告警页面提供：

- 设备 SN。
- 所属柜机 ID。
- 告警类型。
- 处理状态。
- 产生月份。

默认筛选为“当月 + 待处理”。

告警按产生时间倒序排列，不按严重程度重新排序。筛选和重置后返回第一页。

#### 6.5.3 列表与分页

列表字段为：

- 告警 ID。
- 类型。
- 设备 SN。
- 格口。
- 所属柜机 ID。
- 告警内容。
- 处理建议。
- 状态。
- 产生时间。
- 操作。

列表默认每页 10 条，提供上一页、页码、下一页、总条数和当前页信息。

#### 6.5.4 状态处理

告警包含“待处理”和“已解决”两种状态，并允许双向切换：

- 待处理记录显示“标记已解决”。
- 点击后弹出二次确认，提示只有现场问题已经处理完成后才可标记。
- 确认后状态改为“已解决”。
- 已解决记录显示“恢复待处理”。
- 点击后弹出二次确认，并说明恢复后会重新进入待处理列表。
- 确认后状态改为“待处理”。
- 操作成功提示必须包含告警 ID 和变更结果。
- 状态变更需要持久保存，页面刷新后不得恢复为初始状态。

### 6.6 人脸信息管理

进入页面后直接展示当前学校的学生人脸列表，不提供学校选择器。

以下数据均限定为当前学校：

- 学生人脸列表。
- 照片导入。
- 当前识别来源。
- 人脸登录记录。
- 学号和姓名搜索结果。

不得通过学号、姓名或请求参数查询到其他学校学生。

## 7. 演示数据

教师端状态告警准备 20 条 2026 年 10 月演示记录：

- 15 条待处理。
- 5 条已解决。
- 覆盖六种告警类型。
- 覆盖四种人工问题反馈内容。
- 数据分布在本校不同柜机、设备和格口。
- 告警处理状态在本地演示数据中持久保存。

教师端另准备 20 条 2026 年 10 月 10 日使用记录，用于展示“今日使用数据”：

- 18 条成功借出记录。
- 15 条成功归还记录。
- 3 条当前借出记录。
- 成功借出记录涉及 16 名学生。
- 另保留 2 条取消借用记录，用于使用记录列表演示，不计入概览指标。
- 当天归还异常由状态告警中的未关门、未充电和外观损坏记录统计。

## 8. 鉴权与数据隔离

- 登录凭证至少包含用户 ID、角色、学校 ID 和有效期。
- 学校 ID 由服务端签发，不采信前端自行传入的学校 ID。
- 学校信息和设备管理接口先校验 `role === school-admin`，再校验资源所属学校。
- 新增数据时由服务端写入当前账号的学校 ID。
- 更新、删除和远程操作前再次校验资源归属。
- 列表总数、筛选候选项、统计和导出执行相同的数据范围过滤。
- 操作日志记录账号、角色、学校、资源、操作、结果和时间。
- 账号停用、角色移除或所属学校变化后，已有会话立即失效或在下一次请求时拒绝访问。

## 9. 本次明确不增加的内容

本次整改不增加：

- 设备列表字段调整以外的大规模页面重构。
- 按严重程度重新排序告警。
- 复制设备信息功能。
- 页面数据更新时间。
- 筛选条件和当前页跨页面记忆。
- 额外的“当前数据范围”横幅。

空数据、无权限和加载失败是否增加更细的分类提示仍待后续确认。

## 10. 验收标准

### 10.1 角色与学校范围

- 学校管理员能看到“学校信息管理”和“设备管理”，且菜单顺序正确。
- 教师和班主任看不到上述菜单，直接访问也不能获得数据。
- 学校管理员只能访问所属学校的学校信息、班级、教师、学生、柜机、平板、记录、告警和人脸数据。
- 修改请求中的学校 ID 不能越权访问其他学校。
- 管理员所属学校变化后旧会话失效。

### 10.2 设备管理

- 教师端保留六个设备管理子模块。
- 教师端不存在添加柜机、设备导入、设备还原、远程重启和轮播配置入口。
- 编辑柜机只显示允许学校管理员维护的字段。
- 柜机详情不显示“绑定本柜机设备”和“最近告警”。
- 远程开门必须经过包含柜机、位置、格口和现场提示的二次确认。
- 平板列表、使用记录列表和柜机列表的隐藏字段符合本文要求。
- 人脸信息进入后直接展示当前学校数据，且不能跨学校查询。

### 10.3 状态告警

- 概览保留原六项设备状态统计，并增加六项“今日使用数据”。
- 今日使用数据的统计口径、数值和点击后的列表筛选结果一致。
- 概览下方展示状态告警，不再展示最近使用记录。
- 概览和状态告警页面默认筛选当月待处理数据。
- 月份和状态是可操作的筛选项，不是固定描述。
- 两个告警列表均按产生时间倒序，每页 10 条。
- 告警列表包含“处理建议”列。
- “标记已解决”和“恢复待处理”均需要二次确认。
- 状态变更成功提示包含告警 ID 和结果。
- 状态变更刷新后仍然保留。
- 20 条十月演示数据覆盖全部告警类型、人工反馈内容和两种处理状态。

## 11. 原型实现说明

当前教师端原型复用平台后台设备管理页面，并在教师端入口执行学校范围过滤、字段隐藏、按钮删除、告警数据补充和交互覆盖。

正式开发时必须在独立接口和服务端权限层实现这些规则，不能依赖前端 DOM 隐藏、前端脚本过滤或本地存储作为安全边界。
