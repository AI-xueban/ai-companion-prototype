# 全校设备管控评审待确认事项

核对日期：2026-10-28。对应主需求 v2.78、当前 3014 原型。以下事项不擅自改写为已确认需求；此次只整理文档，未修改原型代码。

## 1. 使用时长保存确认取消后，是否应保留表单

- 已有要求：保存确认弹窗点击取消，回到已填写的表单。
- 当前原型：使用时长点击保存后就关闭编辑抽屉；确认弹窗取消后，无法回到原表单。借用和智阅会保留编辑表单。
- 建议：修正使用时长原型，保留原交互要求，不为迁就实现而删掉需求。
- 实现定位：`HierarchicalDeviceControl.tsx` 的 `saveDurationRule` 在打开确认后调用 `setDurationEditor(null)`。

## 2. 智阅部分允许时是否需要人数

- 已有要求：部分允许时展示人数。
- 当前原型：卡片分别显示答案、详解的「部分学生允许」，没有显示各项允许人数；全校摘要也不列人数。
- 待确认：补充「允许 X / Y 人」，还是接受当前简洁状态并删除旧人数要求。
- 建议：评审前先明确口径；此次保留人数要求，不擅自视为废弃需求。

## 3. 新增和转班后，其他模块如何继承学校配置

- 已明确：借用时间与学校临时禁借跟随当前班级，学生个人禁借保留；临时锁屏跟随当前班级；不继承新班主任的历史批量设置。
- 尚不明确：时长、万象视界按学生保存；智阅的新需求已改为按学生和科目保存，但尚未实现。新增或转班学生究竟继承目标班级最近一次学校配置、保留个人已有学校配置，还是回到模块默认值。主需求只写「执行当前学校规则」，不足以判断目标班级已有多种配置时取哪一组。
- 例子：目标班学校将每日累计改为120分钟，新学生是执行120分钟还是默认180分钟？原班已允许查看答案，转班后是否保留？
- 待确认：逐模块明确新生、转班的继承来源，以及目标班多配置时的处理；该问题不能仅凭静态原型推定。
