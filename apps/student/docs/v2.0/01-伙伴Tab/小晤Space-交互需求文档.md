## 1. 背景与目标

### 1.1 背景

「小晤 Space」是学生端 AI 学伴的核心陪伴对话页。学生可与小晤进行文字、语音、图片多模态交流，获得情感陪伴与学习辅助。页面采用沉浸式视频背景 + 聊天气泡布局，强调「陪伴感」而非工具型问答。

### 1.2 建设目标

1. 提供自然、低打扰的陪伴型对话体验。
2. 支持文字、语音、拍照三种输入方式。
3. 小晤回复支持流式文字展示与语音播放。
4. 在用户主动结束当前会话（新建对话）且聊得足够多时，收集一次轻量反馈，用于产品优化。
5. 在用户表达负面情绪时，智能推荐情绪调节小游戏。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 陪伴优先 | 交互文案、反馈选项均围绕情感陪伴，避免工具型/讲题型表述 |
| 轻量反馈 | 仅「新建对话」且满足消息阈值时询问；Tab 切换不触发；每会话最多 1 次 |
| 非阻断 | 反馈可跳过；遮罩关闭可取消新建、留在当前会话 |
| 渐进披露 | 流式输出完成后才展示播放按钮；录音时输入区切换为音浪态 |
| 容错可见 | 图片上传展示 loading / 成功 / 失败状态 |

## 3. 核心交互

### 3.1 文字对话

#### 3.1.1 发送消息

| 项目 | 规则 |
|------|------|
| 触发 | 点击发送按钮，或输入框内按 Enter |
| 前置条件 | 输入框有文字 **或** 有上传成功的待发送图片；且没有图片正在上传中 |
| 发送后 | 清空输入框；清空待发送图片；用户消息追加到列表；小晤进入 listening 状态 |
| 占位符 | 默认：「告诉 小晤 你的想法...」；有图片时：「补充说明」 |

#### 3.1.2 小晤回复展示

| 项目 | 规则 |
|------|------|
| 流式输出 | 文本类 / 快捷回复类消息逐字显示，末尾闪烁光标 |
| 输出完成 | 光标消失；若开启自动播放语音则自动朗读 |
| 消息气泡 | 用户：品牌色右对齐；小晤：白色左对齐；系统：灰色小字 |

#### 3.1.3 情绪识别与游戏推荐（原型 Mock）

用户发送消息后，系统对关键词做简单匹配：

| 用户情绪关键词 | 小晤回复倾向 | 推荐游戏 |
|----------------|--------------|----------|
| 烦 / 生气 / 讨厌 / 不开心 | 建议粉碎坏情绪 | 情绪碎纸机 |
| 累 / 焦虑 / 紧张 / 难受 | 建议深呼吸调节 | 呼吸共振 |

推荐以 **游戏卡片消息** 形式出现在聊天气泡下方，点击卡片进入对应游戏。

### 3.2 语音输入

#### 3.2.1 开始录音

| 项目 | 规则 |
|------|------|
| 触发 | 点击输入区右侧 🎤 |
| 视觉 | 输入框切换为浅蓝背景；展示 **音浪动画**；下方显示「聆听中...」或实时识别文字 |
| 边框 | 输入容器高亮：`border-brand/30 ring-2 ring-brand/20` |

#### 3.2.2 停止录音

| 项目 | 规则 |
|------|------|
| 触发 | 再次点击 🎤 |
| 结果 | 识别文字填入输入框；恢复普通文字输入态 |
| 发送 | **不自动发送**，用户需手动点发送 |

#### 3.2.3 技术说明（原型）

- 优先使用浏览器 `SpeechRecognition`（中文 `zh-CN`）。
- 不支持时 Mock：1.5s 后填入「帮我看看这几道题」。
- 录音期间隐藏发送按钮。

### 3.3 拍照输入

#### 3.3.1 拍照浮层

| 项目 | 规则 |
|------|------|
| 触发 | 输入区左侧 📷（相机图标） |
| 模式 Tab | 拍照问小晤（可用）/ 灵镜讲题 / 智阅作业（点击提示「即将上线」） |
| 拍摄 | 最多 3 张；九宫格取景；右侧快门；可选手电筒 |
| 完成 | 点「完成 (n/3)」关闭浮层，图片进入待发送区 |

#### 3.3.2 待发送图片区

位于输入框上方，横向滚动展示缩略图。

| 状态 | 展示 | 可操作 |
|------|------|--------|
| 上传中 | 半透明 + 旋转 loading +「上传中」 | 不可删 |
| 成功 | 正常缩略图 + 右下角绿色 ✓ | 可删除 |
| 失败 | 红色遮罩 +「上传失败」 | 左下角重试；右上角删除 |

#### 3.3.3 发送规则

- 仅 **上传成功** 的图片随消息发送。
- 有图片上传中时 **不可发送**。
- 可只发图片、只发文字、或图片 + 补充说明。
- 原型 Mock：第 2 张图片模拟上传失败（便于演示）。

### 3.4 消息语音播放

#### 3.4.1 展示规则

| 项目 | 规则 |
|------|------|
| 出现时机 | 小晤消息 **流式输出完成后** |
| 位置 | 气泡内左侧，与文字同一行居中排列：`[🔊] 消息文字` |
| 流式进行中 | 不显示播放按钮 |

#### 3.4.2 交互规则

| 操作 | 行为 |
|------|------|
| 点击播放（未播放） | 朗读该条消息 |
| 再次点击（播放中） | 停止当前语音 → 重新流式展示文字 → 流式结束后再次播放 |
| 播放中样式 | 按钮品牌色 + 图标脉冲动画 |

#### 3.4.3 自动播放语音

| 项目 | 规则 |
|------|------|
| 入口 | 侧边抽屉 →「自动播放语音」开关 |
| 开启 | 小晤每条消息流式结束后自动朗读 |
| 关闭 | 仅流式显示文字，需手动点播放 |
| 持久化 | 本地存储（`localStorage`） |

### 3.5 单轮会话反馈

> **设计决策**：不做每条消息下的点赞/踩；不在 Tab 切换时弹窗；仅在用户主动「新建对话」且本轮聊天足够活跃时，最多询问 **1 次**。

#### 3.5.0 会话模型

| 概念 | 说明 |
|------|------|
| 登录会话 | 用户本次登录后的使用周期；登录时自动创建一个小晤聊天会话 |
| 聊天会话 | 用户与小晤的连续对话；Tab 切换**不结束**会话，回来继续聊 |
| 结束当前聊天 | 用户点击侧边栏 **「新建对话」**，清空消息并开启新开场白 |
| 反馈计数重置 | `executeNewChat` 完成后，新聊天会话的「是否已弹反馈」标记清零 |

#### 3.5.1 触发时机

**唯一触发入口：侧边栏「新建对话」**

| 场景 | 是否触发反馈 |
|------|--------------|
| 侧边栏「新建对话」且满足 §3.5.2 全部条件 | ✅ 弹窗 |
| 侧边栏「新建对话」但不满足条件 | ❌ 直接新建，无弹窗 |
| 底部 Tab 切离 / 切回「伙伴」 | ❌ **不触发**（会话继续） |
| 仅有小晤开场白、用户未实质聊天 | ❌ 不触发 |

**遮罩点击（取消新建）**：关闭弹窗，**不新建对话**，留在当前会话；本会话内仍视为「已询问过」，不再重复弹窗。

#### 3.5.2 弹出条件（须同时满足）

| # | 条件 | 阈值 | 说明 |
|---|------|------|------|
| 1 | 本会话尚未弹过反馈 | — | 每登录会话内最多 1 次 |
| 2 | 用户消息数 | **≥ 2** | 用户至少主动发过 2 条（文字 / 语音 / 带图发送均算） |
| 3 | 总消息数 | **≥ 15** | 用户 + 小晤 消息合计，表示聊得足够多 |

**判定伪代码：**

```
shouldAskFeedback =
  !sessionFeedbackShown
  AND count(userMessages) >= 2
  AND count(allMessages) >= 15
```

#### 3.5.3 场景示例

| 用户消息 | 总消息 | 本会话已弹过 | 点「新建对话」 |
|----------|--------|--------------|----------------|
| 0 | 1（仅开场白） | 否 | ❌ 直接新建 |
| 1 | 5 | 否 | ❌ 直接新建 |
| 4 | 10 | 否 | ❌ 直接新建（总消息不足 15） |
| 5 | 16 | 否 | ✅ **弹反馈** |
| 3 | 18 | **是** | ❌ 直接新建 |
| 任意 | 任意 | — | 切 Tab | ❌ **不弹** |

#### 3.5.4 交互流程

```
用户点击「新建对话」
    ↓
是否满足 §3.5.2 全部条件？
   否 → 直接清空并新建
   是 ↓
标记本会话已询问（仅弹 1 次）
    ↓
┌──────────────────────────────┐
│ 小晤想听听                    │
│ 这次聊得怎么样？              │
│  [😊很有帮助] [😐一般] [😕不太满意] │
│           [跳过]              │
└──────────────────────────────┘
    ↓ 选 😊
感谢语 → 1.6s 后关闭 → 新建对话

    ↓ 选 😐 / 😕
┌──────────────────────────────┐
│ 告诉小晤                      │
│ 哪里可以更好？                │
│  可多选                       │
│  [没理解我][答非所问][缺少陪伴感] │
│  [语气不对][回复太长][回复太短]   │
│  [其他想说的（选填，50字）]     │
│        [提交反馈]             │
└──────────────────────────────┘
    ↓
感谢语 → 1.6s 后关闭 → 新建对话

点击遮罩 → 关闭弹窗，不新建，留在当前会话
```

#### 3.5.5 反馈选项（陪伴型）

| ID | 文案 | 说明 |
|----|------|------|
| not_understood | 没理解我 | 未 get 用户感受或想法 |
| off_topic | 答非所问 | 回复未对上用户意图 |
| lack_companionship | 缺少陪伴感 | 不够像朋友、不够贴心 |
| tone | 语气不对 | 太严肃/太幼稚/不像小晤 |
| too_long | 回复太长 | 内容冗长 |
| too_short | 回复太短 | 内容过简 |

- 标签 **可多选**，不限数量。
- 「很有帮助」路径不展开标签，直接提交。

#### 3.5.6 感谢语

| 评价 | 文案 |
|------|------|
| 很有帮助 | 谢谢反馈！小晤会继续陪你学习 ✨ |
| 一般 | 收到，小晤会努力变得更好～ |
| 不太满意 | 抱歉这次没帮上忙，下次可以换种方式问我哦 |

#### 3.5.7 新建对话完成后

| 用户操作 | 结果 |
|----------|------|
| 提交反馈 / 跳过 | 清空当前消息，恢复开场白；新会话反馈标记重置 |
| 点击遮罩取消 | 保持当前消息不变 |

#### 3.5.8 数据（原型）

提交时控制台输出 `[SessionFeedback]`，包含：`rating`、`tags`、`note`、`trigger`（固定为 `new-chat`）、`userMessageCount`、`totalMessageCount`。

## 5. 状态与边界

### 5.1 输入区状态机

```
普通输入 ──点击🎤──→ 录音中（音浪）
    ↑                    │
    └──再次点击🎤─────────┘
         识别结果填入输入框

有 pending 图片 ──→ 显示缩略图条
上传中 ──→ 不可发送
```

### 5.2 会话反馈状态机

```
用户点击「新建对话」
  → 已弹过本会话反馈？
      是 → 直接 executeNewChat
      否 → 用户消息 ≥ 2 且 总消息 ≥ 15？
          否 → 直接 executeNewChat
          是 → 标记已弹过 → 反馈弹窗（rating）
               → helpful → thanks → executeNewChat
               → neutral/bad → tags → thanks → executeNewChat
               → 跳过 → executeNewChat
               → 遮罩关闭 → 留在当前会话（已标记已弹过）

Tab 切换 → 不进入反馈流程
```

### 5.3 异常与降级

| 场景 | 处理 |
|------|------|
| 浏览器不支持语音识别 | Mock 填入示例文字 |
| 图片上传失败 | 展示失败态，可重试 |
| TTS 不可用 | 播放按钮点击无效果，静默失败 |
| 游戏进行中 | 隐藏底部输入区 |

## 6. 与 App 层协作

- 底部 Tab 切换使用 `setActiveTab` 直接切换，**不拦截**、不触发会话反馈。
- 用户登录后由 App 挂载 `LumiSpace`；同一登录周期内组件可因 Tab 切换卸载/重挂载，正式版需与会话持久化方案对齐（见 §7）。

## 8. 验收清单（原型）

- [ ] 文字发送 / 接收，小晤流式输出
- [ ] 语音录音：音浪动画 → 识别填入 → 手动发送
- [ ] 拍照：最多 3 张，上传中/成功/失败态，失败可重试
- [ ] 仅成功图片可发送；上传中不可发送
- [ ] 小晤消息：流式完成后显示播放按钮；播放中再次点击可重播
- [ ] 自动播放语音开关生效且持久化
- [ ] 新建对话：用户消息 ≥ 2 且总消息 ≥ 15 时弹反馈；否则直接新建
- [ ] 新建对话：本会话已弹过反馈时不再弹，直接新建
- [ ] 切换 Tab：任何情况均不弹反馈

## 9. 文档维护约定

本文档为小晤 Space 模块的**唯一交互需求基线**。后续该功能板块有任何新增、调整或下线，**须同步更新本文档**，避免原型、开发与产品认知不一致。

### 9.1 必须同步更新的情形

| 类型 | 示例 |
|------|------|
| 新功能 | 恢复心灵健身房入口、新增消息类型、新的离开会话触发点 |
| 交互变更 | 反馈弹窗流程调整、播放按钮样式/逻辑、输入区状态变化 |
| 文案变更 | 占位符、反馈标签、感谢语、小晤固定话术 |
| 规则变更 | 上传张数限制、反馈触发条件、自动播放策略 |
| 接口对接 | 语音识别、TTS、图片上传、反馈上报等从 Mock 改为真实能力 |
| 范围调整 | 功能上线、延期、下线（含入口隐藏但代码保留） |

### 9.2 更新时须修改的章节

1. **正文对应章节**（§2–§6）：补充或修订交互规则、状态机、边界说明。
2. **§7 待办 / 后续迭代**：已完成项移出或标注完成；新增项写入并标注优先级。
3. **§8 验收清单**：新增或调整验收条目。
4. **§10 修订记录**：增加版本号、日期、变更摘要。

### 9.3 建议的协作方式

- 产品 / 交互提出需求或改稿时，以本文档为评审依据。
- 开发合入 `components/LumiSpace/` 或相关 App 层逻辑前，确认文档已更新或在同一 PR / 任务中一并提交文档变更。
- 若与其他文档有关联（如 [`奖励结算体系.md`](../06-公益与奖励/奖励结算体系.md)），在正文或 §7 中增加交叉引用，避免重复定义冲突规则。

### 9.4 版本号规则（建议）

| 变更幅度 | 版本 |
|----------|------|
| 文案微调、验收项勾选 | v1.x（小版本 +1） |
| 单模块交互变更 | v1.x 或 v2.0（视影响面） |
| 架构级变更（如会话持久化、多模态重构） | 大版本 +1 |
