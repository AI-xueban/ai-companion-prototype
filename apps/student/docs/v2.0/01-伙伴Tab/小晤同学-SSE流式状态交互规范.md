# 小晤同学 · SSE 流式状态交互规范

| 项 | 内容 |
|---|---|
| 模块 | 底栏「伙伴」· 小晤同学会话层 |
| 版本 | v1.0 · 2026-08-24 |
| 文档类型 | 前端交互规范 · SSE 事件消费契约 |
| 面向角色 | 前端 / Agent 工程 / 后端 / 测试 |
| 上游依据 | [伙伴Tab-小晤同学-产品需求文档PRD](./伙伴Tab-小晤同学-产品需求文档PRD.md)、[小晤同学-Agent开发需求文档](./小晤同学-Agent开发需求文档.md) |
| 关联代码 | `components/LumiSpace/` |

> 本文规定前端如何消费 `api/v1/app/xiaowu/chat/stream` 返回的 SSE 事件流：哪些状态对用户可见、以什么文案与位置展示、状态之间如何转移、失败如何降级。风控相关流程对用户完全静默，不在本文展开用户可见表现，仅规定其前端处理方式。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 风控静默 | `risk_gate` 全过程对用户不可见；不展示风险标签、分数、模型报错或内部原因 |
| 过程可见 | 仅"思考中""联网搜索中""搜索到的查询词"三类过程状态对用户可见，其余节点级事件只用于前端状态机驱动 |
| 单一指示器 | 同一时刻只展示一个过程状态；新状态直接替换旧状态，不叠加 |
| 流式优先 | 第一个 `token` 到达即关闭所有过程状态指示器，进入流式渲染 |
| 不解析自由文本 | 前端不从 `token` 文本中猜测跳转、搜索、写入等动作；可操作元素只来自结构化 `ui` / `tool` 字段 |
| 失败可降级 | 长时间无 `token` 或连接断开时，给出可理解的降级文案与重试入口，不展示错误码 |

## 2. SSE 事件总表与可见性

| SSE 事件 | node | 对用户可见 | 前端处理 |
|---------|------|:---:|------|
| `flow_start` | — | ❌ | 初始化本轮前端会话状态，不渲染 UI |
| `node_start` | `risk_gate` | ❌ | 风控开始，静默；不触发任何 loading |
| `node_end` | `risk_gate` | ❌ | 风控结果只进日志/埋点；按 `action` 静默调整后续可用工具开关，不渲染 |
| `node_start` | `guide` | ⚠️ 间接 | 触发"思考中"过程状态（若尚未显示） |
| `web_search` (status=`searching`) | `guide` | ✅ | 显示"正在联网搜索…"，替换"思考中" |
| `web_search` (status=`completed`) | `guide` | ✅ | 记录 `query`，待回答渲染时作为气泡顶部小字展示 |
| `token` | `guide` | ✅ | 关闭所有过程状态指示器，逐 token 追加渲染回答文本 |
| `node_end` | `guide` | ❌ | 仅用于收尾：结束流式、释放 loading、触发埋点；不直接渲染 |
| `flow_end`（建议补） | — | ❌ | 标记本轮结束，回到 idle，启用输入框 |
| `error`（建议补） | — | ❌ | 触发降级文案与重试入口，不展示错误码 |

### 2.1 风控静默的特殊行为

风控结果不展示，但需"悄悄改变"后续可用能力：

| 风控 action | 前端表现（不提风控二字） |
|------------|----------------------|
| `pass` | 正常进入回答流程 |
| `rewrite` / `limited` | 正常渲染回答；**不展示任何工具确认按钮**（工具已被关闭） |
| `block` | 渲染安全话术模板（`visible_template_id`），不展示"被拦截" |
| `escalate` | 渲染紧急话术 + 求助入口，不展示"风险等级" |

## 3. 用户可见的过程状态

仅以下三个状态对用户可见，均出现在小晤回答气泡的"过程指示区"。

### 3.1 思考中

| 项 | 规则 |
|----|------|
| 触发事件 | `node_start`（node=`guide`） |
| 触发时机 | 用户发送消息后，风控静默通过、进入 guide 节点时 |
| 文案 | 无文案，仅三点跳动 loading 动效 |
| 位置 | 小晤回答气泡内，回答文本区上方，独立一行 |
| 视觉 | 三个品牌色圆点依次跳动（`animate-bounce`，间隔 0.15s） |
| 退出 | 收到 `web_search: searching` → 替换为"联网搜索中..."；收到首个 `token` → 直接进入流式渲染 |

> 用户发送消息后应**立即**显示思考态，不等 `flow_start` 或 `risk_gate` 完成，避免风控耗时（建议 ≤800ms）造成卡顿感。

### 3.2 联网搜索中

| 项 | 规则 |
|----|------|
| 触发事件 | `web_search`（status=`searching`） |
| 文案 | "联网搜索中..." |
| 位置 | 同 §3.1，**直接替换**思考态，单一指示器 |
| 视觉 | 浅色小字 + 旋转 loader 图标 + 圆角胶囊背景 |
| 退出 | 收到首个 `token` → 关闭指示器，进入流式渲染 |

### 3.3 搜索到的查询词（搜索完成）

| 项 | 规则 |
|----|------|
| 触发事件 | `web_search`（status=`completed`，带 `query`） |
| 文案 | "关于「{query}」"（如 "关于「2026年8月24日深圳天气」"） |
| query 来源 | **Agent 改写后的检索词**，不是用户原话；如用户说"深圳罗湖今天天气怎么样？"，改写为"2026年8月24日深圳罗湖天气" |
| 位置 | **小晤回答气泡内顶部**，作为回答文本的首行小字，与回答正文在同一气泡内 |
| 视觉 | 灰色小字（`text-[11px] text-gray-400`），字号小于正文；回答正文在其下方 |
| 时机 | `completed` 事件到达时先记录 `query`；待首个 `token` 到来、开始渲染回答气泡时，将 query 作为气泡顶部首行渲染 |
| 退出 | 随回答气泡常驻，不单独消失 |

> 选择"气泡内顶部小字"而非独立一行，是为了让搜索过程与回答在视觉上归属同一条消息，强化"小晤查到后回答"的因果感。

## 4. 前端状态机

```text
idle（空闲，可输入）
  │
  │ 用户发送消息
  ▼
thinking（三点跳动，无文案）       ← 立即进入，不等风控
  │
  ├─ 收到 node_start: guide        ← 保持 thinking
  │
  ├─ 收到 web_search: searching    ← 替换为 searching
  │     ▼
  │   searching（联网搜索中...）
  │     │
  │     ├─ 收到 web_search: completed  ← 记录改写后的 query，保持 searching
  │     │
  │     └─ 收到首个 token              ← 关闭指示器，进入 streaming
  │
  └─ 收到首个 token（无搜索）       ← 关闭指示器，进入 streaming
        ▼
      streaming（流式渲染中）        ← 气泡内：query 小字（若有）+ 正文逐字
        │
        ├─ 持续接收 token            ← 追加文本
        │
        └─ flow_end / node_end: guide / 连接关闭
              ▼
            idle（回到空闲，可继续输入）
```

### 4.1 状态转移要点

| 转移 | 规则 |
|------|------|
| thinking → searching | **直接替换**，不叠加；单一指示器 |
| searching → streaming | 第一个 `token` 到达即关闭 searching 指示器 |
| thinking → streaming（无搜索） | 第一个 `token` 到达即关闭 thinking 指示器 |
| 任意 → idle | `flow_end` 或连接关闭；启用输入框，触发本轮埋点 |

## 5. 失败与降级

### 5.1 搜索失败 / 长时间无 token

采用"保持搜索态直到 token 或断连"策略：

| 场景 | 前端表现 |
|------|---------|
| 已显示 searching，长时间无 `token` | **保持"正在帮你查一下…"**，不切换为错误态 |
| 连接断开 / `error` 事件 | 关闭指示器，显示降级文案："小晤刚没接好这句，再说一遍？" + 重试入口 |
| 后端返回降级回复（无搜索结果） | 正常流式渲染小晤的降级回答（如"这次没查到，我先按知道的回答你"），不展示错误码 |

> 不设硬性超时切换为错误态；只要连接存活且未收到 `error`，就保持 searching，避免误判后端仍在正常工作的情况。

### 5.2 其他降级（沿用主 PRD）

| 异常 | 用户可见结果 |
|------|------------|
| 风控服务异常 | 采用最小安全模板，仅普通短聊；不展示风险信息 |
| 专项 Agent 超时 | "我刚刚没接好这句，你可以再说一遍吗？"，允许重试 |
| 前端断连 | 允许从会话历史恢复；不重复写同一条记忆 / 工具操作（`request_id` 幂等） |

## 6. 埋点（最小集合）

| 事件 | 必填属性 |
|------|---------|
| `partner_turn_started` | `request_id`、`session_id`、`entry` |
| `partner_thinking_shown` | `request_id`、`shown_at_ms` |
| `partner_search_started` | `request_id`、`node`、`trigger`（web_search） |
| `partner_search_completed` | `request_id`、`query`、`latency_ms` |
| `partner_first_token` | `request_id`、`ttft_ms`（首字时延） |
| `partner_turn_ended` | `request_id`、`end_reason`（`flow_end` / `error` / `disconnect`）、`token_count` |
| `partner_turn_fallback` | `request_id`、`fallback_reason`、`retry_shown` |

> 风控相关事件不在此列，按主 PRD §11.8 与 Agent 开发文档 §8.2 单独记录，且不保留不必要原文。

## 7. 待后端补全的事件

当前 SSE 协议缺少以下事件，建议推动后端补齐以支撑本规范：

| 事件 | 作用 | 必要性 |
|------|------|--------|
| `flow_end` | 明确标记本轮流结束，前端据此回到 idle、启用输入框、触发 `partner_turn_ended` | 必需 |
| `error` | 标记流程异常，触发降级文案与重试入口 | 必需 |
| 结构化 `ui` / `tool`（在 `node_end: guide` 的 data 中） | 驱动确认按钮、快捷回复、跳转等可操作元素 | 必需（P2 工具门控） |

## 8. 验收清单

- [ ] 用户发送消息后立即显示三点跳动思考态（无文案），不等风控
- [ ] `risk_gate` 的 `node_start` / `node_end` 不产生任何可见 UI
- [ ] 收到 `web_search: searching` 后，思考态被直接替换为"联网搜索中..."
- [ ] 收到 `web_search: completed` 后，**改写后的 query** 被记录，并在回答气泡顶部以"关于「xxx」"小字展示（非用户原话）
- [ ] 第一个 `token` 到达即关闭所有过程状态指示器，开始流式渲染
- [ ] 回答气泡结构：顶部 query 小字（若有）+ 正文逐字渲染
- [ ] 长时间无 `token` 时保持 searching 指示器，不切换为错误态
- [ ] 连接断开 / `error` 时显示降级文案与重试入口，不展示错误码
- [ ] 前端不从 `token` 文本中解析跳转 / 搜索 / 写入动作
- [ ] `flow_end` 后回到 idle，输入框可用，本轮埋点已触发
