## 4. 尚存技术债务

- 多个大型页面仍同时承担视图、状态机和 Mock 数据职责，应按业务域渐进拆分。
- V0.6 的历史 TypeScript 类型债务已在当前基线清零，`npm run typecheck` 与生产构建均作为固定检查项。
- 依赖安装时 npm 报告 6 个审计项（1 个低危、5 个高危）；当前网络审计接口受限，后续需在可访问 npm registry 的环境运行 `npm audit`，评估后再升级，避免直接执行破坏性自动修复。
- Tailwind 当前仍通过浏览器 CDN 注入；后续应在 UI 改版阶段迁移到本地构建链并统一设计令牌。
- Lumi 空间仍保留部分旧打卡状态代码，主应用已不再激活，后续需结合新任务规划流程彻底下线或重构。

## 5. 后续开发顺序

1. 根据新的 UI 方案建立设计令牌与组件状态规范。
2. 拆分 `App.tsx` 的路由/场景编排和学生会话状态。
3. 把 Mock 数据替换为仓储接口，统一加载、空、错误和重试状态。
4. 补齐关键状态机单测与学生端五主导航端到端回归。
5. 将 `npm run check` 接入持续集成，并逐步提高 `strict` 与未使用代码规则的强度。
