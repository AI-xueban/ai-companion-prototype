# 错题本 · 数据来源与逻辑 · 需求文档

> **产品**：AI学伴 · **版本**：v1.5 · 2026-07-06  
> **用途**：统一错题从哪来、何时入库、错因如何标记、如何复习；第 8 章为错题 Tab 交互与数据查询一体说明  
> **关联**：《错题预览-本题练习情况》《答题推题-交互需求》《奖励结算体系》

**本期不做**：错题本内拍照 OCR 录入；能力测评不计入错题本；**星标 / 收藏**（仅保留「加入错题本 / 取消加入错题」）。

---

## 1. 核心规则（必读）

| 场景 | 涵盖范围 | 进错题本 | 错因 |
|------|----------|----------|------|
| **出题作答** | 系统从题库出题、用户做题（见第 2 章） | **答错 → 自动加入** | **用户手动标记** |
| **非出题** | 作业批改、灵境讲题；答对后手动加入 | **用户手动加入** | **用户手动标记** |

**两条原则**

1. **入库与错因分离**：答错可自动进本，但错因**从不自动填**；未标时可显示「待标记错因」，支持跳过与事后补标。  
2. **重复答错**：更新同一条记录（错误次数 +1、状态回「待攻克」），不重复建档。

**用户侧只有一对操作**：**加入错题本** / **取消加入错题**（无单独星标、收藏）。

| 情况 | 加入错题本 | 取消加入错题 |
|------|------------|--------------|
| **答错（出题作答）** | 系统自动加入，无需用户点击 | 用户可主动取消；记录删除，错因一并清除 |
| **答对（出题作答）** | 用户手动点击加入 | 用户可取消加入 |
| **作业批改 / 灵境讲题** | 用户手动点击加入 | 用户可取消加入 |

**答错自动加入**  
判题为错 → 写入/更新错题记录（**错因为空**）→ 界面显示「已加入错题本」→ 用户可标错因（可选）。

**答对手动加入**  
用户点「加入错题本」→ 创建记录 → 选错因（可选）。

## 2. 出题作答：功能入口

以下入口**答错均自动加入错题本**（错因用户自标）：

| 入口 | 说明 |
|------|------|
| 专属计划 / 星轨日课 | 今日学习计划中的测验、练习 |
| 知识图谱练题 | 图谱 → 可练知识点 → 诊断卡 |
| 知识点题库 | 按知识点浏览、预览、挑战 |
| 动态推题 | 知识点未掌握时「做一题推一题」 |
| 错题本复习 | 每日攻克、批量攻克、举一反三 |
| 测验复盘 | 交卷后「消灭错题」 |
| 试卷 / 手写作答 | 带原图或需自批的题库题 |

**答错时需记录**：题目 ID/快照、用户错答、答案与解析、练习会话 ID、来源场景、掌握状态（待攻克）、错因为空。

| 来源场景 | 对应入口 |
|----------|----------|
| 日课任务 | 专属计划 / 星轨日课 |
| 图谱练题 | 知识图谱诊断卡 |
| 题库浏览 | 知识点题库 |
| 动态推题 | unknown 知识点推题 |
| 错题复习 | 每日攻克 / 举一反三 |
| 错题复盘 | 「消灭错题」 |
| 错题预览 | 列表点开、单题结果卡 |

## 3. 其他来源

### 3.1 总览

| 来源 | 题目从哪来 | 答案/解析从哪来 | 加入错题本 |
|------|------------|-----------------|------------|
| 出题作答 | 题库 | 题库 | 答错自动；答对手动 |
| 智阅作业 | 用户拍照 | 好未来作业批改 API | 用户手动 |
| 灵境讲题 | 用户拍照 + 切题 | 可能有 / 可能没有 | 用户手动 |

**存储用来源标识**：`question_bank` · `homework_grading` · `lingjing_tutor` · `manual_add`（答对手动加入）

### 3.2 智阅作业（作业批改）

- 照片：用户拍/传；批改与解析：**好未来 API**
- 用户点「加入错题本」并标错因；可「取消加入」
- 以批改会话 + 题块序号标识；列表主展示原图

### 3.3 灵境讲题

- 拍照 → 切题 → 讲题 → 用户「加入错题本」；可「取消加入」
- 入库时可能仅有题干/原图（不完备），后续可补全答案解析

## 4. 错因

**一律用户手动**，最多选 **3** 项：

| 分组 | 选项 |
|------|------|
| 审题与知识 | 审题有误、知识点忘了、概念模糊 |
| 思路与计算 | 想不到思路、思路卡壳、计算出错、公式用错 |
| 其他 | 时间不够、蒙的/不会、其它 |

**题目反馈**（举报用）与学习错因无关。

---

## 5. 掌握、复习与错题本用法

掌握三态：待攻克 → 待复习 → 已掌握（艾宾浩斯间隔复习）。支持标记/撤销已掌握。

错题本内：每日攻克（默认最多 5 题）、批量攻克、举一反三、消灭错题复盘。

列表筛选：学科、状态、错因（含「待标记」）、来源。**不提供星标筛选。**

---

## 6. 数据与接口要点

**错题记录核心字段**：记录 ID、用户、来源及场景、题目内容、用户错答、答案与解析、错因列表、掌握状态、练习统计、知识点/学科、是否在错题本中、时间戳等。

| 能力 | 说明 |
|------|------|
| 答错自动加入 | 判错后自动写入；错因为空 |
| 手动加入 | 答对、批改、讲题等场景 |
| 取消加入 | 从错题本移除整条记录；**错因一并删除** |
| 标记错因 | 更新错因列表，最多 3 项 |
| 掌握状态 | 标记/撤销已掌握 |

---

## 7. 加入与取消加入错题本

### 7.1 界面上的两种状态

| 状态 | 含义 |
|------|------|
| **已加入错题本** | 该题在错题本列表中（答错自动加入，或用户手动加入） |
| **未加入错题本** | 该题不在错题本列表中 |

用户操作只有切换这两种状态，**没有**单独的「收藏 / 星标」。

### 7.2 各场景下的加入方式

| 场景 | 如何进入「已加入」 | 用户能否「取消加入」 |
|------|-------------------|----------------------|
| 出题作答 · 答错 | **系统自动** | **可以** |
| 出题作答 · 答对 | 用户点「加入错题本」 | 可以 |
| 智阅作业 / 灵境讲题 | 用户点「加入错题本」 | 可以 |

**答错结果页建议**：已自动加入时，主按钮可写「已加入错题本」+ 次要操作「标记错因」；若提供取消，文案用「取消加入错题」，避免与「收藏」混淆。

### 7.3 取消加入后，错因是否删除？

**是，一并删除。**

| 项 | 规则 |
|----|------|
| 错题记录 | 从错题本移除（删除或用户不可见） |
| 错因 | **随记录删除**，不单独保留 |
| 再次答错/再次加入 | 按**新记录**处理，错因**重新为空**，不恢复历史错因 |

取消前可提示：「取消后已标记的错因将清除；若再次做错或加入，需重新标记。」

### 7.4 与学情统计

用户侧取消加入即视为删除。后台若需聚合，可脱钩归档，**不**在再次加入时自动恢复历史错因。

## 8. 错题 Tab：交互与数据查询一体说明

> 按「用户操作 → 界面变化 → 查什么数据 → 怎么筛/聚合 → 写回什么」组织，供产品、前端、后端对齐。  
> 与第 5 章（掌握与复习）、第 6 章（字段与接口）配套阅读。

### 8.0 前置约定

#### 错题记录（查询依赖字段）

| 字段 | 说明 |
|------|------|
| `id` | 记录 ID |
| `subject` | 学科：数学 / 英语 / 语文 |
| `status` | `new` 待攻克 · `reviewing` 待复习 · `mastered` 已掌握 |
| `errorReasons` | 错因列表（最多 3，用户手标，见第 4 章） |
| `source` | 来源：`question_bank` · `homework_grading` · `lingjing_tutor` · `manual_add` |
| `dueDate` | 下次应复习日期 |
| `masteredAt` | 变为已掌握的时间（用于「今日掌握」） |
| `lastAttemptAt` | 最近练习时间（列表默认排序） |
| `isInVault` | 是否在错题本中 |

#### 基础数据集（所有查询的起点）

```text
baseSet = records WHERE userId = 当前用户 AND isInVault = true
```

#### 掌握与调度规则（与第 5 章一致）

| 事件 | status | dueDate |
|------|--------|---------|
| 答错入库 / 复习再错 | 待攻克 | 今天 |
| 第 1 次答对 | 待复习 | 明天 |
| 第 2 次连对 | 待复习 | +3 天 |
| 第 3 次连对 | 待复习 | +7 天 |
| 达标掌握 | 已掌握 | +30 天（防遗忘抽查） |
| 用户标记掌握 | 已掌握 | +30 天 |
| 撤销掌握 | 待复习 | 今天 |

```text
isDueToday(r) = r.status ≠ 已掌握 AND (r.dueDate ≤ 今天 OR r.dueDate 为空)
```

新入库默认 `dueDate` 为空，视为今日应复习。

### 8.2 总览页

#### 8.2.1 错题复习总览卡

**展示与聚合**

| UI | 查询/聚合 |
|----|-----------|
| 待办 **N** | `COUNT(baseSet WHERE status ∈ {待攻克, 待复习})` |
| 待攻克 **X** | `COUNT(baseSet WHERE status = 待攻克)` |
| 待复习 **Y** | `COUNT(baseSet WHERE status = 待复习)` |
| 今日掌握 **+N** | `COUNT(baseSet WHERE status = 已掌握 AND masteredAt = 今天)` |
| 进度条 | `X / (X + Y)` |
| 今日复习计划文案 | `min(5, COUNT(baseSet WHERE isDueToday))` → 展示「继续攻克 N 题」 |

**交互 → 查询**

| 用户操作 | 界面变化 | 查询参数 |
|----------|----------|----------|
| 点击卡片主体 / 待办数字 | 进入全部错题列表 | `subject = All`，`status = pending` |
| 点击「规则」 | 弹出艾宾浩斯复习规则说明（静态，无查询） | — |
| 点击「继续拿下 N 题」 | 打开每日攻克 | 见 §8.5.1 |

#### 8.2.2 学科卡片（数学 / 英语 / 语文）

**展示与聚合（每科独立）**

| UI | 查询/聚合 |
|----|-----------|
| 待消灭 **N**（主数字） | `COUNT(baseSet WHERE subject = X AND status ∈ {待攻克, 待复习})` |
| 圆环红/黄 | 待攻克占比 / 待复习占比 |
| 待攻克 **X**（底栏） | `COUNT(baseSet WHERE subject = X AND status = 待攻克)` |
| 待复习 **Y**（底栏） | `COUNT(baseSet WHERE subject = X AND status = 待复习)` |

> 学科入口不展示「今日」「累计掌握」。今日调度见总览「继续拿下」。  
> 约束：`待消灭 N = 待攻克 X + 待复习 Y`。

**一致性约束**：`Σ 各学科待消灭 = 总览待办 N`（同一 `baseSet` 聚合，禁止分源统计）。

**交互 → 查询**

| 用户操作 | 界面变化 | 查询参数 |
|----------|----------|----------|
| 点击学科卡 | 进入该学科错题列表；隐藏底部导航 | `subject = 该科`，`status = all` |

### 8.3 错题列表页（详情）

#### 8.3.1 页面结构

| 区域 | 作用 |
|------|------|
| 顶栏 | 标题、返回、状态下拉、高级筛选、编辑 |
| 状态快捷标签 | 未掌握 / 待复习 / 已掌握 |
| 错题卡片列表 | 单题预览 |
| 底部「批量订正」 | 当前列表内待办题批量练习（有待办时显示） |

#### 8.3.2 列表查询

```text
list = baseSet
  .filter(subject 匹配)       // All 或具体学科
  .filter(status 匹配)         // 见下表
  .filter(reason 匹配)         // 全部 / 具体错因 / 待标记
  .filter(source 匹配)        // 可选，见第 3 章
  .sort(lastAttemptAt DESC)
```

| 筛选项 | status 条件 |
|--------|-------------|
| 全部 | 不过滤 |
| 待办 | `status ≠ 已掌握` |
| 未掌握（待攻克） | `status = 待攻克` |
| 待复习 | `status = 待复习` |
| 已掌握 | `status = 已掌握` |

| 错因筛选 | 条件 |
|----------|------|
| 全部错因 | 不过滤 |
| 具体错因 | `errorReasons` 包含该项 |
| 待标记 | `errorReasons` 为空 |

#### 8.3.3 入口与默认筛选

| 入口 | subject | status |
|------|---------|--------|
| 点总览「待办」 | All | pending |
| 点学科卡 | 该学科 | all |
| 点状态快捷标签 | 当前范围 | 对应状态 |

#### 8.3.4 交互 → 查询 / 写回

| 用户操作 | 界面变化 | 数据侧 |
|----------|----------|--------|
| 点返回 | 回总览 | 重新跑总览聚合 |
| 状态下拉 / 快捷标签 | 列表刷新 | 更新 `status` 参数 |
| 点「筛选」→ 错因 | 列表刷新 | 更新 `reason` 参数 |
| 点单条错题卡 | 打开单题订正 | `queue = [该条]`，见 §8.5.3 |
| 点「批量订正」 | 打开批量订正 | 见 §8.5.2 |
| 编辑 → 改错因 | 卡片更新 | `PATCH` 更新 `errorReasons` |
| 编辑 → 标记/撤销掌握 | 确认后卡片更新 | `PATCH` 更新 `status`、`dueDate` |
| 编辑 → 取消加入 | 记录移出列表 | `isInVault = false`，见第 7 章 |

### 8.4 入库与查询的关系

错题记录进入 `baseSet` 后，总览、列表、取题方可查到。规则见第 1～3 章，摘要如下：

| 场景 | 入库方式 | 初始 status | 初始 dueDate |
|------|----------|-------------|--------------|
| 各练习入口答错 | 自动 | 待攻克 | 今天（或空，按 isDueToday） |
| 答对后手动加入 | 手动 | 待攻克 | 今天（或空） |
| 作业批改 / 灵境讲题 | 手动 | 待攻克 | 今天（或空） |
| 同题再次答错 | 更新原记录 | 回退待攻克 | 今天 |

入库时 `errorReasons` 为空；取消加入后移出 `baseSet`，错因一并清除。

### 8.5 练习取题

#### 8.5.1 每日攻克

**触发**：总览「继续拿下 N 题」

```text
queue = baseSet
  .filter(status ≠ 已掌握)
  .filter(isDueToday)
  .sort(待攻克优先 → dueDate ASC → lastAttemptAt ASC)
  .limit(5)
```

| 交互 | 流程 |
|------|------|
| 开始 | 按 queue 逐题作答 |
| 交卷 | 逐题写回（§8.6） |
| 完成 | 关闭弹层 → 刷新总览聚合 |

#### 8.5.2 批量订正

**触发**：学科/全部列表底栏「批量订正」

```text
queue = 当前列表筛选结果
  .filter(status ≠ 已掌握)
  // 无数量上限
```

#### 8.5.3 单题订正

**触发**：点击列表中单条错题

```text
queue = [点击的那一条]
```

#### 8.5.4 举一反三

**触发**：错题预览页内操作

```text
queue = [原题] + similarIds 关联题（去重，至少 1 道）
```

### 8.6 答题与手动操作写回

每题提交或用户编辑后更新记录，完成后重新聚合总览数字。

**答题写回**

| 答题结果 | 写回 |
|----------|------|
| 答错 | `status → 待攻克`，`dueDate → 今天`，`wrongAttempts + 1` |
| 待攻克答对 | `status → 待复习`，`dueDate → 明天`，`correctAttempts + 1` |
| 待复习答对 | 连对次数 +1，按 Stage 推 `dueDate`；达标则 `status → 已掌握`，`masteredAt → 今天` |
| 已掌握答错（抽查） | `status → 待攻克`，`dueDate → 今天` |

**用户手动操作**

| 操作 | 写回 |
|------|------|
| 标记掌握 | `status → 已掌握`，`masteredAt → 今天`，`dueDate → +30 天` |
| 撤销掌握 | `status → 待复习`，`dueDate → 今天`，`masteredAt` 清空 |
| 改错因 | 更新 `errorReasons`（≤ 3 项） |
| 取消加入 | `isInVault → false` |

```text
     → 每日攻克取题

POST /mistakes/{id}/attempt
     → 答题结果写回，返回新 status / dueDate

PATCH /mistakes/{id}
     → 改错因 / 标记掌握 / 撤销掌握

DELETE /mistakes/{id}   （或 PATCH isInVault=false）
     → 取消加入
```
