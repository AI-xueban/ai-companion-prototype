## 1. 背景与目标

### 1.1 背景

「万象视界」为学生端内容浏览模块。后台通过**阅读量、点击率、阅读时长**支撑内容展示、自动取数排序及运营分析；数据来源于学生端埋点上报。

### 1.2 建设目标

1. 覆盖核心路径：进入模块 → 首页/频道 → 曝光/点击 → 详情阅读/视频播放。
2. 支撑后台三指标聚合（UV 口径）。
3. 对齐学生端上报接口：内容曝光、内容点击、视频播放。
4. 事件 ID、字段名**中英文并存**，便于研发与数据对接。

### 1.3 范围与优先级

| 维度 | 说明 |
|------|------|
| 本期必接 | P0 事件（约 13 条），支撑三指标 |
| 本期建议 | P1 事件（导流、刷新、异常、短视频等） |
| 本期不做 | P2：搜索、爱心公告栏、图片预览、生词点击等（原型有） |
| 标签 | 学生端不展示，不上报 tag 字段 |
| Tab/频道 | `tab_key` ↔ `channel_id` **由接口下发映射**，客户端不写死 |

## 2. 统计口径约定（UV）

### 2.1 UV 含义（简要）

- **UV**：统计周期内，有多少**不同的学生**发生过某行为（同一人多次只算 1 人）。
- 本需求**主指标均按 UV**；不向产品/运营主报表提供 PV。

### 2.2 UV 去重键（服务端聚合）

```
dedup_key = user_id + content_id + stat_period
```

| 组成部分 | 英文字段名 | 中文字段名 | 说明 |
|----------|------------|------------|------|
| 用户 | user_id | 用户ID | 学生唯一标识 |
| 内容 | content_id | 内容ID | 内容唯一标识 |
| 周期 | stat_period | 统计周期 | 按日/周/月，与报表一致 |

### 2.3 三指标定义（已对齐后台）

| 后台字段 | 英文字段名 | 中文字段名 | 计算规则（UV） | 依赖事件 ID |
|----------|------------|------------|----------------|-------------|
| 阅读量 | read_count | 阅读量 | 周期内对 `content_id` 的 `detail_view` 按 user_id 去重计数 | wanxiang_detail_view |
| 点击率 | click_rate | 点击率 | 同 content_id：点击 UV ÷ 曝光 UV | wanxiang_content_click / wanxiang_content_expose |
| 阅读时长 | read_duration | 阅读时长 | 图文 read_duration_ms 累加；视频 watch_duration_ms 累加 | wanxiang_detail_read_complete、wanxiang_video_progress、wanxiang_video_complete |

**说明：**

- 阅读量**仅**用详情访问，不用有效阅读时长门槛。
- 客户端曝光可在 session 内按 `session_id+content_id+section_id+position` 去重以减少重复上报；服务端 UV 仍按 `user_id` 去重。

## 9. 上报接口与策略

| 埋点类型 | 事件ID（示例） | 接口 | 请求体核心字段（英文） |
|----------|----------------|------|------------------------|
| 曝光 | section_expose, content_expose, banner_expose | POST 上报内容曝光 | events[], user_id, session_id, page_version, event_id, … |
| 点击 | content_click, channel_click, tab_click | POST 上报内容点击 | content_id, channel_id, section_id, source_page, position, event_id |
| 播放 | video_play, video_progress, video_complete | POST 上报视频播放 | content_id, action, duration_ms, progress_pct |

**客户端策略：**

1. 曝光：批量上报，每 3s 或满 20 条。
2. 点击/详情/播放：实时上报，失败重试最多 3 次。
3. session：`wanxiang_module_enter` 生成 session_id；`wanxiang_page_leave` 上报停留时长。
4. 离线补报：超过 24h 的事件可丢弃。

## 10. 验收标准

1. P0 事件全部接入，且携带公共参数 + 专属字段（英文字段名与本文一致）。
2. 服务端能按 UV 产出：曝光人数、点击人数、点击率、阅读人数、阅读时长、视频完播率。
3. `wanxiang_detail_view` 与后台 read_count 一致（同周期同去重规则）。
4. `content_click` / `content_expose` 与后台 click_rate 一致。
5. Tab 切换等场景在映射命中时同时上报 `tab_key` 与 `channel_id`。
6. P2 事件本期可不上报，不影响三指标验收。
