## 0. 阅读说明

### 0.1 推荐的需求管理方式

本项目适合采用“1 份整体需求基线 + 多份单功能迭代需求”的方式。

- 整体基线负责统一产品边界、角色、信息架构、公共状态、数据口径、跨模块联动和二开优先级。
- 单功能需求负责描述某次开发的详细流程、页面、接口、状态、异常、埋点和验收标准。
- 不建议只按功能逐个写而缺少总册。当前项目存在今日任务双流程、两套公益入口、Mock 与真实 AI 混用、学生/教师/内部管理三端共存等情况，单独梳理容易产生口径冲突。

后续每次二开，应先更新本总册中的状态和跨模块规则，再新增对应功能文档，例如：

- `F03-今日任务生成与调整-v1.1.md`
- `F06-知识图谱真实数据接入-v1.0.md`
- `F07-错题闭环服务端化-v1.0.md`

### 0.2 状态标记

| 标记 | 含义 |
|---|---|
| 已实现 | 当前代码存在入口和可操作界面，主要流程可在原型中运行 |

## 1. 产品总览

### 1.1 产品名称

统一名称：**AI伴学V0.6**。

代码和页面中仍存在 `XiaowuLearn AI`、`Xiaowu Teach OS`、`Lumi`、`小晤`、旧版本号等历史命名。二次开发应建立统一的品牌词表，并明确：

- 产品名：AI伴学。
- AI 学习伙伴名：小晤或 Lumi，二者需选定一个正式对外名称。
- 教师端名称：待确认。
- 内部管理端名称：金币运营或 AI伴学运营后台，待确认。

### 1.2 产品定位

AI伴学V0.6 是面向 K12 学生的平板学习伴侣原型，核心闭环为：

1. 了解学生状态和学情。
2. 生成或选择学习任务。
3. 通过微课、答题、AI 讲题完成学习。
4. 更新知识掌握状态和错题状态。
5. 发放 XP、金币和成就反馈。
6. 通过伙伴陪伴、联赛、商店、公益和内容发现提升持续使用意愿。

项目同时包含教师学情工作台和内部金币/公益运营后台，用于展示三端联动愿景。

### 1.3 目标用户

| 角色 | 当前原型身份 | 核心诉求 |
|---|---|---|
| 学生 | 新手、普通学生、学霸三种演示画像 | 获得个性化学习任务、理解知识、订正错题、获得陪伴和激励 |
| 教师 | 数学教研组长/班级教师 Mock | 查看班级学情、风险、错题、学生档案，配置并核销班级激励 |
| 内部运营 | 金币与公益运营人员 | 管理金币规则、流水、兑换、捐赠、爱心池、称号和风控 |
| 产品/演示人员 | 右下角演示控制台使用者 | 切换画像、端和专项场景，快速展示原型状态 |

### 1.4 当前成功标准

当前版本更接近“可演示、可评审、可验证交互”的原型，成功标准是：

- 学生五个主模块可访问并展示完整体验方向。
- 主要学习链路可从任务/地图进入微课或答题，再进入结果与奖励。
- 可展示 AI 解题、错题攻克、知识图谱、成长激励、公益、教师分析和运营管理。
- 关键状态可通过 Mock 或演示控制台稳定复现。

正式产品成功指标目前未在代码中落地。二开时建议至少定义：日活、今日任务生成率、任务完成率、答题完成率、错题攻克率、微课有效观看率、AI 解题完成率、7 日留存和奖励通胀指标。

## 2. 系统范围与真实完成度

### 2.1 三端范围

| 子系统 | 当前入口 | 当前状态 | 说明 |
|---|---|---|---|
| 学生端 | 默认启动 | 已实现原型 | 五个一级导航和大量浮层/全屏流程 |
| 教师端 | 演示控制台切换 | 已实现原型 | 默认已登录，数据为 Mock |
| 内部管理端 | 演示控制台切换 | 已实现原型 | 金币和公益运营，操作主要保存在组件内存或 Mock |
| 演示控制台 | 右下角齿轮 | 演示专用 | 正式发布必须隐藏或通过环境开关控制 |

### 2.2 技术形态

- React 19 + TypeScript + Vite 单页应用。
- Framer Motion 负责大量动效。
- Tailwind 当前通过 CDN 使用，生产构建提示不建议用于生产。
- 构建采用单文件内联策略，适合原型交付，不等同于正式前端资源策略。
- 当前没有业务服务端工程、数据库、正式身份认证或权限中心。
- Gemini SDK 已引入，但多数 `geminiService.ts` 方法仍返回 Mock。
- 小晤对话可通过 Vite 代理接千问；生产环境必须自建后端代理，不能把 API Key 放入前端。

### 2.3 当前数据真实性分层

| 数据类型 | 当前来源 | 生产化要求 |
|---|---|---|
| 用户、等级、金币、画像 | Mock 内存数据 | 用户中心、账户服务、统一登录态 |
| 今日任务 | 固定规则和 Mock 生成 | 学情/课表/作业/偏好驱动的推荐服务 |
| 题库 | 本地 TypeScript 数据和图片 | 题库服务、版本、版权、上下架和内容审核 |
| 知识图谱 | 本地 JSON，当前重点支持四年级演示册 | 统一知识树 API、教材版本映射、学情掌握度 |
| 错题 | Mock 数据 + 本地状态 | 错题服务、来源去重、状态调度、作答写回 |
| 奖励 | `localStorage` 日账本 | 服务端幂等结算、流水、日限和风控 |
| 联赛 | 随机生成 Mock | 排行服务、赛季、分组、反作弊 |
| 公益 | Mock 记录 + 本地募款阶段 | 真实扣币、捐赠账本、审计、风控和公示 |
| 教师学情 | Mock | 班级、学生、作答、知识点聚合服务 |
| 内部运营 | Mock + 组件内状态 | 运营后台 API、权限、审计日志、发布机制 |
| 万象视界 | 本地内容 Mock | CMS、推荐、内容审核、搜索和播放服务 |

## 4. 全局产品规则

### 4.1 平板画布与适配

- 学生端固定交互舞台为 `2400 x 1600`，宽高比 3:2。
- 当前内部设计基准为 `768 x 512`，整体放大至固定舞台，再按浏览器可用区域等比缩放。
- 所有学生端 HUD、导航、浮层和触控区域应共享同一坐标体系，禁止对单个按钮做与整体布局脱离的补偿缩放。
- 正式验收至少覆盖：2400x1600 原始舞台、桌面浏览器等比缩放、平板横屏、浏览器窗口变窄后的完整可见性。
- 教师端和内部管理端是桌面工作台，不应套用学生端固定画布规则。

### 4.2 全局用户状态

- 学生姓名默认“李华”，年级默认“七年级”。
- 演示画像分为 `newbie`、`average`、`ace`。
- 新手未测评时，学科地图锁定并引导先完成能力测评。
- 用户统计包含今日 XP、XP 目标、今日学习时长、连续天数、金币、本周 XP。
- 当前画像、统计、任务和多数设置没有统一持久化，刷新或组件重挂载可能恢复 Mock 默认值。

### 4.3 XP 与金币

- XP 用于成长等级和联赛表现。
- 金币用于装扮、许愿池和公益捐赠。
- 当前奖励引擎支持答题、每日攻克、视频有效观看和见面礼等场景。
- 每日金币全局上限按已有需求文档为 80。
- 重复练习不重复发金币，部分 XP 可减半。
- 正式版结算必须由服务端执行，前端仅展示结果，所有场景以 `scene + refId + userId + ruleVersion` 做幂等。

### 4.4 状态持久化

当前使用方式包括：

- `localStorage`：奖励日账本、知识点掌握覆盖、语音自动播放设置、部分公益阶段等。
- `sessionStorage`：知识图谱练题返回节点和待写回状态。
- React 内存：页面开关、任务计划、教师/运营操作等。

二开时应按数据所有权拆分：用户长期数据存服务端；当前会话草稿可本地缓存；纯视觉开关可保留本地设置。

### 4.5 异常与反馈通则

当前原型以动画、Toast、禁用态和 Mock 降级为主，缺少统一错误体系。正式版要求：

- 所有异步操作必须有加载、成功、失败、重试和超时状态。
- 提交类按钮加载期间防重复点击。
- 退出未完成流程时，根据数据价值决定是否二次确认和保留草稿。
- 网络恢复后不得重复结算、重复建错题或重复捐赠。
- 用户可理解的错误文案与技术日志分离。

## 5. 学生端详细功能需求

## F01 启动、登录与新手引导

**当前状态：部分实现，默认运行直接进入首页；完整流程可由状态或演示画像触发。**

### 目标

建立学生身份、年级教材信息和初始能力档案，为任务推荐和知识地图提供基础。

### 主流程

1. 启动动画。
2. 认证页登录。
3. 输入/确认姓名与年级。
4. 学业罗盘选择年级、教材版本、当前进度。
5. 测评邀请：开始或跳过。
6. 完成后进入首页并展示新手引导浮层。

### 业务规则

- 校准结果结构包含 `grade`、`textbookVersion`、可选 `currentTopicId`。
- 跳过测评可进入首页，但未测评用户的学科地图保持锁定。
- 完成测评后刷新成长数据，并允许生成个性化任务。
- 现有认证仅为前端流程，没有真实账号、Token、学校和班级绑定。

### 状态与异常

- 初始、提交中、认证失败、资料缺失、校准完成、测评跳过、测评完成。
- 正式版需要处理账号不存在、设备离线、Token 过期、未成年隐私授权、学校身份变更。

### 二开验收

- 新用户可完整进入首页，刷新后仍保持登录和校准结果。
- 跳过测评与完成测评会产生不同的地图权限和任务内容。
- 返回、退出和中断后能从合理节点恢复。

## F02 首页沉浸式学习空间

**当前状态：已实现原型，是学生端功能聚合中心。**

### 页面组成

- 顶部：头像、等级、XP 进度、心情记录、金币、公益阶段、通知。
- 中央：AI 伙伴/角色视频主舞台和动态话术。
- 左侧：AI 助手、联赛、万象视界等快捷入口。
- 右下：今日任务提醒/任务面板。
- 底部中央：键盘、语音、拍照入口。
- 底部：五个一级导航。

### 核心规则

- 无任务时展示“定制今日任务”提醒。
- 有任务时展示任务列表、进度和开始按钮。
- 心情最多选择 3 个标签。
- 金币按钮打开商店；公益按钮跳转“我的”并打开公益页。
- 联赛在 `weeklyXp = 0` 时锁定并引导去学习。
- AI 解题、相机、今日任务全屏页打开时隐藏底部导航。

### 当前风险

- 首页集成过多功能，`DashboardImmersive.tsx` 体积很大，状态耦合高。
- 任务、联赛、万象视界、公益、AI 解题均在单组件中管理，后续容易产生浮层和层级冲突。
- 二开建议拆为首页壳层、今日任务域、AI 解题域、内容域、联赛域和公益快捷域。

### 二开验收

- 各入口在正常、空、加载、失败、锁定状态下布局不重叠。
- 任一全屏流程关闭后回到原入口和原状态。
- 金币、XP、任务进度在跨模块操作后即时一致。

## F03 今日任务生成、定制与调整

**当前状态：部分实现，项目中并存两套流程，二开必须先统一。**

### 当前流程 A：新版首页任务定制

状态机包括：

`idle -> greeting_init -> ocr_alignment -> anchor_ready -> task_buffet -> planning_generating -> task_ready`

同时预留 `status_check`、困难/普通/优秀三分支状态，以及未生成提醒和未完成提醒。

主要行为：

1. 用户从首页点击定制。
2. 通过语音或拍照识别当天所学内容。
3. 生成知识锚点，用户选择规定数量的锚点。
4. 生成任务池，用户选择任务。
5. 展示生成过程和今日计划。
6. 用户开始任务或重新定制。

### 当前流程 B：伙伴页晨检

1. 首页切到伙伴 Tab 的晨检模式。
2. 通过固定多轮问题收集学校状态、科目、难点、学习时间和精力。
3. 调用 `generateDailyPlan()` 生成计划。
4. 返回首页展示任务。

### 现状规则

- `DayPlan` 包含 id、标题、描述、任务列表和总 XP。
- `Task` 至少包含 id、标题、学科、时长、完成状态，可带推荐理由、关卡类型、题型和同步微课信息。
- 快速生成模拟等待约 2 秒；晨检完成后模拟等待约 1.5 秒。
- 当前生成结果主要由画像和固定 Mock 决定，并未真正使用全部晨检答案。
- 首页新版任务定制和旧晨检对话存在重复职责。

### 二开决策建议

- 统一以“今日计划服务”为唯一数据源。
- 首页和伙伴页可以保留不同入口，但应进入同一个任务会话与同一个草稿。
- 定制信息统一为：学业来源、知识锚点、主观状态、可用时长、任务偏好、历史学情。
- 生成后必须支持增删任务、调整难度/时长、重新生成和保存草稿。

### 二开验收

- 同一天只有一个有效计划版本，重新定制产生版本记录。
- 同时从首页和伙伴页进入时看到同一草稿。
- 生成失败可重试，原输入不丢失。
- 任务总时长、数量和奖励预估与实际任务一致。
- 已完成任务不会因重新定制被无提示删除。

## F04 拍照识题与 AI 解题

**当前状态：已实现复杂交互原型，识别和讲解内容以 Mock 为主。**

### 入口

- 首页“AI 解题”。
- 首页底部拍照按钮。
- 伙伴页拍照后识别为题目并选择“讲讲”。
- 错题页调用 AI 老师。

### 主流程

1. 打开相机/作业/镜像模式。
2. 拍摄或选择图片，最多数量按具体相机组件限制。
3. 进入识别处理中状态。
4. 单题直接进入讲解，多题打开选题浮层。
5. 展示题目原图或重构题面，可标注。
6. 先进入快速讲解，再可切换引导式讲解。
7. 引导模式按步骤提问、判断回答、给提示并记录错误次数。
8. 用户关闭后返回原入口。

### 讲解状态

- `quick`：快速分步讲解和骨架板书。
- `guide`：前置知识确认、逐步作答、检查、提示和纠错。
- 输入状态包括空闲、引导提问、前置确认、自由提问、检查中。
- 支持角色切换、深度思考、语音/文字输入和讲解反馈。

### 生产化要求

- 图片上传、OCR、题目切分、题库匹配、公式识别和图片安全审核。
- 讲解模型需绑定题目、标准答案、知识点和年级，避免自由生成错误解析。
- 记录讲解会话、学生回答、提示次数和最终掌握结果。
- 未识别、低置信度、多题、非题目图片、隐私图片和服务不可用均需明确降级。

### 二开验收

- 单题、多题、模糊图、非题目图、上传失败均有可恢复路径。
- 讲解中题面与当前步骤始终对应。
- 重复提交和返回不会创建重复学习记录。
- 讲解结果可选择加入错题或发起变式练习。

- 同视频重复观看不重复领取。

- 每次提交只产生一次作答、错题和奖励记录。

## 10. 非功能需求

### 10.1 性能

- 首屏不应一次加载全部知识树、题库、视频和后台模块。
- 学生端视频、图片、知识图谱和万象视界应按入口懒加载。
- 当前单文件超大资源内联只适合演示，正式版应使用分包、CDN 和缓存。
- 关键交互在常用平板上保持稳定帧率，动画需支持降低动态效果设置。

### 10.2 安全与隐私

- API Key 仅保存在服务端。
- 未成年人对话、照片、作答和画像需定义采集目的、保存周期、删除机制和监护人策略。
- 图片上传需内容安全、隐私检测和访问控制。
- 教师和运营数据必须按学校/班级/岗位隔离。
- 金币、捐赠、退款、人工调整和规则发布必须审计。

### 10.3 可用性与无障碍

- 平板触控目标建议不小于 44 CSS 像素等效尺寸。
- 图标按钮提供可访问名称，不能只依赖颜色表达状态。
- 学生端关键文字在 2400x1600 舞台及等比缩放后仍清晰可读。
- 所有浮层支持明确关闭；键盘、返回键和浏览器返回策略需统一。

### 10.4 兼容性

- 重点支持横屏平板和桌面 Chrome/Edge。
- 语音识别、TTS、摄像头权限和自动播放策略需做能力检测。
- 不支持的能力必须给出可操作的替代入口，不能静默失败。

### 10.5 可观测性

正式版至少记录：

- 页面和功能入口曝光。
- 今日计划开始、生成、修改、确认、失败。
- 任务开始、退出、完成。
- 微课有效观看和答题提交。
- AI 解题上传、识别、选题、讲解阶段、反馈。
- 错题加入、错因选择、攻克、掌握。
- 奖励结算成功/跳过原因。
- 商店下单、许愿申请、教师核销。
- 公益捐赠成功/失败/退款。
- 教师风险处理和运营规则发布。

## 12. 核心验收场景

1. 新学生完成登录、学业校准和测评后进入首页，刷新仍保持资料。
2. 未测评学生进入学科页时地图锁定，完成测评后自动解锁。
3. 无今日任务时，从首页定制并成功生成一个唯一计划。
4. 生成失败后保留输入，重试不会创建重复计划。
5. 从任务进入微课，达到有效观看比例后进入答题并只结算一次。
6. 从学科知识节点进入练题，完成后返回原节点并更新掌握状态。
7. 答错题后错题本新增记录，总览数字同步变化。
8. 每日攻克完成后错题状态、奖励余额和今日完成数同步。
9. 拍摄单题直接进入 AI 讲解；拍摄多题先选择题目。
10. AI 讲解识别失败时可重拍、手动选题或返回，原页面状态保留。
11. 小晤文字、语音和图片输入均可用；切换 Tab 后会话按规则保留。
12. 金币购买成功后余额、订单和拥有状态一致，重复点击不重复扣币。
13. 公益捐赠成功后同时产生扣币流水、捐赠记录和阶段进度；失败不扣币。
14. 教师只能查看授权班级；风险处理后仪表盘和消息同步。
15. 运营修改规则并发布后仅影响新行为，历史流水保留原规则版本。
16. 学生端在 2400x1600 舞台和常见窗口等比缩放时，无按钮过小、遮挡、重叠或越界。
