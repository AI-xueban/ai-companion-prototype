## 怎么维护

1. **新写的 V2.0 需求**只放进 `v2.0/<功能>/`，不要丢回 `docs/` 根目录。
2. 某模块被 V2.0 **整篇重写**后：新稿进 `v2.0/`，旧稿挪到 `pre-v2.0/` 对应功能，并在两边 README 标明「现行真源」。
3. 尚未重写的模块（知识图谱、万象视界、公益、答题推题等）继续留在 `pre-v2.0/`，仍是当前实现口径。
4. 每个功能目录用 `README.md` 标出：**先看哪一份、哪份已过时、关联代码在哪**。
5. 文件名保持 `模块-文档类型.md`；不要再在根目录堆平铺文件。
6. 改需求时同步改交叉链接，避免再出现「同主题两份 04 PRD」。
