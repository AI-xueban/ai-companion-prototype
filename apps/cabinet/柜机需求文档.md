# AI学伴共享柜机 — 柜机端需求文档

## 1. 基本信息

| 项目 | 内容 |
|------|------|
| 产品 | 通晤纪 · AI学伴共享柜机 |
| 版本 | v1.11 |
| 更新日期 | 2026-11-11 |
| 屏幕 | 竖屏 1080 × 1920 |
| 原型预览 | 当前局域网：http://192.168.100.101:5173；本机：http://localhost:5173（电脑与服务需保持运行，局域网 IP 可能变化） |

柜机用于学生借、还平板。学生可自行操作；遇到格口或设备问题时可提交反馈。

## 2. 通用规则

- 操作页左上角显示「通晤纪·AI学伴」Logo，首页不显示。
- 学生借取成功提示显示 3 秒：编号密码登录借取后返回首页，人脸识别借取后返回自动扫脸页；扫脸页（含身份确认弹窗）连续 1 分钟无操作返回首页。识别结果和系统自动跳转不算用户操作。
- 归还成功提示保留 5 秒后返回扫码页；右上角倒计时和关闭 × 可提前关闭，关闭后同样返回扫码页。管理员借取仍手动关闭并停留管理员借取页。
- 设备状态只有两种关键结果：
  - **借出中**：学生确认登录并通过借用校验后，自动分配设备并开柜借出；若柜门硬件异常未弹开，按已记借出转管理员处理，不自动解除借用状态。
  - **已归还**：用户完成归还流程，设备已充电且柜门已关闭，并在确认归还弹窗中点击「确认」校验通过。

- 自动开柜借出记录归属（2026-11-12确认）：人脸及编号密码两种学生借取均以本次实际分配并开柜的设备生成借出记录，关联当前学生编号、设备编号、柜机/格口号及借出时间，设备记为借出中；成功提示中的设备和格口必须与记录一致，不能记到其他设备名下。当前成功演示不新增学生本地记录的边界保持，正式记录由业务系统落地。

- 账号借用规则：
  - 一个账号同时只能借出 **1 台**设备；已有借出中设备时，登录后提示「用户已有正在借出的设备」，该设备在列表中不再显示为可借，但仍可发起归还。
  - 借出状态**不跨柜机共享**，仅在当前柜机校验。
  - 同一账号**不允许同时在多台柜机登录**。

| 位置 | 内容 |
|------|------|

- **借**：
  1. 首页左侧上下排列「人脸识别借」「编号密码借」，仅图标与名称，无借取操作说明；右侧保留归还卡片和步骤。人脸入口直接扫脸，编号密码入口直接打开表单，不先启动扫脸。

  1. 在平板上打开设置中心，点【归还设备】

  3. 对应格口自动打开并拍照存证

- 点击「人脸识别借」进入自动扫脸，点击「编号密码借」直接进入编号密码登录。
- 点击「还」进入正常归还流程。
- 「问题反馈」用于上报格口或设备异常。

## 4. 借设备

### 操作流程

```text
点击「人脸识别借」 → 自动扫脸 → 身份弹窗展示本次人脸截图和学生编号
  ├─ 点击「取消」 → 返回自动扫脸，不登录、不开门
  └─ 点击「确认登录」 → 校验借用资格、已有借用和可借设备
      → 自动分配设备并开柜 → 借取成功 → 3秒后返回自动扫脸
扫脸页（含身份弹窗）连续1分钟无操作 → 首页
```

### 页面与规则

| 步骤 | 规则 |
|------|------|
| 登录 | 点击「人脸识别借」直接自动扫脸；身份弹窗展示本次人脸截图和学生编号。确认登录且借用校验通过后自动借取，无需选设备或再次确认取用。编号密码作为备用入口，学生验证通过后走同一自动借取流程；管理员仍走管理员入口。正式系统必须验证账号密码，不能仅判断非空。 |
| 已有借出拦截 | 一个账号同时只能借出 1 台设备。若已有借出中设备，登录后提示「用户已有正在借出的设备」，该设备在列表中不再显示为可借，但仍可发起归还。借出状态不跨柜机共享，仅在当前柜机校验。 |
| 单点登录 | 同一账号不允许同时在多台柜机登录。 |
| 自动分配 | 登录校验通过后，系统分配一台可借设备；真实无可借设备时提示并保持登录页，不开门、不记成功。当前学生原型固定模拟1号格口借取成功，不读取库存或历史学生借用拦截。 |
| 取消身份确认 | 返回自动扫脸，不登录、不开柜门、不改变设备状态。 |
| 自动开柜 | 登录及借用校验通过后直接打开对应柜门并提示借取成功；重复点击不重复分配。 |
| 借取成功提示 | 显示「借取成功 / 柜门开了，把平板拿走吧」，附平板编号和格口号，3 秒倒计时或提前关闭后，编号密码借取返回首页，人脸借取返回自动扫脸页。 |
| 扫脸闲置 | 扫脸及身份确认期间连续 60 秒无人操作回首页；触摸、点击或键盘操作重新计时。切换编号密码或注册流程后停止扫脸超时，离开页面清理识别回调。 |

### 重要说明

- 柜门成功打开就表示已借出。即使用户没有拿走设备、没有拔充电线，或又把门关上，设备仍然是「借出中」。如需恢复为在柜状态，必须重新走归还流程。
- 若点「确认」后柜门硬件故障未弹开，接受「已记借出需人工处理」，由管理员介入处理。

### 4.1 人脸登录与人脸注册（第三方柜机确认版）

- 点击「人脸识别借」直接自动扫脸，不再需要点击开始识别。
- 人脸匹配后必须确认本次截图及学生编号，不能仅凭匹配就开柜。失败可重试或使用编号密码登录；无匹配不触发录入。
- 学生编号密码验证通过后直接模拟分配一台设备并开柜，提示借取成功；3秒或提前关闭提示后返回首页，不进入扫脸页。已有借出记录不阻断原型演示；不进入设备列表、不触发人脸注册。
- 首页双入口按钮文案为「人脸识别借」「编号密码借」，移除末尾的「取」字。扫脸识别期间仅显示「正在识别」，移除「请正对屏幕，系统将识别画面中最大的人脸」提示；最大脸选择规则仍生效。
- 多人脸截取规则：识别到多张人脸时，选取人脸特征区域最大的一张，裁出该人脸用于身份确认，并展示该人脸对应的学生编号；不截取整张多人画面，也不以人物身体大小判断。当前原型使用两张模拟人脸检测框的面积比较，蓝色扫描框标识选中的大脸，确认弹窗只展示该大脸裁图。
- 学生原型演示范围（2026-11-11用户确认）：仅展示匹配成功后的确认登录→模拟开柜→借取成功→3秒返回（人脸借取回扫脸，编号密码借取回首页）；人脸及编号密码两入口均不展示已有借用、无库存或本地存储失败等无法借取状态。每次重复演示均可成功，不新增学生本地借用记录、不消耗模拟库存、不清除已有本地记录；管理员/教师原有记录逻辑保留。无法借取的业务规则仅在本文档保留，正式接入仍须按业务规则校验。
- 当前网页为原型：身份匹配为固定演示编号，开柜为本地模拟；使用一大一小两名学生的人脸扫描动图模拟识别，约2.6秒后展示同一学生的静态模拟截图，不调用摄像头、不请求摄像头权限。截图仅保留在本页内存，不上传、不写入借用记录；真实人脸匹配、借用管控和硬件仍需接入。
- 首页「问题反馈」左侧新增「人脸注册」。学生首次注册或想更换人脸，均从此入口操作，不区分首次/重新录入业务状态。

#### 页面按钮与返回规则

| 页面 | 按钮及行为 |
|------|------|
| 人脸识别页 | 进入即自动识别；保留编号密码备用入口和返回首页。匹配后展示当次人脸截图、学生编号及「取消」「确认登录」；取消重新扫脸，确认且借用校验通过后自动借取。连续 1 分钟无操作回首页。 |
| 借设备的编号密码登录页 | 首页「编号密码借」直接进入，也可从扫脸页切入；学生验证通过后自动借取；「返回」回首页；「人脸识别」重新进入自动扫脸。管理员账号仍进入管理员后台。 |
| 人脸注册的编号密码验证页 | 保留「登录」和「返回首页」。不展示「返回扫脸」「人脸识别」及借设备登录页的「返回」按钮。验证成功只进入注册采集，不进入设备列表。 |
| 人脸录入页 | 显示「绑定编号：XXX」和「开始录入」；开始后显示采集状态。无返回、退出或登录入口。 |
| 录入失败页 | 只提供「重新录入」重试，无返回首页或使用已验证账号登录入口。 |
| 录入成功页 | 提示「录入成功」，自动返回首页，不进入设备列表。 |

借设备编号密码页的「返回」采用浅色描边次按钮；底部「人脸识别」为轻量文字按钮。注册验证页的「返回首页」沿用轻量文字样式。

注册流程：
```text
首页「人脸注册」 → 编号密码验证
→ 查询验证账号的人脸记录
  ├─ 无记录：直接进入录入
  └─ 有记录：自动删除旧人脸后进入录入
→ 统一进入不可退出的录入流程
→ 开始录入 → 视频采集与保存
  ├─ 失败：只允许「重新录入」，直到成功
  └─ 成功：「录入成功」 → 自动返回首页
```

- 删除旧人脸前必须验证编号密码；验证前可以返回首页。
- 有无旧人脸是系统内部处理分支，页面统一称为「人脸注册」「录入人脸」「录入成功」，不显示首次、补录或覆盖更新状态。「重新录入」仅作为采集失败后的重试按钮。
- 开始注册后固定绑定已验证学生编号，失败重试复用本次验证身份。
- 用户看不到独立删除人脸入口；旧人脸由柜机自动删除，删除后立即不能再用于识别。失败时不恢复旧人脸。
- 失败页仅显示「录入失败」「本次人脸未保存，请重新录入」和「重新录入」按钮。
- 成功显示「录入成功」及账号绑定结果，然后返回首页，不自动登录借设备。借设备需重新点击「借」。
- 视频保存在柜机本地，识别数据绑定账号 ID/学生编号；密码仅用于验证，不写入视频、特征或日志。每个账号仅一个有效人脸版本。
- 日志记录账号、柜机编号、时间、操作视频引用、旧人脸删除结果、新数据保存结果及失败原因；历史存证视频不作为可登录人脸。
- 正式柜机应持久化“注册未完成”状态，应对断电、进程重启并恢复录入，不能让已删除旧人脸的流程丢失。具体恢复方式需与第三方确认；网页只能限制页面内退出，不能保证物理断电或关闭浏览器无法中断。

验收：点击「人脸识别借」直接自动扫脸；身份弹窗包含本次截图和学生编号；确认后自动借取，3秒回扫脸，闲置1分钟回首页；归还成功后回扫码；两种借用登录均不触发注册。独立注册验证、录入、日志要求继续按本节检查。

## 5. 归还设备

### 操作流程

```text
点击「还」 → 在平板上点【归还设备】并对屏幕下方扫描口扫二维码
→ 扫码成功 → 对应原格口自动打开 + 调起摄像头拍照
→ 提示「格口已打开」+ 弹出「确认归还」弹窗（含「确认」「取消」）
→ 用户将设备放入原格口、插好充电线、关好柜门
→ 点击「确认」
  ├─ 已充电且门已关 → 归还成功
  ├─ 未充电（不论设备是否放入）→ 提示「设备没充电」→ 自动重新打开柜门 → 回到等待状态
  ├─ 已充电但门未关 → 提示「门没关」→ 弹窗保留
  └─ 点击「取消」 → 不论柜门是否关闭，自动再开一次门 → 判定「取消借用」→ 设备仍为借出中
```

### 页面与规则

| 步骤 | 规则 |
|------|------|
| 开始归还 | 必须先在柜机点击「还」。未开始流程时，直接把设备放入柜内并关门，不算归还。 |
| 扫码归还 | 页面提示「请扫码归还」，将平板上的二维码对准屏幕下方扫描口。扫的是**设备上的二维码**，扫码成功后打开**该设备对应的原格口**（归还回原格口，不开任意空闲格口）。 |
| 扫码失败 | 提示扫码失败，停留在扫码页可重试。 |
| 开门+拍照 | 扫码成功后对应原格口自动打开，并调起摄像头拍照存证。拍照失败不阻断归还流程，扫码成功即可继续，拍照异常会记录供管理员核查。 |
| 格口已打开 | 页面提示「格口已打开」，显示格口号和「把平板放进去，插好电，再关好柜门哦」，并弹出「确认归还」弹窗（含「确认」「取消」）。 |
| 放入设备 | 学生将平板放入原格口、插上充电线并关好柜门。 |
| 确认归还 | 点击「确认」后系统校验：①设备是否充电中 ②柜门是否已关。两项均通过则归还成功。 |
| 未充电 | 若设备未充电（不论设备是否放入格口），提示「设备没充电」，自动重新打开柜门，回到等待状态，用户需重新放好设备并插电后再次点击「确认」。重试无次数上限，直到用户点击「取消」或设备已充电且门已关为止。 |
| 门未关 | 若设备已充电但柜门未关，点击「确认」提示「门没关」，弹窗不消失，等待用户关门后再次点击「确认」。 |
| 取消归还 | 点击「取消」后，不论柜门是否已关闭，自动再开一次门，判定为「取消借用」，设备仍为「借出中」。取消后设备可能在用户手里也可能在柜内（无论是否充电），系统一律按「设备在用户手里」处理，下次归还需重新走完整流程。 |
| 归还成功 | 柜门已关闭且设备已充电，点击「确认」校验通过后，设备变为「已归还」，弹出「设备归还成功 / 谢谢你，平板回家啦」；5 秒后或提前关闭提示后回扫码页，继续扫码归还，不返回首页。 |

### 重要说明

- 归还必须完整完成「柜机发起归还 → 扫码 → 开门+拍照 → 放入设备 → 充电 → 关门 → 确认」。任一步缺失，系统都不能把设备认定为已归还。
- 取消借用后，设备状态保持「借出中」，用户需重新发起归还流程。
- 拍照用于存证，拍照失败不阻断归还，但会记录异常供管理员核查。

## 6. 管理员

柜机存在管理员角色，用于处理借还流程中无法由学生自助闭环的异常情况。

管理员可在柜机端执行的操作：

| 操作 | 说明 |
|------|------|
| 开柜门 | 远程或本地打开指定格口柜门，用于设备卡住、学生未取走等情况。 |
| 改格口设备状态 | 修改柜机本地记录的格口设备在柜/离柜状态，用于格口传感器误判、设备实际在柜但状态异常等场景。 |

### 重要约束

- **借出状态由后台判定**：设备是否被用户借走以后台业务系统的借出记录为准，柜机本地状态不作为借出状态的依据。因此管理员修改柜机端的格口设备状态，**不能直接解除用户的借出状态**，也无法让设备重新变为可借。
- 涉及借出状态变更（如确认学生已实际归还但系统未识别、强制解除借出、设备丢失销账等），必须由后台业务系统核实并处理，柜机端管理员无权直接完成。

### 管理员介入场景

| 场景 | 处理方式 |
|------|------|
| 借出确认后柜门硬件故障未弹开 | 学生已记为「借出中」但未拿到设备。管理员可开柜门让学生取设备；若设备实际不可用，借出状态的解除需后台核实处理。 |
| 归还时充电接口损坏充不上电 | 学生无法自助归还。管理员可开柜门放设备，但借出状态解除需后台核实充电异常后处理。 |
| 格口传感器误判（设备在柜但状态异常） | 管理员修改柜机本地格口设备状态，使其与实际一致。 |
| 归还拍照异常 | 不阻断归还，异常记录供管理员核查。 |
| 设备/格口长期异常 | 通过问题反馈或后台告警触达管理员处理。 |

> 学校管理员登录入口、验证码登录、账号字段对应及功能权限以[柜机学校管理员登录与权限需求](柜机学校管理员登录与权限需求.md)为准。后台创建学校管理员时同时创建柜机管理员账号，仅允许同校手机号验证码登录；删除学校管理员或改为非学校管理员后回收柜机管理员权限。登录后沿用柜机管理员全部功能，不再限制为五项。

## 2026-10-27 柜机版本升级（管理员手动安装）

- 后台下发APK后，柜机只接收更新信息，不自动下载或安装。首页底部展示当前已安装版本「版本 Vx.x.x」；存在未安装更新时，在版本号后显示「可升级」，不再使用底部红点。点击版本区域提示「请登录管理员账号进行版本更新」。
- 管理员页面的「版本更新」按钮下方显示版本号：有待更新包时显示「可升级版本 Vx.x.x」（目标版本），没有待更新包时显示「当前版本 Vx.x.x」（实际已安装版本）。
- 管理员登录后点击「版本更新」，先弹出「是否下载（包名）？」；选择「取消」不开始下载，选择「下载」才开始。下载过程中在管理页面展示安装包名称、百分比和进度条，完成100%后提示「是否安装（包名）？」，可取消或安装。
- 取消系统安装确认不改变当前版本，也不清除「可升级」提示；已完整下载的包再次点击「版本更新」可直接进入安装确认。安装成功后读取并更新实际版本，弹出「安装完成／当前版本 Vx.x.x」供管理员确认；仅在没有更高待更新版本时移除「可升级」。
- 当旧版APK尚未开始系统安装、又收到更高版本时，柜机只保留最新版本作为可升级目标，停止旧下载并删除旧版已下载APK以释放存储空间；管理员点击「版本更新」须重新确认并下载最新APK，旧包不再提供安装入口。
- 若旧包已经进入系统安装，新版本到达也不打断本次安装；安装完成后读取柜机实际已安装版本，若仍低于最新目标版本，再提示管理员下载最新APK。
- 柜机重启后重新读取实际已安装版本并核验本地APK：已安装成功则更新显示，仅在没有更高待更新版本时清除「可升级」；本地包缺失或不完整时，管理员重新下载最新版本。
- 下载中断网即中断并丢弃未完成下载；联网后管理员再次点击「版本更新」，重新确认并从头下载，不自动续传。下载安装流程、系统权限及结果获取由研发与第三方柜机对接；原型仅演示进度与弹窗，不实际安装APK。
- 后台根据明确的安装成功或失败结果更新记录，被更高版本替代的旧任务按下一条规则结束；等待下载、下载中、等待安装或安装中统一显示「待更新」。下载断网、取消系统安装确认及长时间等待不自动判失败。升级不得中断正在进行的借还操作。
- 后台再次下发更高版本时，尚未开始系统安装的旧记录转为「失败」，说明「已被更高版本替代」；已经开始系统安装的旧记录等实际安装结果返回后结束，不因新版到达而中断。
- 后续版本需求：柜机自动下载并升级安装最新APK，减少管理员手动操作；自动触发时机、借还避让、安装授权和失败恢复另行评审。本期仍按管理员手动确认下载安装。
