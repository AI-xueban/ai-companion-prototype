# AI学伴共享柜机 — 柜机端需求文档

## 1. 基本信息

| 项目 | 内容 |
|------|------|
| 产品 | 通晤纪 · AI学伴共享柜机 |
| 版本 | v1.8 |
| 更新日期 | 2026-10-08 |
| 屏幕 | 竖屏 1080 × 1920 |
| 原型预览 | 当前局域网：http://192.168.100.101:5173；本机：http://localhost:5173（电脑与服务需保持运行，局域网 IP 可能变化） |

柜机用于学生借、还平板。学生可自行操作；遇到格口或设备问题时可提交反馈。

---

## 2. 通用规则

- 操作页左上角显示「通晤纪·AI学伴」Logo，首页不显示。
- 成功提示弹窗显示 5 秒，右上角有倒计时和关闭 ×；可提前关闭。
- 设备状态只有两种关键结果：
  - **借出中**：用户在取用确认弹窗中点击「确认」，且柜门成功打开。
  - **已归还**：用户完成归还流程，设备已充电且柜门已关闭，并在确认归还弹窗中点击「确认」校验通过。

- 账号借用规则：
  - 一个账号同时只能借出 **1 台**设备；已有借出中设备时，登录后提示「用户已有正在借出的设备」，该设备在列表中不再显示为可借，但仍可发起归还。
  - 借出状态**不跨柜机共享**，仅在当前柜机校验。
  - 同一账号**不允许同时在多台柜机登录**。

- **借**：
  1. 选择登录方式，使用人脸识别或编号密码登录
  2. 在可用列表中选择设备并取用
  3. 在确认弹窗中点击「确认」，柜门开启，取出平板使用

  1. 在平板上打开设置中心，点【归还设备】
  2. 在屏幕下方扫描口扫二维码

- 点击「还」进入正常归还流程。
- 「问题反馈」用于上报格口或设备异常。

## 4. 借设备

### 操作流程

```text
点击「借」 → 选择登录方式 → 人脸识别或编号密码验证 → 登录成功 → 选择设备
→ 点击「取用」 → 弹出确认弹窗「是否取出设备」
  ├─ 点击「取消」 → 不开柜门，流程结束，可重新选择其他设备
  └─ 点击「确认」 → 柜门打开 → [设备记为借出中] → 弹出取出成功提示
```

### 页面与规则

| 步骤 | 规则 |
|------|------|
| 登录 | 先选择人脸识别登录或编号密码登录。人脸识别成功后弹窗展示识别到的学生编号，用户确认后进入设备列表；编号密码验证成功后直接进入设备列表。登录流程不触发人脸注册；独立注册流程见 4.1。正式系统必须验证账号密码，不能仅判断非空。 |
| 已有借出拦截 | 一个账号同时只能借出 1 台设备。若已有借出中设备，登录后提示「用户已有正在借出的设备」，该设备在列表中不再显示为可借，但仍可发起归还。借出状态不跨柜机共享，仅在当前柜机校验。 |
| 单点登录 | 同一账号不允许同时在多台柜机登录。 |
| 设备列表 | 可搜索设备编号；展示序号、设备编号、格口号和「取用」按钮；使用上一页、下一页翻页。若无可借设备，提示「暂无可借设备」。 |
| 取用确认 | 点「取用」后弹出确认弹窗「是否取出设备」，提供「取消」「确认」。 |
| 取消取用 | 不开柜门，不改变设备状态；用户可重新选择其他设备。 |
| 确认取用 | 打开对应柜门。柜门成功打开后，设备立即变为「借出中」，并弹出取出成功提示。 |
| 取出成功提示 | 显示「取出来啦 / 柜门开了，把平板拿走吧」，附平板编号和第几格，5 秒倒计时后返回首页。 |

### 重要说明

- 柜门成功打开就表示已借出。即使用户没有拿走设备、没有拔充电线，或又把门关上，设备仍然是「借出中」。如需恢复为在柜状态，必须重新走归还流程。
- 若点「确认」后柜门硬件故障未弹开，接受「已记借出需人工处理」，由管理员介入处理。

### 4.1 人脸登录与人脸注册（第三方柜机确认版）

- 点击「借」先进入登录方式选择页，两个大按钮分别为「人脸识别登录」「编号密码登录」。
- 人脸识别页没有编号密码登录按钮。匹配成功自动进入设备列表；失败可以重试或返回选择页。无匹配不触发录入。
- 编号密码登录沿用现有页面，验证成功进入设备列表，不触发人脸采集。
- 首页「问题反馈」左侧新增「人脸注册」。学生首次注册或想更换人脸，均从此入口操作，不区分首次/重新录入业务状态。

#### 页面按钮与返回规则

| 页面 | 按钮及行为 |
|------|------|
| 登录方式选择页 | 两个大按钮「人脸识别登录」「编号密码登录」进入对应页面；「返回首页」返回首页。 |
| 人脸识别页 | 左上角「〈 返回」回到登录方式选择页；底部不设置返回或编号密码入口，失败可点击「重新扫脸」。识别成功后弹窗显示当前识别到的编号，并提供「取消」「确认登录」；点击「取消」返回登录方式选择页，只有点击「确认登录」后才能进入设备列表。 |
| 借设备的编号密码登录页 | 「登录」验证后进入设备列表；「返回」回到登录方式选择页；底部「人脸识别」进入扫脸页。 |
| 人脸注册的编号密码验证页 | 保留「登录」和「返回首页」。不展示「返回扫脸」「人脸识别」及借设备登录页的「返回」按钮。验证成功只进入注册采集，不进入设备列表。 |
| 人脸录入页 | 显示「绑定编号：XXX」和「开始录入」；开始后显示采集状态。无返回、退出或登录入口。 |
| 录入失败页 | 只提供「重新录入」重试，无返回首页或使用已验证账号登录入口。 |
| 录入成功页 | 提示「录入成功」，自动返回首页，不进入设备列表。 |

借设备编号密码页的「返回」采用浅色描边次按钮；底部「人脸识别」为轻量文字按钮。注册验证页的「返回首页」沿用轻量文字样式。

注册流程：
```text
首页「人脸注册」 → 编号密码验证
→ 查询验证账号的人脸记录
  ├─ 无记录：直接进入录入
  └─ 有记录：自动删除旧人脸后进入录入
→ 统一进入不可退出的录入流程
→ 开始录入 → 视频采集与保存
  ├─ 失败：只允许「重新录入」，直到成功
  └─ 成功：「录入成功」 → 自动返回首页
```

- 删除旧人脸前必须验证编号密码；验证前可以返回首页。
- 有无旧人脸是系统内部处理分支，页面统一称为「人脸注册」「录入人脸」「录入成功」，不显示首次、补录或覆盖更新状态。「重新录入」仅作为采集失败后的重试按钮。
- 开始注册后固定绑定已验证学生编号，失败重试复用本次验证身份。
- 用户看不到独立删除人脸入口；旧人脸由柜机自动删除，删除后立即不能再用于识别。失败时不恢复旧人脸。
- 失败页仅显示「录入失败」「本次人脸未保存，请重新录入」和「重新录入」按钮。
- 成功显示「录入成功」及账号绑定结果，然后返回首页，不自动登录借设备。借设备需重新点击「借」。
- 视频保存在柜机本地，识别数据绑定账号 ID/学生编号；密码仅用于验证，不写入视频、特征或日志。每个账号仅一个有效人脸版本。
- 日志记录账号、柜机编号、时间、操作视频引用、旧人脸删除结果、新数据保存结果及失败原因；历史存证视频不作为可登录人脸。
- 正式柜机应持久化“注册未完成”状态，应对断电、进程重启并恢复录入，不能让已删除旧人脸的流程丢失。具体恢复方式需与第三方确认；网页只能限制页面内退出，不能保证物理断电或关闭浏览器无法中断。

验收：登录方式选择正常；两种借用登录均不触发注册；注册前验证失败不删除；注册期间不能退出；录入失败只能重试；旧人脸删除后立即无效；新数据绑定验证账号；成功回首页；日志可追溯。

## 5. 归还设备

### 操作流程

```text
点击「还」 → 在平板上点【归还设备】并对屏幕下方扫描口扫二维码
→ 扫码成功 → 对应原格口自动打开 + 调起摄像头拍照
→ 提示「格口已打开」+ 弹出「确认归还」弹窗（含「确认」「取消」）
→ 用户将设备放入原格口、插好充电线、关好柜门
→ 点击「确认」
  ├─ 已充电且门已关 → 归还成功
  ├─ 未充电（不论设备是否放入）→ 提示「设备没充电」→ 自动重新打开柜门 → 回到等待状态
  ├─ 已充电但门未关 → 提示「门没关」→ 弹窗保留
  └─ 点击「取消」 → 不论柜门是否关闭，自动再开一次门 → 判定「取消借用」→ 设备仍为借出中
```

### 页面与规则

| 步骤 | 规则 |
|------|------|
| 开始归还 | 必须先在柜机点击「还」。未开始流程时，直接把设备放入柜内并关门，不算归还。 |
| 扫码归还 | 页面提示「请扫码归还」，将平板上的二维码对准屏幕下方扫描口。扫的是**设备上的二维码**，扫码成功后打开**该设备对应的原格口**（归还回原格口，不开任意空闲格口）。 |
| 扫码失败 | 提示扫码失败，停留在扫码页可重试。 |
| 开门+拍照 | 扫码成功后对应原格口自动打开，并调起摄像头拍照存证。拍照失败不阻断归还流程，扫码成功即可继续，拍照异常会记录供管理员核查。 |
| 格口已打开 | 页面提示「格口已打开」，显示格口号和「把平板放进去，插好电，再关好柜门哦」，并弹出「确认归还」弹窗（含「确认」「取消」）。 |
| 放入设备 | 学生将平板放入原格口、插上充电线并关好柜门。 |
| 确认归还 | 点击「确认」后系统校验：①设备是否充电中 ②柜门是否已关。两项均通过则归还成功。 |
| 未充电 | 若设备未充电（不论设备是否放入格口），提示「设备没充电」，自动重新打开柜门，回到等待状态，用户需重新放好设备并插电后再次点击「确认」。重试无次数上限，直到用户点击「取消」或设备已充电且门已关为止。 |
| 门未关 | 若设备已充电但柜门未关，点击「确认」提示「门没关」，弹窗不消失，等待用户关门后再次点击「确认」。 |
| 取消归还 | 点击「取消」后，不论柜门是否已关闭，自动再开一次门，判定为「取消借用」，设备仍为「借出中」。取消后设备可能在用户手里也可能在柜内（无论是否充电），系统一律按「设备在用户手里」处理，下次归还需重新走完整流程。 |
| 归还成功 | 柜门已关闭且设备已充电，点击「确认」校验通过后，设备变为「已归还」，弹出「设备归还成功 / 谢谢你，平板回家啦」。 |

### 重要说明

- 归还必须完整完成「柜机发起归还 → 扫码 → 开门+拍照 → 放入设备 → 充电 → 关门 → 确认」。任一步缺失，系统都不能把设备认定为已归还。
- 取消借用后，设备状态保持「借出中」，用户需重新发起归还流程。
- 拍照用于存证，拍照失败不阻断归还，但会记录异常供管理员核查。

## 6. 管理员

柜机存在管理员角色，用于处理借还流程中无法由学生自助闭环的异常情况。

管理员可在柜机端执行的操作：

| 操作 | 说明 |
|------|------|
| 开柜门 | 远程或本地打开指定格口柜门，用于设备卡住、学生未取走等情况。 |
| 改格口设备状态 | 修改柜机本地记录的格口设备在柜/离柜状态，用于格口传感器误判、设备实际在柜但状态异常等场景。 |

### 重要约束

- **借出状态由后台判定**：设备是否被用户借走以后台业务系统的借出记录为准，柜机本地状态不作为借出状态的依据。因此管理员修改柜机端的格口设备状态，**不能直接解除用户的借出状态**，也无法让设备重新变为可借。
- 涉及借出状态变更（如确认学生已实际归还但系统未识别、强制解除借出、设备丢失销账等），必须由后台业务系统核实并处理，柜机端管理员无权直接完成。

### 管理员介入场景

| 场景 | 处理方式 |
|------|------|
| 借出确认后柜门硬件故障未弹开 | 学生已记为「借出中」但未拿到设备。管理员可开柜门让学生取设备；若设备实际不可用，借出状态的解除需后台核实处理。 |
| 归还时充电接口损坏充不上电 | 学生无法自助归还。管理员可开柜门放设备，但借出状态解除需后台核实充电异常后处理。 |
| 格口传感器误判（设备在柜但状态异常） | 管理员修改柜机本地格口设备状态，使其与实际一致。 |
| 归还拍照异常 | 不阻断归还，异常记录供管理员核查。 |
| 设备/格口长期异常 | 通过问题反馈或后台告警触达管理员处理。 |

> 【待确认】管理员的登录入口、操作后台界面需补充确认后细化。管理员不区分超级管理员，权限统一。

## 7. 问题反馈

仅首页提供「问题反馈」入口。

1. 选择格口号（当前为 1～16）。
2. 选择一个问题：门关不上、充电线损坏、格口内有异物、设备损坏。
3. 两项都选好后才能提交。

提交成功后显示“感谢您的反馈，工作人员会尽快处理！”，并展示所选格口和问题类型。关闭弹窗后，已选内容清空。
