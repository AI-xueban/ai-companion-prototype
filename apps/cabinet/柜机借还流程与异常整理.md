# AI学伴共享柜机：借还流程与异常整理

## 售前培训简版流程

### 一、借设备

1. 在首页点击「借」。
2. 输入编号和密码并登录。
3. 在设备列表中选择要借的设备，点击「取用」。
4. 在确认弹窗中点击「确认」。系统提示借出成功，学生即可取走设备；成功提示 5 秒后回到首页。

### 二、还设备

1. 在首页点击「还」。
2. 在平板上打开【归还设备】，将设备二维码对准柜机扫描口。
3. 扫码成功后，设备对应的原格口打开并拍照。
4. 将平板放回原格口，插好充电线并关好柜门。
5. 点击「确认归还」，系统检查设备是否充电、柜门是否关好。
6. 充电和关门都通过后，提示归还成功，设备完成归还。

### 三、问题反馈

1. 在首页点击「问题反馈」。
2. 选择出现问题的格口号。
3. 选择问题类型：门关不上、充电线损坏、格口内有异物或设备损坏。
4. 点击提交；提交成功后提示“感谢反馈”，并自动回到首页。

> 整理依据：`柜机需求文档.md`（v1.6，2026-08-27）、当前原型 `index.html/app.js` 的可交互页面，以及 `柜机端埋点需求文档.md`。以当前需求文档和已确认规则为准。

## 一、业务状态与总原则

- 设备业务状态只有两种关键终态：**借出中**、**已归还**。
- 借出成立条件：学生在“是否取出设备”弹窗点击「确认」后，流程即提示借出成功，学生编号立即进入“已借设备”状态。柜门成功打开时学生取走设备；若柜门打开失败，视为柜门硬件异常，仍保持学生已借设备状态，由管理员介入开门处理，不能因此解除借用状态。
- 归还成立条件：柜机发起归还 → 扫设备二维码 → 原格口打开并拍照 → 放入设备、插好电、关门 → 点击「确认」校验通过（已充电 + 门已关）。
- 账号同一时间最多借 1 台；借出状态只在当前柜机校验；同一账号不允许同时在多台柜机登录。
- 归还扫码打开的是该设备的**原格口**，不是任意空闲格口。
- 拍照失败不阻断归还，但必须记录异常供管理员核查。

## 二、正常借出流程

1. 首页点击「借」，进入编号/密码登录页。
2. 输入编号和密码；任一为空或校验失败，停留在登录页并提示，不能进入设备列表。
3. 登录成功后进入设备列表：可按设备编号搜索、分页；展示序号、设备编号、格口号和「取用」。无可借设备时显示空态。
4. 点击某设备「取用」，弹出“是否取出设备”。
5. 点击「取消」（已确认）：取消本次借取，不开柜门，停留在设备列表页面，可重新选择。
6. 点击「确认」：系统写入学生已借设备状态并显示“取出来啦 / 柜门开了，把平板拿走吧”，展示平板编号和格口号。柜门正常打开时学生取出设备；柜门未打开时仍提示借出成功，记录柜门硬件异常并转管理员处理。
7. 成功提示显示 5 秒，可点 × 提前关闭；5 秒后提示消失并回到首页。

## 三、正常归还流程

1. 首页点击「还」，进入扫码页；学生先在平板设置中心点击【归还设备】。
2. 将平板上的设备二维码对准柜机下方扫描口。
3. 扫码成功后：识别未结借用记录，打开该设备原格口，并调起摄像头拍照存证；页面提示格口已打开并弹出“确认归还”。
4. 学生把平板放回原格口，插好充电线，关好柜门。
5. 点击「确认」：系统同时校验“设备充电中”和“柜门已关闭”。
6. 两项均通过：设备变为已归还，显示“设备归还成功 / 谢谢你，平板回家啦”，5 秒后回首页。

## 四、归还分支与异常处理

| 触发点/异常 | 页面/系统处理 | 设备业务状态 | 后续动作 |
|---|---|---|---|
| 扫码失败（已确认） | 提示扫码失败 | 不变 | 停留扫码页，用户继续重试 |
| 找不到对应未结借用/二维码无效（已确认） | 判定扫码无效，无提示、不开门 | 不变 | 用户可重新扫码 |
| 扫码成功但原格口实际未打开（已确认） | 系统仍提示“门开了” | 仍按借出中处理 | 学生联系管理员开门 |
| 拍照失败（已确认） | 不影响后续归还流程 | 继续归还中 | 正常完成归还；后台没有本次拍照照片 |
| 点击确认：设备未充电（已确认） | 语音提示并弹窗提示“没充电”，自动再次打开柜门 | 借出中 | 学生充好电、关好门后点击确认；系统再次校验，未充电则重复本分支 |
| 点击确认：已充电但门未关（已确认） | 语音提示“门没关好”并弹窗提示；学生需手动关门 | 借出中 | 关门后继续确认；弹窗 1 分钟无人操作才自动消失 |
| 充电和关门均通过（已确认） | 校验通过，提示归还成功 | 已归还 | 归还流程完成 |
| 点击确认：未充电且门未关（已确认） | 按未充电分支语音+弹窗提示并自动开门；学生充电、关门后再次确认，随后继续执行充电和关门校验 | 借出中 | 直到充电、关门均通过 |
| 点击取消归还（已确认） | 柜门保持打开，学生需手动关门；取消归还弹窗并返回首页 | 仍为借出中 | 下次需要重新发起归还流程 |
| 确认归还弹窗 1 分钟无操作（已确认） | 先执行一次关门校验；若门没关，进入“门没关”的语音+弹窗处理；若门已关，继续判断设备是否充电；相关弹窗消失后停留在扫码页，不自动跳首页 | 仍为借出中 | 按后续校验结果处理 |
| 归还中途返回/离开/超时 | 不能直接记为已归还；需按未完成处理（超时策略需补充） | 借出中 | 重新发起归还或人工介入 |
| 设备放入后未发起柜机归还流程 | 直接放入并关门不算归还 | 借出中 | 必须重新发起“还→扫码→确认” |

## 五、借出侧异常与账号异常

- 编号或密码为空（已确认）：提示“请输入编号和密码”，页面停留在登录页。
- 编号/密码校验失败（已确认）：提示“编号或密码错误”，页面停留在登录页。
- 账号已有借出中设备（已确认）：登录时提示“该编号已有一台设备正在借出中”，不能继续借用，页面停留在登录页。
- 当前柜机无可借设备（已确认）：设备列表展示设备均为“借出中”，用户不能借用。
- 搜索不存在的设备编号（已确认）：不会搜索到该设备，提示“未搜索到”。
- 借出确认后柜门未弹开：仍提示借出成功，学生编号保持已借设备状态；记录柜门硬件异常，管理员介入开门让学生取出。不得因柜门异常自动解除借用状态。
- 学生点击取用确认后又关门/未拔线：不自动撤销借出，必须重新走归还流程。
- 同账号在多台柜机登录（已确认）：仍按已有设备借出处理，提示“该编号已有一台设备正在借出中”。

## 六、管理员介入边界

柜机管理员可：

- 远程/本地打开指定格口；
- 修改柜机本地格口设备“在柜/离柜”状态，用于传感器误判或设备卡住。

柜机管理员不可直接解除用户借出状态。以下情况必须后台业务系统核实并处理：确认实际归还但系统未识别、强制解除借出、设备丢失销账、充电异常导致的借出闭环。

建议后台离线时展示：柜门状态=未知、充电状态=未知、最后上报状态及时间；“已借出”仍可作为业务状态保留，不能把“关闭/充电中”当作实时状态。

## 七、问题反馈流程

仅首页入口：选择 1～16 格口号 + 选择问题类型（门关不上、充电线损坏、格口内有异物、设备损坏）→ 点击提交但未选完整时提示“选择格口号和问题类型” → 两项齐全后提交成功，提示“感谢反馈” → 自动回到首页。

> 归还过程中的弹窗消失后，页面停留在扫码页，不自动跳转首页。

## 八、当前原型与需求的差异/待确认项

1. 当前原型的 `confirmBorrow()` 点击确认后直接展示成功提示，未模拟“柜门打开失败/已记借出”分支；真实接入需以后端/硬件门状态为准。
2. 当前原型用“模拟扫码成功/失败、模拟未充电、模拟门没关、模拟归还成功”导航按钮演示状态，真实设备信号尚未接入。
3. 当前原型通过随机设备/格口模拟归还对象；真实流程必须由扫码结果关联原借用记录并固定打开原格口。
4. 管理员登录入口、权限、告警确认/处理说明、扫码无借用记录、流程超时/断电/离线恢复、同账号多柜机登录策略仍需补充确认。
