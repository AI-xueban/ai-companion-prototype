# AI学伴共享柜机 — 友盟埋点需求 PRD

## 1. 目标与范围

本版以柜机当前原型和既有公共字段为准，按友盟 U-App 的自定义事件、事件属性、用户属性模型，重新梳理柜机端用户行为与借还流失漏斗。

覆盖：首页、借设备（登录、设备列表、取用确认、开门、借出完成）、归还（扫码、原格口开门、拍照、确认校验、取消归还/重新打开、归还完成）及问题反馈。

不在本期范围：异常归还入口、管理员操作、管理员登录；不改变柜机既有页面和业务规则。柜机原型是流程和页面状态的最终参考。

关键业务规则：借出在“取用确认 + 柜门成功打开”后成立；归还须完成“扫码 → 原格口开门 → 放入设备并充电 → 关门 → 确认校验通过”；拍照失败不阻断归还；弹窗的“重新打开”是“取消归还”的界面文案：重开原格口成功后，归还流程取消，设备继续为借出中。

## 2. 友盟上报规范

|规则|要求|
|---|---|
|事件 ID|稳定英文小写下划线，统一以 `cabinet_` 开头；中文名仅用于展示，不参与代码上报。|
|参数 Key|使用本文英文属性名；中文只用于评审说明。|
|事件类型（友盟后台）|全部注册为多参数类型事件（类型填 `0`）。|
|参数值类型|一律按 String 上报；首次上报会锁定类型。|
|上报方|客户端报页面可见、点击、提交；服务端或硬件接入层报登录、开门、拍照、校验和业务终态。同一事件只允许一个最终上报方。|
|结果事件|结果统一由 `result` 或专用结果属性区分。成功率、完成漏斗必须筛选成功终态。|
|事件记录类型|页面可见 `page_view`；有效操作 `click`；请求提交 `submit`；业务或硬件最终状态 `result`；会话开始 `system`。|
|属性值|枚举使用稳定英文值，不随界面文案变化；可选属性缺失直接省略，不传空字符串。|
|去重|同一 `borrow_flow_id`、`return_flow_id` 的超时、重试、离线补报复用同一幂等键；完成终态只报一次。|
|时区|自然日按 `Asia/Shanghai`；流程跨日不重置流程 ID。|
|保留字段|不得使用 `id`、`ts`、`du`、`token`、`app_version`、`channel`、`device_model` 等友盟保留字段作为事件 ID 或参数 Key；柜机业务版本用 `client_ver`。|
|隐私|不上传编号原文、密码、姓名、手机号、二维码内容、照片、IMEI、MAC、完整设备序列号或详细地址。|

友盟设备 DAU 是柜机设备活跃，不等于服务学生数。业务 DAU 为当天发生有效借还行为的去重 `user_id`；共享柜机看板必须同时展示两种口径。

## 3. 公共字段与装配

业务模块仅传事件专属属性；公共字段由统一封装、登录态、占用记录或 SDK 装配。

### 3.1 装配分层

|分层|字段|规则|
|---|---|---|
|SDK 自动|事件时间、平台、App 版本、系统版本、设备基础信息|后台确认可查后，不重复作为自定义属性上传。|
|柜机上下文|`cabinet_id`、`cabinet_site_id`、`client_ver`|全事件必备；站点只传稳定 ID，不传详细地址。|
|身份|`user_id`、`user_role`|借设备在登录成功后设置；归还在扫码成功后从未结占用取原借用人。扫码前没有 `user_id`。|
|会话页面|`session_id`、`page_name`、`module_name`、`source_page`、`entry_source`|统一封装填写；`session_id` 在柜机启动后生成。|
|业务流程|`borrow_flow_id`、`return_flow_id`、`rental_session_id`|借、还入口点击立即生成对应 flow ID；`rental_session_id` 只在成功借出后生成，归还扫码成功后从未结占用找回。|
|质量|`schema_version`、`is_offline_event`、`business_event_time`（仅补报）|统一封装填写。|
|技术排查|`event_id`、`trace_id`、`retry_count`|仅用于去重或技术日志/APM，不作为友盟分析维度。|

### 3.2 公共字段表

|字段|类型|是否必填|说明|示例|生成/获取方式|
|---|---|---|---|---|---|
|`event_id`|string|统一上报器内部必填|单条业务事件唯一 ID；超时重试、离线补报必须复用，防止重复上报。不作为友盟分析属性|`evt_20260917_000001`|客户端或服务端生成 UUID|
|`event_name`|string|是|事件 ID，必须与本文事件清单英文 ID 一致|`cabinet_borrow_entry_click`|埋点代码写死或事件封装层传入|
|`event_time`|timestamp|是|事件真实发生时间，不是服务端收到时间|`2026-09-17T19:10:00+08:00`|客户端或服务端生成|
|`business_event_time`|timestamp|条件必填|仅离线缓存、延迟补报导致上报时间不能代表真实发生时间时使用|`2026-09-17T19:10:00+08:00`|事件首次发生时生成并随缓存保留|

|`user_role`|enum|登录后必填|当前操作者角色，柜机端固定为 `student`；未登录时不传|`student`|登录账号角色|

|`cabinet_site_id`|string|是|柜机所在点位 ID，用于按学校/校区聚合|`site_school_001_gate_a`|柜机配置|
|`client_ver`|string|是|柜机端业务版本号（不用保留字段 `app_version`）|`1.0.0`|柜机端构建写入|
|`session_id`|string|是|一次柜机连续使用过程 ID|`sess_abc123`|柜机启动后生成|
|`page_name`|string|建议必填|当前页面标准英文名，不随中文标题变化|`cabinet_home`|前端按路由/组件赋值|
|`module_name`|string|建议必填|当前功能模块|`borrow`|前端按模块枚举赋值|
|`source_page`|string|否|行为发生前所在页面|`cabinet_home`|前端记录跳转前页面|
|`entry_source`|string|否|进入当前功能的入口来源|`home_borrow_card`|点击入口时赋值|
|`is_offline_event`|boolean|是|是否为离线缓存后补报|`false`|统一封装根据上传状态赋值|
|`trace_id`|string|技术日志可选|前后端技术链路 ID，不进入友盟分析|`trace_xxx`|链路追踪系统|
|`retry_count`|integer|技术日志可选|上传重试次数，不作为友盟业务属性|`0`|统一上报层维护|

## 5. 用户行为事件

### 5.1 柜机访问

|优先级|事件 ID|中文名|类型/最终上报方|触发条件|事件专属属性|
|---|---|---|---|---|---|
|P0|`cabinet_session_start`|柜机会话开始|system / 客户端|柜机应用新建 `session_id` 后，仅一次|`landing_page`|
|P0|`cabinet_home_view`|首页展示|page_view / 客户端|首页关键内容实际可见|`available_device_count`|

### 5.2 借设备

|优先级|事件 ID|中文名|类型/最终上报方|触发条件|事件专属属性|
|---|---|---|---|---|---|
|P0|`cabinet_borrow_entry_click`|点击借设备|click / 客户端|首页点击借设备，创建 `borrow_flow_id`|`borrow_flow_id`、`entry_type`|
|P0|`cabinet_borrow_login_result`|借设备登录结果|result / 服务端|编号和密码校验获得终态|`borrow_flow_id`、`result`、`fail_reason`（失败必填）|
|P0|`cabinet_borrow_active_loan_blocked`|已有借出拦截|result / 服务端|登录成功后发现当前柜机已有借出中设备|`borrow_flow_id`、`block_reason`|
|P0|`cabinet_borrow_device_list_view`|设备列表展示|page_view / 客户端|可借设备列表实际可见（含空列表）|`borrow_flow_id`、`available_device_count`、`search_used`|
|P0|`cabinet_borrow_device_select`|点击取用|click / 客户端|点击某设备取用，弹出确认框|`borrow_flow_id`、`slot_no`|
|P0|`cabinet_borrow_confirm_click`|取用确认弹窗点击|click / 客户端|点击确认或取消|`borrow_flow_id`、`slot_no`、`confirm_action`|
|P0|`cabinet_borrow_door_open_result`|借出开门结果|result / 硬件接入层|确认取用后，门锁返回最终开门结果|`borrow_flow_id`、`slot_no`、`result`、`fail_reason`（失败必填）|
|P0|`cabinet_borrow_complete`|借出完成|result / 服务端|开门成功且借出状态写入成功|`borrow_flow_id`、`slot_no`、`completion_rule`、`duration_ms`、`rental_session_id`|

上报规则：

|场景|上报|说明|
|---|---|---|
|登录字段未填|`cabinet_borrow_login_result`，`result=fail`，`fail_reason=empty_field`|不报列表、取用、完成|
|登录失败|`cabinet_borrow_login_result`，`result=fail` 带 `fail_reason`|不报列表、取用、完成、拦截。`logged_in_elsewhere`：该账号已在其他柜机登录|
|登录成功但当前柜机已有借出|`login_result(success)` + `cabinet_borrow_active_loan_blocked`|顺序上报；不报列表、取用、完成|
|取用后点「取消」|`cabinet_borrow_confirm_click`，`confirm_action=cancel`|不开门；不报开门结果与完成|
|取用后点「确认」但开门失败|确认 + 开门结果失败|不报借出完成|
|柜门打开成功|确认 + 开门结果成功 + `cabinet_borrow_complete`|借出完成只报一次；此时生成 `rental_session_id`|
|列表空态「暂无可借设备」|计入 `cabinet_borrow_device_list_view`，`available_device_count=0`|不单开事件|

### 5.3 归还设备

|优先级|事件 ID|中文名|类型/最终上报方|触发条件|事件专属属性|
|---|---|---|---|---|---|
|P0|`cabinet_return_entry_click`|点击归还|click / 客户端|首页点击还，创建 `return_flow_id`|`return_flow_id`、`entry_type`|
|P0|`cabinet_return_scan_result`|归还扫码结果|result / 硬件接入层|扫描设备二维码得到终态|`return_flow_id`、`result`、`fail_reason`（失败必填）|
|P0|`cabinet_return_door_open_result`|归还开门结果|result / 硬件接入层|扫码成功后打开设备原格口得到终态|`return_flow_id`、`slot_no`、`result`、`fail_reason`（失败必填）|
|P0|`cabinet_return_photo_result`|归还拍照结果|result / 硬件接入层|原格口开门后拍照存证得到终态|`return_flow_id`、`slot_no`、`photo_result`|
|P0|`cabinet_return_confirm_click`|确认归还弹窗点击|click / 客户端|点击确认或界面按钮「重新打开」|`return_flow_id`、`slot_no`、`confirm_action`；「重新打开」映射为 `cancel`|
|P0|`cabinet_return_device_check`|归还设备校验结果|result / 服务端|确认后校验充电和门锁状态|`return_flow_id`、`slot_no`、`check_result`|
|P0|`cabinet_return_door_reopen_result`|归还重开门结果|result / 硬件接入层|未充电或点击「重新打开」触发原格口重开门|`return_flow_id`、`slot_no`、`reopen_reason`、`result`、`fail_reason`（失败必填）|
|P0|`cabinet_return_cancel`|取消归还|result / 服务端|点击「重新打开」后，原格口重开门成功；设备继续借出中|`return_flow_id`、`slot_no`、`cancel_outcome`、`rental_session_id`|
|P0|`cabinet_return_complete`|归还完成|result / 服务端|充电、关门校验均通过且归还状态写入成功|`return_flow_id`、`slot_no`、`completion_rule`、`duration_ms`、`rental_session_id`|

上报规则：

|场景|上报|说明|
|---|---|---|
|扫码失败|扫码结果失败|不报开门、拍照、确认、完成；无 `user_id`，不上报 `rental_session_id`|
|扫码成功但开门失败|扫码成功 + 开门失败|不报拍照、完成；补原借用人 `user_id`，找回 `rental_session_id`；设备仍为借出中|
|拍照失败|`photo_result=fail`|不阻断后续归还|
|确认但未充电|确认点击 + `check_result=not_charging` + 重开门结果|不报归还完成|
|确认但门未关|确认点击 + `check_result=door_open`|不报重开门、不报完成；关门后可再次确认|
|点击「重新打开」|`confirm_action=cancel` + 重开门结果 + `cabinet_return_cancel`（带找回的 `rental_session_id`）|不报归还完成；设备继续借出中|
|校验通过|`check_result=pass` + `cabinet_return_complete`（带找回的 `rental_session_id`）|归还完成只报一次|
|同一 `return_flow_id` 内多次确认/校验|允许|`return_complete` 只报一次|

## 6. 漏斗与流失分析

友盟单个漏斗只允许确定路径，不在同一步使用 OR 分支。每步均按事件属性筛选；借还流程按 flow ID 去重。

|漏斗|步骤（按顺序配置）|主键/窗口|完成定义|
|---|---|---|---|
|柜机首页可用|`cabinet_session_start` → `cabinet_home_view`|`session_id` / 5 分钟|启动后首页实际展示|
|借设备入口|`cabinet_home_view` → `cabinet_borrow_entry_click`|`session_id` / 5 分钟|学生从首页发起借设备|
|借设备完成|`cabinet_borrow_entry_click` → `cabinet_borrow_login_result`(result=success) → `cabinet_borrow_device_list_view` → `cabinet_borrow_device_select` → `cabinet_borrow_confirm_click`(confirm_action=confirm) → `cabinet_borrow_door_open_result`(result=success) → `cabinet_borrow_complete`|`borrow_flow_id` / 10 分钟|柜门成功打开且借出状态写入成功|
|归还设备入口|`cabinet_home_view` → `cabinet_return_entry_click`|`session_id` / 5 分钟|学生从首页发起归还|
|归还设备完成|`cabinet_return_entry_click` → `cabinet_return_scan_result`(result=success) → `cabinet_return_door_open_result`(result=success) → `cabinet_return_confirm_click`(confirm_action=confirm) → `cabinet_return_device_check`(check_result=pass) → `cabinet_return_complete`|`return_flow_id` / 10 分钟|设备充电、柜门关闭、状态写入成功|
|取消后再次归还|`cabinet_return_cancel` → `cabinet_return_entry_click`|`user_id` / 24 小时|点击「重新打开」取消归还后，再次发起归还；跨流程分析|
|问题反馈|`cabinet_feedback_entry_click` → `cabinet_feedback_submit`|`session_id` / 10 分钟|反馈成功提交|

|流程|流失窗口|流失节点|优先分析字段|
|---|---|---|---|
|借设备|10 分钟|登录失败、已有借出拦截、列表后未取用、确认后未开门、开门后未完成|`fail_reason`、`available_device_count`、`search_used`、`confirm_action`、`slot_no`|
|归还设备|10 分钟|扫码失败、开门失败、确认后未通过、未充电、门未关、取消归还（界面文案「重新打开」）|`fail_reason`、`photo_result`、`check_result`、`reopen_reason`、`confirm_action`、`slot_no`|
|反馈|10 分钟|进入后未提交|`issue_type`、`slot_no`|

无终态不能直接等同失败：客户端超时、离线或硬件回调延迟，须由服务端/接入层以原 flow ID 补报最终结果。

## 7. 字段枚举

## 10. 验收标准

|验收项|标准|
