# 柜机学校管理员手机号验证码登录需求

版本：v2.0
日期：2026年10月21日
适用分支：huwei-cabinet

## 1 需求目标与范围

后台管理平台创建学校管理员后，后台同时创建对应的柜机管理员账号。学校管理员可使用登录名（手机号）接收短信验证码，登录同校柜机的管理员账号。

本次只新增学校管理员手机号验证码登录及后台账号创建、权限回收联动。登录成功后原样进入第三方现有柜机管理页面，页面及管理操作流程保持现状。

柜机管理员账号在后台创建和管理，不要求用户在柜机上手动新增账号。

## 2 后台账号创建与字段对应

| 柜机管理员字段 | 学校管理员字段 | 规则 |
| --- | --- | --- |
| 用户账号 | 登录名（手机号） | 用于手机号验证码登录 |
| 用户昵称 | 姓名 | 显示真实学校管理员姓名 |
| 所属学校 | 学校管理员所属学校 | 仅允许登录同校柜机 |
| 用户类型 | 柜机管理员 | 使用柜机现有管理员全部功能 |

后台创建学校管理员时，同时创建关联的柜机管理员账号；重复处理同一创建请求不得重复建号。关联关系应可追溯，不能仅凭显示姓名判断对应账号。

用户密码、用户卡号不纳入此次字段对应和登录要求，新增登录方式不要求输入柜机账号密码或用户卡号。

已有学校管理员账号是否需要批量补建对应柜机管理员账号，由研发核实现状并在上线前明确处理方式。

## 3 首页入口与登录页面

首页底部保留「人脸注册」「问题反馈」「管理员登录」，管理员登录位于最右侧。点击后进入独立手机号验证码登录页。

| 页面元素 | 内容及行为 |
| --- | --- |
| 标题 | 管理员登录 |
| 说明文案 | 使用本校学校管理员绑定的手机号登录 |
| 手机号 | 输入11位登录手机号 |
| 获取验证码 | 本校管理员资格校验通过后可点击，发送后显示重发倒计时 |
| 短信验证码 | 输入6位数字验证码 |
| 登录 | 提交手机号及验证码，由后台完成校验 |
| 返回首页 | 返回柜机首页 |

登录页不展示此前删除的管理图标、「柜机管理 · A03」及「仅限本校授权管理员登录管理」提示。

## 4 登录流程与学校校验

1. 用户输入完整11位手机号后，后台校验该账号是否仍为当前柜机所属学校的学校管理员，并具备对应柜机管理员登录权限。
2. 校验通过后，启用「获取验证码」。不符合资格时，在手机号输入框下方红字提示「当前账号不是本校学校管理员账号」，禁用获取验证码。
3. 点击获取验证码，后台再次检查资格并通过现有短信平台发送柜机管理员登录验证码。
4. 输入验证码并点击登录，后台校验验证码，同时再次校验学校管理员角色、对应柜机管理员权限和学校一致性。
5. 全部通过后，登录后台已创建的柜机管理员账号，进入柜机现有管理员首页；登录时不在柜机本地创建账号。

手机号发生修改时，清除此前资格校验结果和已输入验证码，禁用获取验证码，待完整手机号重新校验后再启用。不能沿用旧手机号的资格或验证码。

当前柜机身份及学校归属以服务端登记为准。柜机未绑定学校、学校归属异常或账号不属于本校时，不得登录。

## 5 权限回收与账号变化

| 后台变化 | 柜机管理员处理 | 登录结果 |
| --- | --- | --- |
| 创建学校管理员 | 后台同时创建对应柜机管理员账号 | 可在同校柜机校验资格并验证码登录 |
| 删除学校管理员 | 后台收回该手机号对应的柜机管理员权限 | 不得再登录柜机管理员账号 |
| 将角色改为非学校管理员 | 后台收回该手机号对应的柜机管理员权限 | 不得再登录柜机管理员账号 |
| 学校发生变化 | 按最新学校归属校验 | 不得登录原学校柜机，仅在满足新学校资格时登录 |

权限回收后，即使持有此前获取且尚未过期的验证码，也不能完成登录；不能只在发送验证码时检查资格。

已登录用户失去管理员权限时，应结束其管理员会话并阻止继续管理操作。第三方需确认已有会话失效及管理操作中退出的衔接方式。

回收要求针对柜机管理员权限，不自行扩大为删除普通用户账号、清除历史记录或删除柜机本地用户。

## 6 登录后的功能与退出

登录成功后原样展示下方参考图中的第三方现有柜机管理页面。页面左上角为「返回」；两列四行入口依次为：开箱测试／激活设备、用户管理／格口详情、摄像头配置／人脸底库、设备管理／退出软件。保留现有图标、文案、颜色、布局和操作流程，不新增标题或账号信息栏。

沿用第三方既有操作边界、操作异常处理和后台现有操作记录能力，柜机不新增操作记录功能。

管理首页「返回」结束管理员会话并返回柜机首页；功能子页返回沿用第三方现有流程。

返回退出、无操作超时、软件重启后清除管理员登录状态。无操作超时时长待确认；管理操作执行中发生超时是否已有处理，由第三方确认，不在本次自行确定中断规则。

## 7 短信平台与验证码

复用教师端手机号登录已接入的短信平台及已有验证码服务方案。短信签名优先沿用教师端已审核签名，具体可用性由研发确认；新增「柜机管理员登录」短信模板，不能发送教师端登录用途的文案。

### 7.1 短信模板

> 【现有短信签名】您正在登录AI学伴柜机管理员账号，验证码为${code}，5分钟内有效。请勿向他人泄露验证码，非本人操作请忽略。

${code}为动态验证码参数，按平台实际参数格式配置。「现有短信签名」替换为实际可用的已审核签名，不作为字面内容发送。模板按短信平台流程配置和审核，使用独立的柜机登录模板标识。

### 7.2 验证码规则

| 参数 | 要求 |
| --- | --- |
| 格式 | 6位随机数字，允许首位为0 |
| 有效期 | 生成后5分钟，短信内容与实际时效一致 |
| 重发间隔 | 同一手机号同一登录用途60秒 |
| 验证成功 | 立即失效，不可重复使用 |
| 成功重发 | 新码生效，旧码失效 |
| 发送频率、输错限制及异常处理 | 沿用教师端现有方案，由服务端执行 |

验证码由后台生成、发送及校验，与手机号和柜机管理员登录用途绑定。柜机不持有短信服务密钥，不生成或自行校验真实验证码，不在接口响应和日志中泄露验证码。

## 8 异常提示

| 场景 | 提示与处理 |
| --- | --- |
| 手机号为空或格式错误 | 请输入正确的11位手机号；不允许获取验证码 |
| 非本校管理员、已删除或角色已变更 | 手机号框下红字提示「当前账号不是本校学校管理员账号」；禁用获取验证码 |
| 网络异常或资格校验超时 | 提示「暂时无法校验，请稍后重试」；禁用获取验证码，不误判为无权限，不删除账号 |
| 验证码为空 | 请输入验证码 |
| 验证码错误或失效 | 验证码错误或已失效，请重新获取 |
| 发送、限流等短信异常 | 沿用教师端已有方案及提示规则 |
| 登录时权限已收回 | 拒绝登录，提示当前账号不是本校学校管理员账号 |
| 后台关联柜机管理员创建失败或尚未完成 | 不进入管理页；提示「管理员账号暂不可用，请联系平台管理员」，后台需可识别异常并补建 |

## 9 联调确认事项

| 事项 | 需明确内容 |
| --- | --- |
| 后台联动建号 | 确认学校管理员与柜机管理员的创建接口、关联方式及失败补建方式 |
| 历史管理员 | 确认上线前是否需补建对应柜机管理员账号 |
| 登录衔接 | 后台验证码验证通过后，第三方如何建立柜机管理员会话 |
| 权限回收 | 删除、改为非学校管理员后的权限生效机制，以及已登录会话如何失效 |
| 同账号多柜机 | 第三方是否已有同账号登录不同柜机的规则，沿用机制待确认 |
| 超时 | 无操作退出时长、管理操作中超时处理是否已有机制 |
| 短信配置 | 签名可用性、柜机登录模板审核和模板标识；核对教师端现有参数与本需求一致性 |

以上为实施衔接项，不改变后台建号、同校登录、删除或改角色后回收权限的已确认业务规则。

## 10 验收要点

1. 后台创建学校管理员时，同步建立关联的后台柜机管理员账号；用户账号为手机号，用户昵称为姓名。
2. 无需在柜机本地新增管理员账号，也无需输入柜机密码或用户卡号。
3. 输入完整手机号后校验本校管理员资格，通过才能获取验证码；无资格时显示红字且按钮不可点击。
4. 有效学校管理员可通过短信验证码登录同校柜机；跨校、无对应权限或资格校验失败时不得登录。
5. 删除学校管理员或改为非学校管理员后，收回其手机号的柜机管理员权限，旧验证码不能绕过回收结果。
6. 已登录账号权限回收后失去管理访问资格，会话清理按双方确认的衔接方式执行。
7. 登录后页面与现有柜机管理页面参考图一致，不新增标题或账号信息栏。
8. 手机号修改后重新校验；网络失败不能触发账号删除或错误撤权。
9. 短信使用柜机管理员登录模板，验证码参数与服务端一致，不接受原型固定演示验证码。
10. 返回退出、超时及重启后清除登录状态；管理操作中超时处理待第三方确认。
