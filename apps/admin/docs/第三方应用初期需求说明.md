# 第三方应用管理与学生端分发需求文档（初期正式开发版）

## 1. 文档信息

- 文档用途：产品、设计、前端、后端、测试共同评审和实施。
- 版本：V1.0
- 开发范围：后台管理端、学生端展示与安装更新流程、应用包存储和元数据管理。
- 本版本目标：完成第三方 APK 的人工上架、按学校分发、学生端安装和更新。

## 2. 背景与目标

学校会提出不同的第三方软件需求。管理员从软件官网获取 APK，在后台上传并关联适用学校。学生登录平板后，只能看到所属学校已关联且已上架的应用，并可以安装、更新和打开。

本版本采用“后台人工上传、统一维护最新版本、学生端按需下载”的模式，不建设开放式应用市场。

## 3. 角色与权限

### 3.1 应用管理员

- 新增、编辑第三方应用。
- 上传和替换 APK。
- 查看应用解析信息和上传记录。
- 上架或下架应用。
- 管理应用与学校的关联关系。
- 查看应用当前关联学校和发布状态。

### 3.2 学生

- 查看所属学校可用的第三方应用。
- 安装未安装应用。
- 更新已安装的旧版本应用。
- 打开已安装应用。
- 暂停、继续或取消正在进行的安装/更新。
- 无卸载权限。

## 4. 核心业务规则

1. 学校关联只决定哪些学校可以使用该应用，不维护应用版本和安装包。
2. 一个应用可以关联多个学校，一个学校可以关联多个应用。
3. 学生端只展示“当前学校已关联且应用状态为已上架”的应用。
4. 如果当前学校没有关联应用，或关联的应用全部下架，则隐藏“更多应用”入口，不展示空页面。
5. 应用下架后，不再通过学生端“更多应用”入口展示，也不能新安装或更新。
6. 应用下架不会删除应用包、版本记录或学校关联记录。
7. 平板系统是否仍保留已安装应用，以及系统桌面是否可以启动，属于设备系统能力，不属于本功能的入口和展示范围。
8. 所有关联学校默认使用应用库中当前最新的已发布版本。
9. 同一应用同一学校只能存在一条有效关联关系。
10. 学生端安装和更新必须支持进度、暂停、继续和取消。

## 5. 后台管理端

### 5.1 菜单与页面

后台仅保留“第三方应用”一级菜单，进入后直接打开应用列表。

### 5.2 应用列表字段

| 字段 | 说明 |
| --- | --- |
| 序号 | 当前列表序号 |
| 名称 | 应用名称 |
| 图标 | APK 解析出的图标 |
| 包名 | Android package name |
| 版本号 | 当前最新版本号 |
| 安装包 | 当前 APK 文件名 |
| 关联学校 | 已关联学校名称，多个学校按列纵向展示 |
| 状态 | 已上架或已下架 |
| 上传时间 | 当前版本包上传时间 |
| 操作 | 编辑、关联学校、上架/下架 |

状态展示：已上架使用绿色标签，已下架使用灰色标签。名称列不重复展示下架文案。

### 5.3 列表筛选

支持：

- 应用名称，模糊匹配。
- 学校，只匹配已经关联该学校的应用。
- 状态：全部、已上架、已下架。
- 上传时间段，包含开始日期和结束日期。

筛选条件点击“查询”后生效，点击“重置”恢复全部数据。分页、排序方式和默认分页大小由后台通用列表规范统一。

### 5.4 上传应用

“上传应用”按钮位于列表左上方。

表单字段：

- 应用名称：必填。
- APK 文件：必填，只允许 APK。
- 应用图标：由服务端从 APK 提取；提取失败时允许管理员手动补充图标后保存。
- 应用包名：优先由服务端从 APK 提取；未提取到时，管理员可以手动补齐后保存。应用创建后包名不可修改，后续上传 APK 的包名必须与原应用一致。
- 版本号：优先由服务端从 APK 提取；未提取到时，管理员可以手动补齐后保存。版本号不得低于当前版本。

服务端校验：

- 校验文件扩展名、MIME 类型和 APK 文件结构，不能只依赖前端扩展名。
- 解析 packageName、versionCode、versionName 和应用图标。
- 计算文件大小、SHA-256 等完整性信息。
- APK 文件损坏时上传失败并返回明确错误。图标、包名或版本号未提取到时，后台显示红字提醒，并允许管理员补充后保存。
- 同一包名上传新版本时，创建新版本记录，不覆盖历史版本。
- 新上传 APK 后，应用在应用库中立即处于已上架状态，但默认不关联任何学校。管理员必须再次执行关联学校操作，学生端才会展示该应用。

### 5.5 编辑应用

- 可修改应用名称和图标。
- 替换 APK 时重新解析版本号和图标并生成新版本记录，保留原有学校关联。
- 不替换 APK 时保留当前版本信息。
- 应用包名不允许修改。上传的 APK 包名与当前应用包名不一致时，提示管理员上传的 APK 包名与当前应用包名不一致。

### 5.6 关联学校

点击应用列表中的“关联学校”打开弹窗。

弹窗要求：

- 显示“可多选，已关联 X 个学校”。
- 列表字段为学校名称、操作。
- 已关联学校显示红色“取消关联”。
- 未关联学校显示蓝色“添加关联”。
- 支持多条关系同时变更，点击“确定”统一保存。
- 点击“取消”放弃本次修改。
- 取消关联只影响后续展示、安装和更新，不删除应用库记录。
- 保存时后端必须进行幂等校验，避免重复关联。

### 5.7 上架和下架

- 下架操作需要二次确认，并提示影响范围。
- 下架后应用在学生端不可见，不允许新的安装和更新。
- 上架后，已关联学校的学生端在打开“更多应用”或手动刷新时立即可见。
- 下架不删除 APK 和历史版本。
- 应用仍被学校关联时允许下架，不提供物理删除操作。

## 6. 学生端

### 6.1 入口显示

首页左侧显示图标和“更多应用”文字的入口，位置约为页面高度 4/5（由UI设计）。

入口显示条件：当前学生所属学校至少存在一个“已关联且已上架”的应用。否则隐藏入口，不显示空状态页。

打开抽屉后：

- 抽屉位于页面最上层。
- 背后显示 50% 黑色蒙层。
- 点击关闭按钮或蒙层可关闭。
- 底部提供“全部”入口。

### 6.2 应用排序

抽屉和“全部”页面统一按以下顺序：

1. 已安装。
2. 待更新。
3. 未安装。

安装完成后应用自动移动到已安装区域；更新完成后从待更新移动到已安装区域。

### 6.3 应用状态与操作

| 状态 | 展示 | 用户操作 |
| --- | --- | --- |
| 未安装 | 安装按钮 | 开始安装下载 |
| 安装中 | 进度条、暂停/继续、取消 | 暂停、继续或取消 |
| 已安装待更新 | 更新按钮 | 可直接打开，也可更新 |
| 更新中 | 进度条、暂停/继续、取消 | 暂停、继续或取消 |
| 已安装最新 | 应用卡片 | 点击直接打开 |

安装和更新按钮使用次要样式，不抢占打开应用的主要操作。

### 6.4 安装和更新流程

1. 学生点击安装或更新。
2. 客户端向服务端获取当前适用学校的最新版本下载地址和校验信息。
3. 客户端开始下载并展示进度。
4. 下载过程中点击应用卡片，暂停下载，按钮显示“继续”，并显示“取消”。
5. 点击“继续”恢复下载；点击“取消”删除临时文件并恢复到下载前状态。
6. 下载完成后校验文件完整性。
7. 校验成功后调用系统安装或更新能力。
8. 安装成功后记录本地 installedVersion，应用进入已安装状态并允许打开。
9. 安装失败表示本次未安装成功，清理本次下载的 APK 缓存；下次操作时重新下载最新安装包，并根据设备是否已有旧版本自动执行安装或更新。

正式开发优先支持断点续传和网络中断恢复；如果技术条件无法支持断点续传，则网络中断后从头重新下载。进度以服务端文件大小和客户端已接收字节计算。

## 7. 异常和边界场景

- 上传非 APK、损坏 APK、解析失败：阻止提交并展示原因。
- 版本号低于当前版本：禁止上传。
- 重复上传相同包名和版本：允许覆盖原安装包；覆盖成功后仍保留原有学校关联。
- 学生下载过程中应用下架或取消学校关联时，不主动中断下载。下载完成后，在安装前重新校验应用状态和学校关联：应用下架时提示“该应用已被学校下架，无法安装”；学校取消关联时提示“该应用学校已不再使用，无法安装”。两种情况都删除已下载的 APK 临时文件。学生端更新下载同样执行这套校验；更新失败时删除更新包临时文件，保留旧版本，旧版本仍可正常打开，且不再显示更新按钮。
- 学校关联被取消：学生端下次同步后不再展示该应用。
- 学校应用全部下架：学生端隐藏“更多应用”入口。
- 网络中断：保留下载进度，恢复网络后允许继续。
- 存储空间不足：安装前检查并提示释放空间；本次安装失败后清理 APK 缓存，下次操作重新下载最新安装包，并根据设备是否已有旧版本自动执行安装或更新。
- 下载失败：按钮统一显示“重试”。新安装点击“重试”时重新下载安装包，下载完成后自动安装；更新点击“重试”时重新下载安装更新包，下载完成后自动安装更新。
- 下载完成但安装失败：本次未安装成功，清理 APK 缓存；下次操作重新下载最新安装包，并根据设备是否已有旧版本自动执行安装或更新。
- 安装失败：清理本次下载的 APK 缓存；下次操作重新下载最新安装包，并根据设备是否已有旧版本自动执行安装或更新。

## 8. 非功能要求

- APK 文件存储使用对象存储，后台数据库只保存元数据和地址。
- 上传、解析、下载和安装过程记录操作日志。
- 管理员操作需要审计：操作者、时间、应用、变更前后状态。
- 下载接口需要鉴权、限流和短时效授权。
- 应用包需要校验哈希，防止文件被替换。
- 学生端列表接口只返回当前学校可见的应用。
- 列表、上传和关联操作要有明确的加载、成功和失败反馈。

## 9. 验收标准

- 管理员可以上传合法 APK，服务端能解析并保存应用元数据。
- 非 APK、损坏包和解析失败文件不能上架。
- 应用列表支持名称、学校、状态和上传时间段筛选。
- 状态列正确显示绿色已上架和灰色已下架。
- 关联学校弹窗支持多选，正确显示已关联数量。
- 添加关联为蓝色，取消关联为红色，批量保存后数据正确。
- 学校没有可见应用时，学生端不显示“更多应用”入口。
- 学生端应用顺序为已安装、待更新、未安装。
- 安装和更新具备进度、暂停、继续、取消和失败重试能力。
- 待更新应用在更新前仍可打开。
- 安装或更新完成后，应用可以正常打开。
- 后台下架后，应用不再出现在学生端更多应用入口。
- 关联学校取消后，学生端同步后不再展示该应用。




## 11. 已确认的正式规则补充

### 11.1 APK 信息补充

APK 能正常读取但没有提取到图标、包名或版本号时，后台允许管理员手动补充缺失信息后保存。APK 文件损坏时不允许保存。

### 11.2 上传与学校关联

新上传的应用立即进入应用库“已上架”状态，但不自动关联任何学校。管理员需要单独执行“关联学校”操作；在完成关联前，该应用不会展示给任何学校的学生。

### 11.3 包名校验

应用包名属于应用身份信息，不允许修改。编辑时如果新 APK 的包名与当前应用不一致，提示管理员重新创建应用，系统不自动创建新应用。

### 11.4 下架期间的下载和安装

- 学生已经开始的安装或更新下载，应用下架后继续下载，不主动中断。
- 下载完成后、安装开始前必须重新校验应用是否仍为已上架且对当前学校有效。
- 安装校验失败时提示：“该应用已被学校下架，无法安装”，并删除 APK 临时文件。
- 更新校验失败时提示：“该应用已被学校下架，本次更新未安装”，并删除 APK 临时文件。
- 更新失败后保留原有旧版本，旧版本可继续打开。
- 更新校验失败后不再显示更新按钮。

### 11.5 安装失败后的处理

安装失败表示本次未安装成功，清理本次下载的 APK 缓存。下次学生操作时重新下载最新安装包：设备没有旧版本时执行安装，设备已有旧版本时执行更新。

### 12.3 状态处理约束

- 点击下载或更新时必须先校验应用当前状态和当前学校关联关系。
- 下载过程中不因后台下架主动中断下载任务。
- 下载完成、安装开始前必须再次校验应用状态和学校关联关系。
- 新安装校验失败时删除 APK 临时文件。
- 更新校验失败时删除更新包临时文件并保留旧版本。
- 更新校验失败后不再显示更新按钮。
- 应用下架后从学生端“更多应用”列表移除。
- 应用重新上架且仍关联当前学校后，学生打开“更多应用”或手动刷新时恢复展示。



### 学生端同步时机

学生打开“更多应用”或手动刷新时，立即从服务端获取当前学校的应用上架状态和关联关系。后台的上架、下架、关联和取消关联变更在下一次打开或手动刷新后生效。
