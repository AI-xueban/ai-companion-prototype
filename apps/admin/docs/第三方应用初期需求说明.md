# 应用运营与学生端第三方应用需求文档（初期）

## 1. 范围与角色

本文用于产品、设计、开发和测试评审，覆盖后台应用库、学校关联管理，以及学生端 APK 安装更新和 WebView 使用流程。

管理员维护 APK 和 Web 应用、版本历史、上下架状态及学校关联。学生查看所属学校可用应用；APK 支持安装、更新、打开和卸载，Web 支持模拟安装、通过 WebView 打开、模拟卸载和重新安装。

初期采用后台人工维护、按学校分发的方式，不建设开放式应用市场。

## 2. 核心规则

- 应用与学校为多对多关系。同一学校与同一应用只能存在一条关联记录。
- 应用版本、APK 和 Web 地址统一在应用库维护，学校关联不单独维护版本。
- 新增应用保存后立即上架，不自动关联学校。管理员在关联管理中添加关联后，学生端才可见。
- 学生端仅展示当前学校已关联且已上架的应用。
- 当前学校没有可见应用时，隐藏“更多应用”入口，不展示空状态页面。
- 下架和取消关联不卸载设备已有应用，不删除应用库和历史记录；下架保留学校关联。
- 应用重新上架且仍关联当前学校时，恢复学生端展示。取消关联后需重新添加关联才会恢复展示。
- 学生打开“更多应用”或手动刷新时，同步最新应用信息、上下架状态和学校关联。
- 安装、更新过程展示进度，不支持暂停；取消任务后，恢复安装前的状态，强制更新限制仍然有效。

## 3. 后台：菜单与公共列表交互

一级菜单为“应用运营”，包含两个二级菜单：

- 应用库：维护应用信息、资源、版本历史和上下架状态。
- 关联管理：维护学校与应用的关联关系。

两个页面均支持页码选择、上一页、下一页、总条数和每页条数选择。默认每页 10 条，可切换为 20 条、50 条。查询后返回第一页；切换页码和每页条数时保留筛选条件。列表序号按筛选后的完整结果连续编号。

上传、编辑、版本历史和添加关联使用较宽弹窗；添加关联的应用表格铺满表单右侧可用空间。取消关联、批量取消关联和下架确认使用窄弹窗。小屏幕适配可用宽度，内容过多时在弹窗内滚动。

## 4. 后台：应用库

### 4.1 列表与筛选

“上传应用”按钮位于列表左上角。不展示“当前结果”“已上架”“学校使用关系”统计卡片。

| 字段 | 展示规则 |
| --- | --- |
| 序号 | 列表连续序号 |
| 名称 | 应用名称，不重复展示下架文字 |
| 图标 | 展示实际图标图片，不展示图片文件名 |
| 包名 | APK 包名；Web 显示“—” |
| 版本号 | 当前 APK 版本号；Web 显示“—” |
| 安装包 | 当前 APK 文件名；Web 显示“—” |
| Web 地址 | Web 完整网址；APK 显示“—” |
| 状态 | 已上架为绿色，已下架为灰色 |
| 上传时间 | 当前资源上传时间 |
| 操作 | 编辑、版本历史、上架/下架 |

应用库不展示关联学校字段，操作列不提供关联学校按钮。

筛选项为应用名称（模糊搜索）、学校（已关联该校的应用）、状态（全部/已上架/已下架）、上传时间范围。点击“查询”生效，“重置”清空条件。日期范围包含起止日期。

### 4.2 上传应用

应用类型使用 APK、Web 两个单选项，默认 APK。表单一个设置项一行，切换类型后仅展示该类型适用的字段，保存校验也按所选类型执行。

#### 4.2.1 APK

字段顺序为应用类型、应用名称、APK 安装包、应用图标、应用包名、版本号、是否强制更新。

- 应用名称、APK 安装包、图标、包名、版本号均须填写完整才能保存。
- 仅支持 APK。校验扩展名、MIME 类型和 APK 文件结构，并校验文件完整性；损坏文件不能保存。
- 从 APK 提取图标、包名和版本信息。未提取到的信息显示红字提醒，允许管理员手动补齐；图标允许手动上传。
- 应用创建后包名不可修改。替换 APK 的包名必须与原应用一致；不一致时提示重新创建应用，系统不自动新建应用。
- 新版本不得低于当前版本；同一包名、同一版本允许覆盖原安装包。
- “是否强制更新”为最后一个设置项，必选，选项为“强制”“非强制”。新上传时需主动选择；未选择不能保存。已有未配置此项的 APK 按非强制兼容，编辑时可修改。该设置是应用当前生效策略，不绑定具体版本；后台修改后，学生端下次同步立即按新策略执行。
- 保存按钮为“保存并上架”；新建应用不自动关联学校。

#### 4.2.2 Web

展示应用类型、Web 地址、应用名称和应用图标。

- 名称、图标和 Web 地址必填，图标由管理员上传。
- 地址须为完整、可通过浏览器访问的网址。
- 隐藏 APK 文件、包名、版本号、是否强制更新，不执行 APK 必填校验，不出现要求上传 APK 的提示。
- 保存按钮为“保存并上架”；新建应用不自动关联学校。
- Web 使用与 APK 相同的上下架和学校关联规则。

### 4.3 编辑应用

编辑弹窗回显当前信息，应用类型固定为创建时的 APK 或 Web，不允许切换。

- 名称和图标可以修改。
- APK 可替换安装包，不替换时保留现有包和版本信息。替换时执行上传校验，并保留学校关联。
- APK 可修改是否强制更新，该设置仍位于最后。
- Web 可修改网址，不涉及 APK 和版本号。
- 点击“保存并上架”后，应用处于已上架状态；取消放弃本次修改。

### 4.4 版本历史

点击“版本历史”打开只读列表，按上传时间从新到旧排列。

| 字段 | 展示规则 |
| --- | --- |
| 名称 | 该次记录的应用名称 |
| 图标 | 该次记录的实际图标 |
| 包名 | 该次 APK 包名；Web 显示“—” |
| 版本号 | 该次 APK 版本号；Web 显示“—” |
| 上传时间 | 该次资源保存时间 |
| 安装包/Web 地址 | APK 文件名或 Web 地址 |

新增应用、替换 APK、修改 Web 地址时记录资源历史，保留已有记录。仅修改名称、图标或强制更新设置不新增资源历史。相同版本覆盖安装包不改变学校关联。

### 4.5 上下架

- 下架必须二次确认，弹窗显示应用名称及下架影响；点击取消不变更，点击确认下架后生效。
- 上架直接操作。
- 已关联学校不阻止应用下架。
- 下架不删除应用资源、版本历史及学校关联，不提供物理删除操作。
- 下架对学生端正在下载任务的处理见第 7 节。

## 5. 后台：关联管理

### 5.1 列表与筛选

每行对应一个学校与一个应用的关联关系。字段为勾选框、序号、学校名称、关联应用、应用版本、应用类型、应用状态、关联时间、操作。

- 关联应用只显示名称，不显示图标。
- APK 显示当前应用版本，Web 版本显示“—”。
- 应用类型显示 APK 或 Web，状态采用绿色已上架、灰色已下架。
- 操作提供红色“取消关联”。
- 按学校名称排列，同一学校内按关联时间从新到旧排列。
- 顶部依次提供“添加关联”“批量取消关联”。

筛选项为学校名称输入搜索、应用名称输入模糊搜索、应用类型、应用状态、关联时间范围。不提供学校下拉筛选和应用下拉筛选。查询与重置规则沿用第 3 节。

### 5.2 添加关联

1. 点击“添加关联”打开弹窗，先单选学校；未选学校时，应用区域显示“请先选择学校”。
2. 选择学校后，仅列出该校尚未关联且已上架的应用。
3. 应用以表格展示：勾选框、应用名称、应用版本、应用类型；不显示图标。
4. 支持多选和全选；全选仅作用于弹窗当前可选应用，部分选中时全选框显示半选状态。
5. 更换学校后重新加载可选应用，清空上一次勾选。
6. 该校已关联全部可用应用时显示提示，不可重复添加。
7. 学校和至少一个应用均为必选；点击保存创建关联，点击取消放弃操作。
8. 保存时校验重复关系，不重置已有关系的关联时间。

### 5.3 取消关联与批量取消

- 单条：点击该行“取消关联”，弹窗展示学校及应用名称，确认后仅取消该条关系。
- 批量：直接勾选当前页列表记录，再点击“批量取消关联”；不另开学校选择列表。
- 表头全选只勾选当前页记录，部分选中时显示半选；切换页码、查询或重置后清空勾选。
- 未选记录时提示先勾选。选中后打开二次确认弹窗，显示待取消的记录数。
- 确认批量取消仅删除已勾选的关联记录，不取消该学校未勾选的其他应用关联。
- 取消关联后的学生端处理见第 7 节。

## 6. 学生端

### 6.1 入口、列表与排序

首页左侧“更多应用”入口包含图标和文字，位置约在页面高度的 4/5。入口显示条件按第 2 节执行。

点击打开最上层应用抽屉，背景为 50% 黑色蒙层；关闭按钮和蒙层可关闭，底部提供“全部”入口。

抽屉和全部页面排序一致：已安装最新版本、待更新、未安装。安装和更新成功后，应用自动移动到已安装最新版本区域。

### 6.2 应用安装、卸载与 APK 强制更新

| 状态 | 展示与操作 |
| --- | --- |
| 未安装 | 显示“安装”；APK 下载后自动安装，Web 执行模拟安装 |
| 已安装最新版本 | 点击应用进入使用，显示垃圾桶卸载按钮；Web 进入 WebView |
| 待更新、非强制 | 显示“更新”，仍可点击应用使用旧版本 |
| 待更新、强制 | 显示“更新”，必须更新成功后才能进入应用；不能绕过更新使用旧版本 |
| 安装或更新进行中 | 显示进度，不提供暂停和继续；完成前不进入应用，可取消任务 |
| 下载失败 | 按钮显示“重试”，点击重新下载最新包并自动安装或更新 |
| 安装失败 | 清理缓存，按设备是否有旧版本恢复为“更新”或“安装” |

强制更新仅用于 APK：设备已有版本且当前存在新版本时生效。学生端读取后台保存的“是否强制更新”设置，不能只根据是否存在更新按钮判断能否打开应用。

- 强制：待更新应用的打开操作不可用，更新按钮可操作；完成更新并安装成功后，才恢复打开操作。取消更新、下载失败、安装失败和重新进入列表都不能解除限制。
- 非强制：待更新应用的卡片可直接打开旧版本，更新按钮独立触发更新；尚未开始更新时，不要求先更新。
- 无新版本：无论配置强制还是非强制，已安装应用均可直接打开。
- 正在安装或更新：点击卡片不能进入应用，也不能暂停任务。进度完成且安装成功后才可打开。

已安装应用（包含待更新应用）显示小垃圾桶卸载按钮，不使用“卸载”文字按钮。点击垃圾桶只打开二次确认弹窗，不直接卸载，也不触发打开应用。

确认弹窗显示待卸载应用名称，提供“取消”“确认卸载”。取消保留原状态；确认后，APK 调用系统卸载能力，Web 清除学生端模拟安装状态。卸载成功后卡片变为未安装状态，显示“安装”，并自动移到未安装区域。学校仍关联且应用仍上架时，可重新安装。

点击已安装且允许使用的 APK 进入应用页面。返回按钮位于屏幕边缘，鼠标从边缘向页面中间滑动时展开，点击后返回学生端。返回不改变应用安装状态。

### 6.3 下载与安装流程

1. 点击安装或更新时，获取当前学校适用的最新包，并校验上架状态和学校关联。
2. 开始下载并展示进度，不支持主动暂停。取消任务时清理临时文件，恢复原状态。
3. 下载完成后校验文件完整性，并再次校验上架状态及学校关联。
4. 校验通过后自动安装或更新；成功后按设备实际版本更新状态。
5. 安装失败清理本次 APK 缓存；下次重新下载最新包。设备无旧版本显示安装，有旧版本显示更新，不保留仅重新安装缓存包的操作。

每个安装或更新任务在开始下载时锁定目标版本，下载过程中后台上传更新版本时，不中断任务、不切换下载文件，也不删除已下载进度。当前目标版本安装成功后立即重新同步应用最新版本：如果仍存在新版本，非强制更新允许进入当前已安装版本并继续显示“更新”；强制更新继续禁止进入，并要求完成最新版本更新。新的版本发布不会使正在下载的安装包失效，应用下架或取消学校关联除外。

网络中断优先支持断点续传，技术条件不支持时从头下载。进度按已接收字节与文件总大小计算。

### 6.4 Web 模拟安装、卸载与使用

Web 应用在学生端的安装状态、按钮、排序和卸载交互与 APK 保持一致，但不下载文件，也不调用系统安装器或卸载器。

1. 未安装的 Web 应用显示“安装”。点击后展示与 APK 安装一致的进度状态，不提供暂停，可取消。
2. 模拟安装完成后按设备保存已安装状态，并自动移到已安装区域。设备重启、学生端重新进入或切换学生账号后仍保持已安装，直到在该设备执行卸载。
3. 只有已安装的 Web 应用可以点击进入。点击后通过学生端 WebView 打开后台配置的网址，不展示系统浏览器界面。
4. 已安装的 Web 应用显示小垃圾桶按钮。点击后二次确认；确认后清除模拟安装状态，卡片恢复为未安装并移到未安装区域，仍可重新安装。
5. Web 没有版本号，不显示更新按钮，不执行版本更新和强制更新规则。后台修改 Web 地址后，设备保留原有模拟安装状态；学生下次打开应用时直接加载最新 Web 地址，不要求重新安装。
6. 模拟安装完成前重新校验应用是否仍上架且关联当前学校；校验不通过时不完成安装，并按学生端同步规则移除应用。

WebView 内提供返回按钮。网页内部存在浏览历史时，点击返回先回到上一网页；已到 Web 应用首页、没有可返回的网页历史时，再关闭 WebView 并返回学生端应用入口。页面加载失败时显示“页面加载失败”状态页，并提供“重试”和“返回”按钮。“重试”重新加载当前 Web 地址；“返回”同样先处理网页历史，没有可返回历史时关闭 WebView。

Web 应用下架或取消学校关联后，按同步规则从更多应用列表移除；学生端保留本地模拟安装状态，重新上架或重新关联后恢复为原安装状态。

## 7. 异常、下架与取消关联

### 7.1 后台校验与失败

| 场景 | 处理 |
| --- | --- |
| 非 APK 文件、APK 损坏 | 阻止保存，提示原因 |
| APK 缺少提取信息 | 红字提醒，允许补齐后保存 |
| 替换包的包名不同 | 阻止保存，提示重新创建应用，不自动创建 |
| 版本低于当前版本 | 禁止上传 |
| Web 地址为空或不符合完整网址要求 | 阻止保存，提示原因 |
| APK 未选择是否强制更新 | 阻止保存，提示“请选择是否强制更新” |

### 7.2 学生端下载失败与安装失败

下载失败显示“重试”，重新下载最新包后自动安装；更新下载失败重新下载最新更新包后自动更新。

存储空间不足时提示释放空间。安装失败清理本次下载缓存，保留设备已有旧版本，后续按第 6.3 节重新下载并尝试安装或更新。

### 7.3 下载前、下载中和安装前的有效性校验

后台下架或取消学校关联不主动中断已开始的下载任务，下载完成后在安装前重新校验。校验失败均不安装，删除临时包，并移除学生端当前列表中的应用；更新任务保留旧版本，不再展示更新按钮。

| 校验场景 | 提示文案 |
| --- | --- |
| 点击安装时发现已下架 | 该应用已被学校下架，无法下载 |
| 点击更新时发现已下架 | 该应用已被学校下架，暂无更新 |
| 新安装下载完成后发现已下架 | 该应用已被学校下架，无法安装 |
| 更新下载完成后发现已下架 | 该应用已被学校下架，当前版本仍可正常使用 |
| 安装前发现学校已取消关联（含更新） | 该应用学校已不再使用，无法安装 |

已安装旧版本仍保留于设备。下架和取消关联后的更多应用入口及列表按第 2 节处理，不提供从该列表打开隐藏应用的入口。

## 8. 验收要点

- 应用运营下有应用库和关联管理两个页面，两者分页、筛选及序号正常。
- APK 与 Web 上传字段、必填校验正确切换；编辑类型不可修改。
